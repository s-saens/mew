The central owner can open a device's **Manage Connected Browsers** from their dashboard, review names, recent access, and connection status, and then select **Revoke Access**. The initial registration time is available through the query API but is not displayed in the current list UI. Revocation records remain in D1 and are not reactivated by trusting the browser again. This is distinct from **Unregister** for the host itself. ## Authentication boundary for device access (2026-10-12)

Mewlink login is used for device registration, listing, deletion, and central account management. Registered `/<유저이름>/<기기이름>` addresses start WebRTC connections without central login, and users sign in with the mew email and password on that computer. Existing member access linking central account IDs to local accounts is not used for new connections. The detailed current contract follows [remote access](../development/remote-access.md) and [ADR 0207](../history/decisions/0207-mewlink-device-access-local-auth.md).

This authentication transition requires redeploying central `mewlink` together with updating the local mew server and UI. Preserve existing registration keys and instance IDs; do not re-register, rotate signing keys, or delete the database. If central and local versions differ, reject the connection rather than bypassing access through existing central account permissions. Central source code remains excluded from public mew Git. The user performs deployment, builds, and server application.
