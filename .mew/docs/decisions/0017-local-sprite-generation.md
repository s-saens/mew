# 0017 — Generating Mewpet with a Local Video Model and Standalone MCP

Status: Source, installation, and deployment boundaries superseded by [Decision 0021](0021-external-local-sprites.md)

## Background

Mew agent chat needs to create animated sprites from character descriptions and optional reference images. Existing Mewpet reads PNG and WebP strips from a global folder without a build, but provides no generation model. Do not tie the GPU and Python dependencies or long-running execution required for generation to the app server's lifetime.

## Decision

1. Register the standalone stdio MCP at `tools/local-sprites` in the selected runtime's existing global configuration. Do not add model execution to Mew's built-in MCP or app server API. Preserve other MCP and runtime settings.
2. Use Apache-2.0-licensed Wan2.1 VACE 1.3B and weights for ComfyUI. Install ComfyUI as a separate GPL-3.0 execution tool and use only its built-in nodes. Remove backgrounds with MIT-licensed rembg and Apache-2.0-licensed U²-Net. Link licenses in [Component Sources](../../../docs/configuration/local-sprites.md#구성출처와-검증-범위).
3. Download models during initial installation and run inference for generation and background removal on the host. Run ComfyUI on loopback only while jobs are running, with external APIs and additional nodes disabled. Preview responses are passed to the selected chat agent; the chat runtime's transmission scope is separate.
4. Generation requests return a job ID immediately, and a separate worker executes them through the GPU queue. Provide status queries, cancellation, all frames, and GIF previews. Use consecutive frames generated by the model; do not substitute simple transformations of still images for animation.
5. Separate generation results from skin registration. Register a new ID at the specified `<DATA_DIR>/mewpet/skins` only when the user requests registration or use. Do not automatically change the browser's current skin; select it in settings.
6. Pin the ComfyUI commit and the repository revision, size, and SHA-256 of the three Wan model files. The installer uses only weights that pass verification and records the actual Python package list. Do not put models, virtual environments, or job results in Git.

## Rationale and Impact

The video model generates motion over time, and VACE image references can keep the character consistent across motions. Normalize results to the existing Mewpet strip contract, leaving the renderer unchanged. The standalone MCP applies to new chats in the selected runtime and requires no Mew build or restart.

This choice requires a CUDA GPU and separate model storage. Motion generation takes time, and references and prompts alone do not guarantee exact identity, anatomy, motion, or looping. Distinguish packing and file registration verification from GPU inference and visual quality checks. [Local Sprite Setup](../../../docs/configuration/local-sprites.md) owns specific installation, usage, and operational contracts.

## Subsequent Correction

[Decision 0021](0021-external-local-sprites.md) supersedes the original decision's `tools/local-sprites` location and the scope of Mew's ownership of installation and operational documentation. Install and reuse the generator from a separate repository, keeping only optional MCP connection and skin format guidance in Mew. Preserve the text above as a historical record of the choice at that time.
