상태: 채택

## 배경

공급자가 선택 모델의 수용량 부족을 알려도 사용자의 구독·잔여 한도가 소진된 것은 아닐 수 있다. 기존 오류 처리로 작업이 끝나면 사용자가 다시 요청해야 하며, 이미 수행한 작업을 반복할 위험도 있다. 사용자가 이런 일시적 실패를 기본 30초 간격·20회로 재시도하고 에이전트 기본 지침 설정에서 값을 조정하도록 요청했다.

## 결정

ACP 채팅의 명시적인 모델 용량 부족·과부하만 같은 논리 턴 안에서 재시도한다. RPC 실패와 답변 말미의 용량 오류 후 정상 턴 종료를 모두 감지한다. 사용자 한도 소진·구독·결제·인증 오류와 일반 속도 제한은 기존 오류 처리를 유지한다. 실행 중인 세션·모델·노력도·권한을 유지하며 자동으로 다른 모델을 고르지 않는다. 공식 TUI·일반 터미널과 CLI 명령 재실행은 범위에서 제외한다.

기본 지침의 뮤 전역 범위에 대기 시간과 최대 횟수를 제공한다. 값은 계정 `agent-guidance.md`의 `capacityRetry` 설정 구간에 메타데이터로 저장하고 기존 revision API로 갱신한다. 별도 설정 파일을 만들지 않으며, 구간이 없는 계정은 원문을 수정하지 않고 기본값을 사용한다. 실행 정책은 모델에게 보낼 지침에서 제외한다.

재시도 설정은 세션 시작 계정에서 논리 턴마다 한 번 읽는다. 대기 중에도 busy와 큐를 유지하고 이미 완료한 작업은 이어 가도록 요청한다. 사용자 중단·탭 종료는 대기와 재요청을 취소한다. 횟수 소진 후에는 최종 오류와 큐 보류로 돌아간다.

## 대안과 근거

에이전트에게 재시도 문구만 보내면 공급자가 요청을 거절한 뒤 실행할 주체가 없다. 모든 오류를 반복하면 실제 한도·인증 문제에도 불필요한 요청을 보낸다. 자동 모델 변경은 사용자가 고른 실행 조건을 바꾼다. 서버의 제한된 판정과 취소 가능한 대기를 사용해 같은 실행 조건을 유지한다.

기존 계정 지침 파일에 실행 메타데이터를 함께 두면 설정창의 권한·revision·원문 보존 계약을 재사용할 수 있다. 별도 JSON은 저장 기준본을 늘리므로 선택하지 않는다.

## 영향

자동 재시도는 실패한 요청의 성공을 보장하지 않는다. 부분 응답 뒤에는 같은 대화의 맥락에서 계속하도록 요청하지만 공급자나 도구의 멱등성을 보장하지 않는다. 서버나 감독 종료 뒤 대기 타이머를 복원하는 기능은 포함하지 않는다. 프로젝트 자동 안내를 끄더라도 이 실행 설정은 적용한다.

현재 값·저장·판정·취소의 상세 계약은 [세션 계약](../development/agent-sessions.md#모델-용량-부족-자동-재시도), 설정 방법은 [사용법](../../../docs/guides/project-setup.md#모델-혼잡-재시도), 검증과 운영 적용 상태는 [작업 기록](../work/agent-capacity-retry.md)이 소유한다.
