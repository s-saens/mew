## 요구사항

- 편집한 내용을 파일에 저장하고 편집 실수를 되돌린다.

### 범위

- 본문 변경을 자동저장하고 실행 취소·다시 실행을 제공한다.

### 경계와 제한

- 자동저장과 Git 커밋은 별개다.
- 외부에서 수정한 파일과 열려 있는 편집기의 저장이 충돌할 수 있으므로 파일 이력·Revert File 경로를 구분한다.

### 상세 계약

- [편집 사용법](../../../../docs/guides/editor.md)

## 구현 내용

- 태스크 문서 저장에는 마지막 저장 원문을 전달한다. 본문만 바뀌면 태스크 패널에서 변경한 최신 태그·담당자를 유지하고, 같은 목록의 상충하는 변경은 409로 중단한다. 서버가 반환한 병합 원문은 편집기·캐시에 반영하며 저장 대기 중의 추가 입력을 보존한다. 적용 경로와 API·탭 회귀는 [태스크 저장 계약](../../development/task-list.md#저장과-동시-수정)을 따른다.

- 브랜치·worktree 전환 준비는 `useTabs`의 자동저장 대기와 진행 중 저장을 마친 뒤, 절대경로로 연 외부 파일을 포함한 수정 탭을 저장한다. 준비 중 새 편집·자동저장을 막고 저장이 실패하면 이동하지 않으며 실패한 저장을 즉시 자동 재시도하지 않는다. 이전 루트의 늦은 저장 콜백은 전환 세대를 검사하고, `PUT /api/file`에 선택적으로 전달한 `workspace`가 요청의 실제 루트와 다르면 서버는 409로 거부한다. 저장을 마친 뒤에는 탭 구조를 유지하면서 대상 worktree의 본문·권한을 다시 확인한다. [worktree 전환 계약](../../development/ui-contracts.md#같은-프로젝트의-worktree-전환)을 따른다.

- 본문 변경을 자동저장하고 실행 취소·다시 실행을 제공한다.

## 검증

- `task-document-save.test.ts`는 열린 문서→패널 태그/담당자 변경→본문 저장, 명시적 태그 삭제·충돌 시 파일 보존을 검사한다. `task-document-save-ui.test.ts`는 실제 `useTabs` 자동저장 응답 중 추가 입력과 후속 저장에서 태그·담당자·본문 유지를 검사한다.

- 아래 항목은 이번 정리에서 실행한 테스트 결과가 아닌 사용자 확인 기준이다:
  - 저장 후 재열기와 실행 취소가 맞고 자동저장을 Git 커밋으로 표시하지 않는지 확인한다.
