## Requirements

Provide the breakpoint, prioritized variable-change display, and variable-pinning requirements from [Build a Debugger](../../../tasks/Done/Build%20a%20debugger.md) through external Debug Adapter Protocol (DAP) adapters. mew does not bundle a debugger engine or language runtime.

### Configuration and Installation

- Manage adapters, server executables, arguments (a JSON array of strings), stdio/TCP, TCP ports, launch/attach, and launch configurations (JSON objects) in **Settings → Debugger**. Provides Save, Test Connection, and Open Debugger. Settings, breakpoints, and pinned expressions are saved per account and current project root.
- Provides presets for js-debug (JavaScript/TypeScript/Node.js), debugpy (Python), LLDB DAP and CodeLLDB (C/C++/Rust), Delve (Go), and custom DAP. Actual supported languages and launch configurations follow the respective adapter's contract.
- **Install js-debug** uses Microsoft's official standalone DAP release `1.140.0`. It downloads only when the button is pressed, checks SHA-256, size, archive paths, and file types, then places it in `debuggers/js-debug-1.140.0/` under the data folder. It does not install VS Code/VSIX or an IDE. When installation completes, it updates that account's settings with the server's Node executable path and adapter path. Installation requires HTTPS access from the server and `tar`. Because the standalone bundle is CommonJS, it explicitly sets `type: commonjs` in `package.json` at the adapter root to avoid inheriting `type: module` from the parent mew project. Other metadata in the existing package.json is preserved. For existing installations, pressing the install button or starting a managed adapter session also corrects the module boundary without downloading again.
- Install the remaining adapters separately on the server and configure their paths and arguments. Presets are provided for CodeLLDB as `codelldb --port 56789`, Delve as `dlv dap --listen=127.0.0.1:56789`, debugpy as `python3 -m debugpy.adapter`, and LLDB DAP as `lldb-dap`. Change the port when using them alongside other TCP debuggers.
- TCP connects only to `127.0.0.1`. Leaving the executable empty connects to an already running loopback DAP server. Managed js-debug starts on port `0` and detects the actual port from stdout. File paths are relative to the **mew server**, and source files and debug targets must also be on the server.

Example Node.js launch configuration:

```json
{
  "type": "pwa-node",
  "program": "/absolute/project/main.js",
  "cwd": "/absolute/project",
  "console": "internalConsole",
  "args": []
}
```

`launch` starts a new program, while `attach` connects to an already running target. Put attach options such as `port` and `processId` in the launch configuration. The TCP connection port field is the **adapter** port, which differs from the debug target's port. Substitute `${workspaceFolder}`, `${workspaceFolderBasename}`, and `${env:NAME}` in the launch configuration using the server environment. Do not write substituted environment variable values to the saved file. Executable variables such as `${command:…}` and `${input:…}` and automatic build/task execution are not supported.

### Browser Connections and Adapter Port Errors

Connect to an already open Chromium tab using js-debug's `pwa-chrome` launch configuration and `attach`. In the launch configuration, `address` and `port` specify the browser's CDP address and port, `urlFilter` specifies the target app URL, and `webRoot` specifies the app source root. The browser port may change after a restart. The Vite development server provides TypeScript source maps; breakpoints on original source lines are limited in builds without source maps.

“Adapter TCP port was not detected” is an error during adapter startup, before connecting to the browser. If the js-debug executable is `node`, its arguments are `[]`, and the TCP port is `0`, Node waits for input instead of running the adapter, causing this error. Click **Current Project Settings → Debugger → Install js-debug** again to reuse the installed files and populate the server's Node path, the `[dapDebugServer.js 절대 경로, "0", "127.0.0.1"]` arguments, and TCP port `0`. Then confirm that the execution mode is **Attach** and the launch configuration is `pwa-chrome`, and save. The installation indicator shows whether shared server files exist; it does not mean that execution arguments are configured for each account and project. Switching the adapter selection again may reset the arguments to their defaults, so reapply them using the install button. In environments without a system Chrome installation where Mew uses Playwright Chromium, also set `runtimeExecutable` in the launch configuration to the absolute path of the actual Chromium executable. Otherwise, the adapter may fail to find a browser installation during initial startup and terminate the connection.

If saved settings were corrected externally, an open settings screen may still contain the old values. Close and reopen settings to reload them before starting. Do not use actual environment paths or browser ports as fixed values in documentation.

### Panel and Sessions

- Open a separate panel using the debugger icon in the dock or **Open Debugger** in settings. It follows the existing dock layout, mobile foreground stack, and per-account project UI restoration. Settings and panel components are lazy-loaded, and closed panels do not poll state. The code editor's gutter and execution position indicators separately share polling for the current root and account, which is canceled when the last editor closes.
- Provides Start, Continue, Pause, Step Over, Step Into, Step Out, and Disconnect. Duplicate default starts are rejected; **Start Additional Session** or **Compound Launch** allows up to 8 independent sessions per account and project. Session, child connection, and thread selection are provided, with separate capabilities and references for each. While any session is running, changes to connection and launch profile settings are rejected, but dynamic settings such as breakpoints and watches can be changed. Installing, viewing settings, or opening the panel alone does not run the adapter. External processes are created only on **Start** or **Test Connection**. The test closes the connection and managed processes after initialize.
- Add, disable, or delete breakpoints in the panel using a source path and a line number starting at 1. Entering part of a filename or path, or `@검색어`, in the source file field shows file candidates under the current project root through the existing filename search API. Selecting a candidate only fills in the relative path; it does not automatically add a breakpoint. Direct path entry remains available. The shared editable `SelectField` supports arrow-key and Enter selection, clicks and touch, closing with Esc, Back, or an outside press, and viewport boundaries for the portal list. Search requests are delayed by 180 ms, and previous requests are canceled when the input or project changes. The list displays ready, no-results, and error states. Results from the separate Documents scope are excluded. Relative source paths are based on the project root. Adapter verification status and messages are displayed, and changes made during execution are also sent. In the code editor, clicking or touching a line number or pressing `F9` toggles breakpoints in the same saved settings without a separate breakpoint column. Line numbers remain visible; verified breakpoints use a solid accent color, unverified breakpoints use an outline, and disabled breakpoints use a faint dashed outline. Partial previews display and save original file line numbers. The line-number gutter is fully transparent in every theme, with no background color or background blur, and remains fixed during horizontal scrolling. When edits move lines or columns, the affected breakpoints and dependent breakpoint keys are updated. The execution line of the currently stopped frame is highlighted, and `Shift+F9` runs to the cursor. Hover evaluation is performed only for simple identifiers when the file has the current top frame and `supportsEvaluateForHovers` is available. mew does not replace running code in response to source edits.
- Fetches the call stack on a stopped event. Selecting a stack row reads that frame's variables and opens the source file and line in the editor if they are inside the project. Sources outside the project are not currently opened in the editor.
- Reads default variables excluding expensive scopes, and reads children only when an object is expanded. Compares values with the previous stop using the same connection, thread, source, frame name, scope, and variable name. Changed default variables are placed first and marked. The initial fetch is not marked as a change. Change indicators are retained when fetching again at the same stop.
- Pin watch targets using a variable's pin button or by entering an expression. Evaluates them in the current frame at every stop and displays value changes. Expression errors are shown on the corresponding watch value. The pinned list persists after sessions end and documents are edited.
- Closing the panel does not end the session. **Disconnect** requests termination of launch targets and preservation of attach targets. Adapters and terminal child processes started by mew are cleaned up on disconnect, errors, or permission revocation. DAP sessions are not restored after the server process restarts.

### Panel Display and Controls

- The header shows the current execution state, with an execution toolbar directly below it that is separate from body scrolling. The primary button changes to **Start** when ready, **Continue** when stopped, and **Pause** when running. Disconnect, stepping, and restart follow the existing capability and execution state checks. The panel uses the shared `PanelCloseButton` to close.
- Use **Session and Execution Options** to select profiles, compound launches, independent sessions, targets, threads, stepping granularity, stop history, reverse controls, and additional sessions. This area is collapsed by default. Selecting a historical record shows a history state in the header and disables execution controls.
- Before execution, source breakpoint settings appear first; while stopped or viewing history, the call stack and variable values appear first. Function, exception, data, and instruction breakpoints are managed under **Advanced Breakpoints** within source breakpoints. Collapsible areas for the main lists, settings, console, memory, browser, and analysis files use the same headers and expansion indicators and support keyboard operation.
- Use **+** next to the breakpoint or pinned watch section title to open or close the input form. Pressing **+** in a collapsed section opens both the section and the form. An empty path or expression disables the Add button, and adding an item closes the form. Expand **Breakpoint Options** inside the form to access the breakpoint column, hit count, condition, and log. Session and Execution Options and Test Debugging are also collapsed by default.
- Sections expanded or collapsed by the user retain their state during live updates within the same execution state. When the default display conditions change, such as when switching between stopped and running, the section's default state is applied. The call stack and variables sections expand on a stop. In touch environments, execution buttons, input fields, and section titles maintain a minimum height of 44 px.
- List titles show item counts in small badges. Source breakpoints separate the filename from the line/column, with the full path provided in a tooltip and accessible name. The stack distinguishes the selected frame; variables distinguish actual changed values and data type colors, and already pinned values have their duplicate pin buttons disabled. Empty lists, loading, failures, and successful saves are indicated. Errors and primary buttons follow semantic color tokens in both themes.
- Candidate rows in source file and test file selection lists use heights of 28 px on desktop and 32 px on touch devices, with 12 px text. Long paths are truncated with an ellipsis on a single line, while the full path is retained in the accessible name and selected value. Lists follow the shared `SelectField` behavior for viewport boundaries, internal scrolling, keyboard selection, and closing.
- Execution buttons, inputs, long paths, and values stay within the panel even when it is narrow; analysis tables and memory dumps scroll within their own areas. Settings are grouped into adapter, launch JSON, profiles, and compound launches, preserving JSON input and the existing save, test, and install actions.

`server/editor-gutter-ui.test.ts` connects the actual CodePane to mock debugger responses and checks a single line-number column, click/touch/F9 toggling, state-specific indicators, partial-preview line numbers, transparent backgrounds, no blur, fixed positioning during horizontal scrolling, and preserved transparency even in solid-color themes at 390/1100 px in Midnight/Rose/Ocean. `server/debugger-advanced-ui.test.ts` uses an isolated DAP adapter and live state connection to check breakpoint and dependent-key movement during edits together with execution-line display.

### Implementation and Boundaries

- Provides settings retrieval and saving, installation, connection testing, session start and stop, and allowed DAP commands under HTTP `/api/debugger`. Checks the current project header and also compares session IDs for commands and termination. Per-account and per-project settings files are saved atomically in the data folder. If the adapter exits before reporting a TCP port, waits for stderr to close and returns the exit code, signal, and recent error lines. Long bundled source lines are excluded from the error summary, which is limited to 2,000 characters.
- Handles byte lengths in DAP headers and fragmented UTF-8 frames, and provides request timeouts and rejection on disconnect. Handles js-debug's `startDebugging` reverse requests by creating separate child connections to the same adapter. Executes `runInTerminal` using argv without shell string interpretation and tracks it as a managed process.
- Requires owner or manager status, the terminal feature, and permission to read and modify all files in the project. Execution and installation run with the server's OS permissions. Running sessions are revalidated on policy changes while connected and in periodic checks every 5 seconds. Detailed permission boundaries follow [Per-Account Feature and File Permissions](../../development/access-control.md).
- Output is limited to the most recent 64,000 characters. Limits are 8 MiB per DAP message, 16 connections per session, 64 retained sessions across the server, 200 breakpoints per configuration, and 64 pinned expressions. Stacks are fetched in batches of 40 up to 200 entries, and each variable fetch is limited to 200 entries. Additional object pages are limited to 2,000 entries in the UI, and variable references are limited to 5,000 per connection. Memory requests are limited to 4,096 bytes, disassembly to 256 instructions, and virtual sources to 512 KB. Arbitrary DAP requests and automatic language runtime installation are not provided.

Control and query operations check the session ID, connection ID, and stop revision, and do not reuse frame, variable, or execution target IDs obtained before resuming or switching threads. Launch configurations and profile JSON are edited in settings, with up to 32 profiles and a total settings size of no more than 1 MB.

### External Analysis Files

Following removal of the general DOM browser, the panel's **Browser Analysis** and CDP connections to Mew tabs were removed. The compatibility state API returns an empty tab list and rejects new connections with HTTP 410. The virtual login screen is not exposed as a debugging target. Existing settings for connecting a separate browser through DAP's `pwa-chrome` and external DAP support such as Node.js are retained.

**Analysis Files** reads files up to 8 MB selected by the user in the browser. It displays actual sample self time from `.cpuprofile`, allocation self size from `.heapprofile`, summed per-object self sizes from `.heapsnapshot`, function execution counts from V8 coverage, span durations and trace/parent relationships from OTLP JSON, error and stack locations from sanitizer text, and mew stop history JSON in limited tables and value bars. Provides search, additional rows, original-file export, and navigation to source paths that can be opened in the project. Files are not automatically uploaded to the server or saved in documents.

CPU/heap tables do not calculate cumulative/retained size or full call trees. Coverage does not provide source map validation or editor line indicators. OTLP analyzes imported files and does not create collector/service instrumentation or live queries. Reading sanitizer reports does not replace sanitizer builds or error detection.

### Agent Debugger Connection

Enabling **Settings → Debugger → Allow Project Agents to Use the Debugger** and starting a new regular agent tab passes the `mew-debugger` MCP to ACP. It is off by default; enabling it alone does not start a debug target or install an adapter. The MCP list of an already running independent supervisor is not replaced, so reconnecting an existing tab alone does not add it. Provider MCP configuration files are not modified, and Mewcat's existing MCP list is retained. Connections for scheduled and one-off runners are outside this scope.

- `debugger_state`: Retrieves the account and project's session list and the selected session's current capabilities, connections, stop revision, stack, and already read history. Does not automatically evaluate expressions.
- `debugger_command`: Executes allowed debugger commands using `sessionId` and the most recently queried `arguments.connectionId` and `arguments.stopRevision`. Variable/stack reference checks, per-command capability checks, stopped-state checks, and size limits are the same as for the HTTP routes. Expression evaluation, value/memory writes, and execution control can change the target's state, so agents also follow existing task and execution restrictions. Arbitrary DAP or CDP requests are not provided.
- `debugger_start` / `debugger_stop`: Starts the saved default configuration or a profile specified by name and stops the exact session. Launch configuration authoring, tool installation, and compound launches are not exposed as MCP tools. The launch/attach termination contract is the same as in the panel.

MCP relays to the server through per-account and per-project Unix sockets (file `0600`, directory `0700`). Checks owner or manager status, `agent` and `terminal`, permission to modify all project files, and the sharing option on every call, on policy changes, and every 5 seconds. Relay connections close when sharing is disabled, permissions are revoked, or the project changes. Responses are limited to 1.5 MB, state query output to the most recent 8,000 characters, and history to the most recent 8 records with 100 variables each. The agent connection itself and session lifetime are owned by the [Agent Session Contract](../../development/agent-sessions.md#agent-debugger-mcp).

### Remaining Scope

Hardware breakpoint registers, JTAG, remote kernel debugging, full process core dumps, code injection, Wasm/DWARF engines, and static analysis engines have not been implemented as native mew features. Features of prepared external DAP/native REPL tools can be used through the current path, but require equipment, OS, and engine setup and actual validation for each language. Collaborative session sharing and control transfer, test listing/failure detection, an E2E trace viewer, and telemetry collection APIs are separate implementation scopes. Distinguish proposals in the investigation records below from current support.

### Debugging exercise: aggregating student grades

[examples/debugger/grades.cjs](../../../../examples/debugger/grades.cjs) is a Node.js program at the first- to second-year level (1–2), using only arrays, objects, functions, loops, and conditionals. It calculates averages for three students and determines whether each passes with a score of at least 80. It uses no external packages, input, or file writes and exits after calculating. The default mode contains one intentional average calculation error for practice.

Select js-debug and launch in settings, enter the JSON below in the launch configuration, and save. The absolute path below is the current mew repository location; on other servers, replace it with the actual example path. `args` in the **launch configuration** contains the example program's arguments, not the adapter arguments.

```json
{
  "type": "pwa-node",
  "program": "/home/saens/dev/mew/examples/debugger/grades.cjs",
  "cwd": "/home/saens/dev/mew",
  "console": "internalConsole",
  "args": []
}
```

1. In the debugger panel, add a breakpoint at line **15** of source `examples/debugger/grades.cjs`, then start. Watch and pin `index`, `score`, and `total`, then continue execution to repeat the score accumulation process. At the first two stops, `score` changes from 85→90 and `total` from 0→85. Breakpoints stop **before** the line executes.
2. Start at line **28** and click Step Into to inspect the `analyzeStudents → calculateAverage` calls and differences in the stack and local variables. At line **19**, compare `total` and `count` to find why the average is lower than expected.
3. End the session and change `args` in the launch configuration to `["--fixed"]` to compare with normal mode. The correct averages are 90 for Minsu, 70 for Jiyeon, and 95 for Seojun, with 2 students passing. The default error mode prints averages of 67.50, 52.50, and 71.25, with 0 students passing. You can also fix the incorrect divisor in the program directly and check the result.

Compare the results in the terminal as well using `node examples/debugger/grades.cjs` and `node examples/debugger/grades.cjs --fixed`. On 2026-10-07, execution and output were checked in both modes, and a real js-debug adapter was used to verify stopping at line 15, inspecting the stack, and changes to `total` and `score` over two iterations. No app build is required because only an executable file was added.
