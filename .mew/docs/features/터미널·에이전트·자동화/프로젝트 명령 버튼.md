## 요구사항

- 현재 프로젝트의 반복 명령을 버튼으로 실행하고 출력을 본다.

### 범위

- 프로젝트 사이드바가 닫혀 있거나 모바일이면 상단바 프로젝트 타이틀 바로 오른쪽에 ▶ 버튼을 둔다. 데스크톱 프로젝트 사이드바가 열려 있으면 각 프로젝트 행의 ▶로 같은 명령 메뉴를 연다. 드롭다운에서 기존 항목으로 프로젝트별 명령 등록·수정·실행·정지와 전용 터미널 팝업을 제공한다.
- 비활성 프로젝트 행의 ▶는 해당 프로젝트의 명령만 다루고 현재 프로젝트를 전환하지 않는다. 조회·저장·실행 요청과 폴링을 대상 프로젝트에 고정하며 서버는 경로와 기존 권한을 다시 확인한다. 현재 프로젝트가 worktree를 사용 중이면 현재 행은 선택한 실제 작업 루트를 사용한다. 루트 프로젝트의 명령 세션은 실제 폴더 경로와 명령 이름으로 구분해 다른 루트의 같은 이름 명령과 격리한다.
- 버튼을 눌러도 파일 탐색기나 별도 작업 패널을 열지 않는다. 목록은 바깥 누름·Esc·뒤로가기로 닫는다.
- 프로젝트·햄버거 드롭다운이 열린 상태에서 ▶ 버튼을 한 번 클릭하거나 터치하면 기존 메뉴를 닫고 명령 목록을 바로 연다. 명령 목록에서 다른 상단 메뉴 버튼을 눌러도 같은 방식으로 전환한다.
- 명령 추가를 누르거나 명령 이름을 우클릭·길게 눌러 수정 창을 열 때는 드롭다운을 먼저 닫는다. 메뉴가 편집 창 위에 남아 입력을 가리지 않으며, 편집 창을 취소·Esc·뒤로가기로 닫아도 목록을 다시 열지 않는다.
- Alt+R 또는 기존 Ctrl+E는 브라우저 기본 동작과 편집기·터미널 입력을 차단하고 현재 프로젝트의 명령 목록을 연다. 프로젝트 사이드바가 열려 있으면 현재 프로젝트 행의 ▶, 닫혀 있거나 모바일이면 상단바 ▶를 사용한다. 목록을 불러온 뒤 첫 실행 가능한 명령 이름에 포커스를 두며, 빈 목록에서는 명령 추가에 둔다. 이미 열려 있으면 같은 위치로 돌아간다. 원격 화면의 전용 키보드 입력 우선권은 유지한다.
- 보조키 없는 1~9와 숫자패드는 목록 순서의 명령을 이름 클릭과 같이 실행한다. 처음 9개 항목의 오른쪽 끝에 번호를 표시하고 `aria-keyshortcuts`를 제공한다. 포트·정지·터미널·추가·정렬 핸들은 숫자 선택 대상에서 제외한다.
- 프로젝트 목록과 같은 왼쪽 핸들·가운데 이름·오른쪽 번호 배치를 사용한다. 핸들을 마우스·터치로 끌거나 핸들의 ↑/↓·행의 Shift+↑/↓로 정렬한다. 순서는 기존 프로젝트 명령 파일에 저장하며 명령 내용·완료 후 종료 옵션·실행 상태를 유지한다. 연속 저장은 순서대로 처리하고, 저장 중에는 상태 폴링으로 순서를 덮어쓰지 않는다. 저장 실패 시 마지막 저장 순서로 되돌리고 오류를 표시한다.
- 실행 중인 명령은 별도 체크나 점 대신 핸들·버튼을 포함한 항목 전체 배경으로 강조한다. hover·focus도 항목 전체에 표시하며, 포트 버튼은 같은 항목의 아래 줄에 둔다.
- 위·아래 방향키는 명령 행과 명령 추가 사이를 순환하고, 좌·우 방향키는 같은 행의 이름·실행/정지·터미널 버튼 사이를 순환한다. 비활성 버튼은 건너뛰며 Home/End는 첫 행/마지막 행으로 이동한다. Enter/Space는 포커스된 버튼을 실행하고 Esc로 닫으면 ▶ 버튼으로 포커스를 돌린다.
- 목록 상단에 `.workspace` 등 내부 프로젝트 식별자를 표시하지 않는다.
- 목록은 햄버거·프로젝트 메뉴와 같은 공용 `ActionMenuSurface`의 헤더 스타일을 사용한다. 너비·글꼴·행 높이·여백·포커스 표시 기준은 [공용 UI 계약](../../development/ui-contracts.md#드롭다운과-선택-컴포넌트)을 따른다.
- 이전에 저장한 파일 탐색기 명령 탭은 파일 탐색기로 복원한다.

### 경계와 제한

- 목록에 등록된 하위 프로젝트도 사이드바 행의 ▶를 사용할 수 있다. 목록에 없으면 해당 프로젝트를 먼저 연다.
- 버튼 설정은 프로젝트별이며 현재 셸에 문자열을 넣는 전역 터미널 버튼과 다르다.
- 루트 세션 식별자 변경 전에 실행한 명령은 자동 종료하지 않는다. 새 메뉴에서 해당 세션의 실행 상태를 이어서 표시하지 않으며 기존 터미널로 확인·종료한다. 하위 디렉터리 명령도 같은 실제 폴더 기준으로 식별한다. [결정 0082](../../decisions/0082-desktop-project-sidebar.md)를 따른다.

## 구현 내용

## 검증

- `server/cmd-button-workspace.test.ts`·`server/cmd-button-workspace-ui.test.ts`는 현재 프로젝트를 바꾸지 않는 대상별 명령 요청과 서버 권한·실행 경계를 검사한다. 루트 명령의 폴더별 세션 식별자는 `server/cmd-button-workspace.test.ts`에서 검사한다. 수행 결과와 이전 세션 제한은 [프로젝트 사이드바 작업 기록](../../work/desktop-project-sidebar.md)을 따른다.
- `server/header-menu-switch-ui.test.ts`는 PC·모바일과 밝은·어두운 단색·그라데이션에서 프로젝트·명령·햄버거 메뉴의 한 번 누름 전환·기존 메뉴 닫기·포커스·Esc/뒤로가기와 일반 바깥 클릭 차단을 검사한다.
- `src/utils/command-menu-keyboard.test.ts`는 Ctrl+E 기본 동작·전파 차단, 반복·수정키·IME 제외, 원격 입력 우선권과 방향키 순환·비활성 버튼 제외를 DOM 환경에서 검사한다.
- `server/overlay-layers-ui.test.ts`는 PC·모바일과 밝은·어두운 그라데이션에서 추가·우클릭 수정·길게 눌러 수정할 때 목록이 사라지고 편집 창이 입력을 받는지, 취소·Esc 후 목록이 닫힌 상태를 유지하는지 검사한다.
- 아래 항목은 이번 정리에서 실행한 테스트 결과가 아닌 사용자 확인 기준이다:
  - 선택 프로젝트의 cwd·명령 파일로 실행되고 팝업 닫기와 프로세스 종료가 구분되는지 확인한다.
