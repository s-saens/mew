## 요구사항

- 계정과 파일·기능 접근 범위를 관리한다.

### 범위

- 내 프로필·비밀번호·로그아웃, owner의 계정·역할·기능/파일 권한 관리와 guest 경로 공유를 제공한다.

- 내 계정은 프로필 사진 오른쪽 위에 **내 계정**과 이메일을 두고, 그 아래에 표시 이름 입력칸과 **저장** 버튼을 나란히 둔다. 프로필 사진은 **기본**, **사진 선택**, **클립보드에서 붙여넣기** 메뉴를 여는 버튼으로 사용한다. 별도의 파일 선택·사진 제거 버튼과 확장자·용량 안내 문구는 표시하지 않는다.

- 기능·파일 권한 표는 열에 프로필 사진, 행에 역할·권한 항목을 둔다. 사진이 없거나 읽기에 실패하면 기본 아이콘을 표시한다. 사진을 누르면 이름·계정 ID, 역할 변경과 계정 삭제를 제공한다. guest는 그룹 아이콘과 이름만 표시한다.
- 삭제는 팝업 안에서 다시 확인하며 실패하면 같은 자리에서 재시도할 수 있다. 본인과 마지막 owner는 삭제할 수 없다. 계정 삭제 시 로그인과 기능·파일 권한을 회수하되 프로젝트 파일·개인 설정·작업 기록은 보존한다.

- Mewlink 로그인 신원의 접근 요청을 owner가 승인하면 비밀번호 없는 member를 바로 등록하고 승인된 계정 목록에 표시한다. 역할은 계정 관리에서 변경한다.
- 기존 이메일 계정이 있는 사용자는 **설정 → 계정 → Mewlink 계정 연결**에서 본인이 연결한다. 같은 접속의 검증된 Mewlink 신원과 완료된 이메일 비밀번호 로그인을 함께 요구한다. 기존 Mewlink 연결도 옮길 수 있으며 이메일 계정의 권한·개인 설정을 사용한다. 로그인 수단이 남지 않는 이전 계정은 병합과 함께 삭제하고 세션·Git 자격증명·기능·파일 권한을 회수한다. 비밀번호나 다른 외부 신원이 남은 계정은 유지하며 마지막 owner 삭제는 거부한다. 이전 작업 기록과 파일은 보존하고 대상 계정으로 자동 이관하지 않는다. 같은 이메일·기기 등록 계정으로 자동 연결하지 않는다. 연결 해제는 외부 로그인만 회수한다.

- Mewlink 기기 등록·연결 설정은 owner 전용 햄버거 메뉴의 **Mewlink**에서 별도 창으로 연다. 계정 관리에는 외부 신원의 접근 승인·회수만 둔다.

### 경계와 제한

- 공개 회원가입은 없다.
- guest 공유는 모든 비로그인 방문자에 대한 경로 규칙이며 개인 초대 링크가 아니다.
- 서버 제어 기능은 파일 권한으로 샌드박싱되지 않는다.

## 구현 내용

- 내 계정의 사진 버튼은 마우스를 올리거나 키보드로 포커스하면 검은 덮개와 연필 아이콘을 표시한다. 공통 `ActionMenu`에서 **기본**은 사진 초안을 기본 표시로 되돌리고, **사진 선택**과 **클립보드에서 붙여넣기**는 이미지 초안을 갱신한다. 사진과 표시 이름은 **저장**으로 함께 반영한다. JPG·PNG·WebP·GIF와 512KB 이하 검증은 유지하며 조건에 맞지 않는 이미지를 선택하거나 붙여넣으면 오류를 표시한다. 클립보드 읽기 미지원·권한 거부·이미지 없음도 오류로 알린다.
- 계정 관리 창은 공통 `DialogFrame`의 포커스 가두기·복원과 Esc·뒤로가기 규칙을 사용한다. 작은 제목·계정 수·추가/닫기 아이콘을 헤더에 모으고, 이메일 추가 폼은 추가 버튼으로 펼친다. 기능·파일 권한은 짧은 탭으로 전환하며 반복 안내는 접고 Mewlink 접근 관리는 아래에 둔다. 창 크기는 설정과 같은 데스크톱 너비 740px·높이 70vh, 모바일 전체 화면으로 고정하며 본문 안에서 스크롤한다.
- 계정 추가 폼은 데스크톱에서 이메일·역할·추가 버튼을 한 줄로 정렬한다. 640px 미만에서는 이메일을 첫 줄, 역할·추가를 다음 줄에 두며 조작 높이를 맞춘다. 저장 중에는 입력과 폼 접기를 막고 실패는 `role="alert"`로 알린다. 발급된 임시 비밀번호의 닫기는 이름·툴팁이 있는 X 아이콘을 사용한다.
- 계정 사진 팝업에는 프로필·자체 역할 선택기·삭제 동작을 묶는다. 가장 가까운 `DialogFrame` 안으로 portal하고 실제 fixed 원점을 측정해 배경 블러로 생기는 좌표 오프셋을 뺀다. 사진 아래 4px에 열고 아래 공간이 부족할 때는 더 넓은 쪽을 택한다. 모달과 visual viewport의 교집합 안에 8px 여백을 둔다. 최대 너비는 288px이고 높이가 부족하면 팝업 내부에서 스크롤한다. 표 스크롤·화면 크기·테마·내용 크기가 바뀌면 다시 배치한다.
- 사진 팝업 안의 역할 목록은 같은 모달에 별도로 portal해 사진 팝업의 스크롤 경계에 잘리지 않게 한다. 역할 필드와 목록은 160px 너비를 사용한다. 역할 목록·사진 팝업·모달은 Esc·뒤로가기로 한 겹씩 닫고, 사진 팝업을 닫으면 호출 사진으로 포커스를 돌린다. 사진과 닫기 버튼의 터치 영역을 확보하며 마지막 owner의 역할 변경·삭제 버튼은 비활성화한다.
- owner 전용 `DELETE /api/admin/users/:accountId`는 존재 여부·본인·마지막 owner를 검사한다. 비밀번호·신뢰 브라우저 세션·Mewlink 연결과 승인 요청, 모든 워크스페이스의 계정별 파일 규칙·기능 덮어쓰기를 제거한다. 같은 ID를 다시 등록해도 이전 세션·권한을 되살리지 않는다. 데모는 동일한 삭제·보호 동작을 탭 안의 가상 상태에 적용한다.

- 기능·파일 권한 표는 창 전체 너비로 늘리지 않고 내용 너비에 맞춘다. 항목 열은 128px, 기능 권한의 계정 열은 64px로 둔다. 역할 행은 owner 왕관·manager 체크 방패·member 사람 아이콘 버튼을 사용하며, 누르면 같은 아이콘과 역할 이름을 함께 표시한 목록에서 선택한다. guest는 그룹 아이콘으로 표시하고 역할을 바꿀 수 없다. 마지막 owner의 역할 버튼은 비활성화한다. 파일 권한 열은 선택 문구에 맞춰 넓어진다. 계정이 많거나 화면이 좁으면 표 안에서 가로로 스크롤한다.

- 기능 권한은 역할과 각 기능을 행으로, 파일 권한은 설정·현재 적용 값을 행으로 표시하며 프로필 사진 머리글을 공유한다. 머리글과 항목 이름은 표 내부 스크롤 중 고정한다. 기능 표의 표시 영역은 최소 96px을 확보해 낮은 창에서도 사진 버튼을 누를 수 있게 하고, 필요한 경우 바깥 본문도 스크롤한다. 사진의 계정 제어 팝업은 화면 안에 배치하고 바깥 누름·Esc·뒤로가기로 먼저 닫는다. 역할·파일 권한 선택은 작은 공통 드롭다운을 쓰고 기능별 기본값 복원은 체크박스 옆 아이콘으로 제공한다. 역할 목록의 아이콘은 계정 사진 팝업과 새 계정 추가 폼에서도 공유한다.

- 로그인 화면의 Mewlink 로그인·접근 요청·승인 대기와 owner 계정 관리의 즉시 승인·거절·연결 해제를 제공한다. 내 계정에서 기존 이메일로 로그인한 본인이 Mewlink 연결을 추가하거나 옮긴다. 이미 승인된 연결을 옮기면 연결 ID를 새로 발급하고 기존 외부 접속 권한을 회수한다. 병합 후 로그인 수단이 없는 이전 계정은 계정 디렉터리에서 원자적으로 삭제해 계정 관리·권한 표에 중복 계정을 남기지 않는다. 신규 사용자는 로컬 비밀번호를 만들지 않으며 설정에서 비밀번호 변경 폼을 숨긴다. 기존 이메일 로그인·임시 비밀번호 변경은 유지한다.
- 계정·비밀번호·외부 연결·요청은 `users.json` v2에서 분리해 원자적으로 저장하며 기존 이메일 ID·데이터는 유지한다. 외부 인증의 프로필 변경은 기존 비밀번호 변경 요구를 지우지 않는다.

- 계정 추가·역할 변경·파일 경로 범위·파일 권한 선택은 공통 자체 드롭다운을 사용하며 기존 저장·권한 경계를 유지한다.

- 내 프로필·비밀번호·로그아웃, owner의 계정·역할·기능/파일 권한 관리와 guest 경로 공유를 제공한다.

## 검증

- `account-access-ui.test.ts`는 라이트·미드나이트·다크와 1366px·390px·320px의 9개 조합에서 창 크기·64px 계정 열, 추가 폼 정렬, 사진 팝업의 모달 경계·호출 사진과의 간격, 역할·파일 권한 목록의 위치·실제 클릭 영역과 중첩 Esc 닫기를 검사한다. 1366×360·390×480에서는 삭제 확인·테마 변경 중 팝업의 화면 경계도 확인한다. 역할·기능·파일 권한 저장, 키보드 입력과 삭제 취소·실패 후 재시도·성공 시 양쪽 권한 표의 계정 제거를 함께 검증한다. 격리 Chromium 검사이며 실제 운영 화면 반영은 사용자 빌드 후 확인한다.
- `admin-users.test.ts`는 owner 인가, 본인·마지막 owner 보호, 비밀번호/외부 계정 삭제, 모든 로그인·워크스페이스 권한 회수와 파일·기록 보존, 같은 ID 재등록 시 이전 세션의 무효화를 격리 환경에서 검증한다. 데모 삭제·재등록은 `src/demo/host.test.ts`로 확인했다.

- `account-access-ui.test.ts`에서 사람 열·항목 행, 아이콘 클릭·키보드 입력으로 여는 이름·이메일 팝업과 바깥 누름·Esc·뒤로가기 우선 닫기, 역할·기능·파일 권한 저장, 기능 기본값 복원과 저장 실패 시 상태 유지를 검증했다. 밝은·어두운 테마의 PC 1366px·모바일 320px·390px에서 창과 팝업이 화면 너비를 넘지 않는지도 확인했다.

- `mewlink-identities.test.ts`, `remote-mewlink-auth.test.ts`에서 이관·owner 승인·비밀번호 없는 사용자·허위 신원·계정 전환·회수를 검증했다. `mewlink-identity-ui.test.ts`에서 승인 요청·대기·즉시 승인·거절·회수, 본인 이메일 로그인 후 연결·오류 재시도와 PC/모바일 양 테마를 확인했다. `remote-mewlink-auth.test.ts`는 본인 연결의 신원·비밀번호 세션·임시 비밀번호 경계, 허위 대상 입력, 중복·충돌·지연 요청과 이전 접속 회수를 검증한다.

- 아래 항목은 이번 정리에서 실행한 테스트 결과가 아닌 사용자 확인 기준이다:
  - 프로필 사진의 호버·키보드 포커스 표시, 사진 메뉴의 세 동작, 사진·이름의 저장과 실패 후 초안 유지, 클립보드 오류, 좁은 화면에서 사진 오른쪽 입력칸·저장 버튼 배치를 확인한다.
  - 역할 기본값·계정별 덮어쓰기·경로 상속·권한 회수와 마지막 owner 보호를 확인한다.
