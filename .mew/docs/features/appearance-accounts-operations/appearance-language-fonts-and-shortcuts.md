## Requirements

- Themes are saved to accounts on the same Mew instance and applied across all devices. Device-specific settings such as language, fonts, and key combinations retain their existing scope.
- If there is no account theme or browser setting to migrate, use Midnight with an animated gradient by default. Preserve previously saved presets, custom themes, legacy modes, and theme colors.
- During initial app loading, authentication checks, and workspace preparation, show only the selected theme's full background and the centered text **Connecting…**. Follow dark, light, and custom solid-color and gradient backgrounds, and do not show the header, file explorer, or panel skeletons. Use the same screen for initial loading in browser popups.
- Apply the close-tab key to internal tabs in the focused file, agent, terminal, or similar panel. If there is no tab to close, do not close a tab in another window.

### Scope

- Select background, text, and accent colors as one theme, with solid-color and gradient presets and custom themes available. Gradients support configuring two colors, direction, and background animation. Also provide language, font, and shortcut configuration and reset.

- The **Dock** category provides independent desktop and mobile placement (top, bottom, left, or right), item visibility, ordering, a live preview, and restoration of defaults. Desktop defaults to left; mobile defaults to bottom.

### Boundaries and limitations

- Theme selection and custom theme lists are per account. Changes from other devices are applied through real-time signals and when returning to the screen or reconnecting. Other appearance settings, including language and fonts, are per browser.
- Fixed editing shortcuts cannot be changed. Fonts that are neither loaded as web fonts nor installed on the device use a system fallback.

### Detailed contracts

- [Account and appearance settings](../../../../docs/configuration/appearance.md) · [Focus-based shortcuts](../../development/ui-contracts.md)

## Implementation details


- The server and browser share the palette and normalization in `shared/theme.ts`. `useAccountTheme` saves the signed-in account's selection and custom theme list on the server and applies the latest theme on presence change signals for the same account, when returning to the screen, and when reconnecting. Existing browser selections are migrated only when the server has no account theme. Stale copies and late responses do not overwrite the latest selection. If saving fails, the selection is retained, an error is reported, and saving is retried on the next return, reconnection, or change. Account switching and browser cache and demo boundaries follow the [account theme contract](../../development/browser-storage.md#account-themes).

- `Ctrl/Cmd+,` opens the settings popup. If it is already open, it stays open. The app handles it first even in editors, terminals, and input fields, while forwarding to the remote takes priority during login video and remote desktop input. Combinations with additional Shift or Alt modifiers and IME composition input are not handled; key repeats are consumed without action.

- On mobile screens (below 768px), browser or device Back from a settings detail screen returns to the settings list. Pressing Back again from the list closes only the settings window. This also applies when entering Mewpet or debugger settings directly. Open dropdowns, color pickers, and custom editing areas handle Back first; the Back button within the settings screen returns to the list. `useOverlayDismiss.closeOnBack` in `SettingsModal` checks the current screen width and detail state and returns `false` when returning to the list to retain the shared History guard. Desktop Back and Esc and Close buttons on all screens close the settings window as before.

- `DockSettingsPanel` and `useDockPreferences` share dock visibility, order, and per-device-class edge preferences. Position fields use the shared custom `SelectField` inside the settings portal and apply immediately. Only available items are shown, and hiding an item keeps its open panel intact. Mobile and PC, light and dark themes, and four languages are supported. Storage, permissions, and reset scope follow [Dock settings](../../../../docs/configuration/appearance.md#dock-settings).

- `Ctrl/Cmd+N/T` opens a new tab in the focused agent or terminal, or opens the new file name input in the editor or file explorer. `Ctrl/Cmd+Shift+N` uses the existing new folder flow (new document in the document tree). Existing Alt combinations and user remappings are also retained.
- `Ctrl/Cmd+Tab/Shift+Tab/PageUp/PageDown` and the existing `Alt+Q/E` cycle through the focused panel's previous and next tabs. `Ctrl/Cmd+1…9` selects internal tabs in display order and ignores numbers with no matching tab. The same boundaries apply to split editors, portal terminals, browser iframes, the file explorer, and tasks.
- `Alt+1…9` selects project tabs in their display order in the header. It follows grouping and rearranged order, independently of the focused panel. It does not switch for the current project, an unmatched number, a modal, key repeats, or lack of owner permission. When the remote screen has focus, it is forwarded to the remote.
- `Ctrl/Cmd+W/Shift+W` closes one focused internal tab. The standard Ctrl/Cmd combinations are fixed aliases and remain available even if custom shortcuts change. Repeated, IME, and modal input for creation and closing is consumed without manipulating background tabs.
- In JavaScript fullscreen activated by the mew button, creation, closing, number, navigation, and R keys are locked, while the remote screen receives all keys at a higher priority. `Ctrl/Cmd+R` in the agent panel is used to [Clear conversation](../terminals-agents-automation/agent-conversations-queue-and-restoration.md#clear-conversation-shortcut). The app's lock is restored when returning from the remote. Reserved-key restrictions in regular Chrome windows, the path for choosing a Chrome app window, and verification follow the [focus contract](../../development/ui-contracts.md#focus-based-tab-shortcuts).

- Language and font selection use the shared `SelectField` component's custom dropdown. Fonts are displayed in a 3-column grid, with each appearance, document, and code label, input/selection field, and reset button on the same row. Shared label widths align the start of the selection fields, and each row stays on one line even on narrow screens. No separate font guidance is provided, and each label is associated with its input's `id`. Direct font name entry, reset, and per-browser storage are retained.

- Korean, English, Simplified Chinese, and Japanese settings also apply to status messages and accessible names in agents, editors, search, Git, scheduling, remote desktop, and shared packages. Drafts, search queries, and body content are retained when switching languages, and missing translations are checked according to the [UI translation contract](../../development/ui-contracts.md#ui-translation).

- `ThemeButton` displays `A` in the text color and `a` in the primary color on a rounded rectangle with the selected solid or gradient background. Selection is indicated by a border, checkmark, and `aria-pressed`. Buttons are arranged in a 3–4-column grid depending on screen width.
- Displays 7 presets—Dark, Light, Midnight, Forest, Paper, Rose, and Ocean—and saved custom themes. Midnight, Rose, and Ocean use slowly moving gradients that smoothly blend two colors. Presets apply immediately, and the final `+` button opens an editing area with a copy of the current theme.
- Custom editing groups the background color, gradient checkbox and two colors, text color, and primary color in one wrapping area. On narrow screens, the text and primary colors move together to the next line. Pressing a color button opens the shared `ColorPicker`, up to 288px wide, as a fixed layer over the settings below. The editing area's height and the positions of the Save and Delete buttons stay unchanged. `getFixedPopupLayout` chooses placement above or below based on blur and scroll reference frames and screen boundaries; if space is insufficient, the picker scrolls internally. It stays within the same DOM scope as the trigger to preserve outside-press handling and Tab order. Reset and Close icons are grouped beside the HEX input, with 8px internal padding, a 112px color area height, 28px input and icon heights, and a 24px slider row height. For touch pointers, inputs and icons expand to 44px and slider interaction areas to 36px. Non-compact pickers, such as those in Paint, retain their existing inline display.
- Enabling gradients displays `ThemeGradientAngle` and **Background animation** directly below the color area. The clock-style graphic is 24px, the same size as the color square, with an interaction area of 32px for regular pointers and 44px for touch. Drag directions from the center and numeric input wrap through integer angles from 0 to 359°. Up 0°, right 90°, down 180°, and left 270° match the actual background. Pressing the center retains the value, and pointer capture continues drags outside the area. Keyboard support includes arrow keys ±1°, Page Up/Down ±10°, Home 0°, and End 359°. An empty numeric input does not change the current angle and is restored on blur or Enter. Check the `Aa` preview, then save and apply with **Add theme**. Identical combinations of gradient presence, both colors, direction, and animation are not added as duplicates.
- Pressing a saved custom theme card applies that theme and immediately opens the editing area below the grid. The Save (diskette) icon to the right of the title adds a new theme or replaces the item being edited. When editing a saved item, a Delete (trash) icon also appears beside it; deleting removes the item and applies the default theme. Both buttons use translated accessible names, shared tooltips, and 18px icons without text. Their interaction areas are 28px on PC and 44px on narrow screens. There is no cancel-editing X or bottom row of text buttons. Esc and Back first close the open color picker and custom editing area. After that, mobile Back goes through the settings list before closing the settings window, while Esc and desktop Back close the settings window. Closing before saving discards the draft, retains the selected theme, and returns focus to the card or `+` button that started editing.
- Solid Light and Paper themes and light custom themes without gradients use light shared backgrounds for bubbles, neutral buttons, inputs, and popups. Themes with gradients derive deeper tints for shared surfaces and display default, raised, and hover surfaces at 48%, 58%, and 72% opacity, respectively, allowing the overall background to show through. The original palette, overall workspace background, gradient, primary color, body text, borders, and terminal default background are retained, and saved item and draft formats do not change.
- The large backgrounds of work panels such as Git, tasks, features, debugger, and notes, along with tab bars and the desktop dock, show the shared gradient directly. Git diff, SVG, media, spreadsheet, and PDF previews, panel loading areas, and commit composition areas use the same background, while active tabs, buttons, and inputs retain translucent tints. Gantt grids and weekend shading also let the gradient show through. Actual document and media content backgrounds and readability inside popups and fixed areas are preserved, and switching to a solid theme restores the existing backgrounds.

- The global gradient is shown through the transparent workspace background all the way to the `[data-dock-workspace]` portal host in the actual `DockWorkspace`, preventing the default border-color background from covering the agent body. In light mode, floating windows, dialogs, menus, selection lists, and tooltips apply 75% opacity and 6px backdrop blur to their outer background surfaces, regardless of whether a gradient is present. This applies to Light, Paper, Rose, Ocean, and all light custom themes, mixing 70% theme background color with 30% existing popup surface color for a light tint. The black light-modal backdrop appears only outside the rounded panel so it does not show through beneath the translucent panel. Dark-mode gradient popups retain the existing 75% background and 6px blur, while solid-color popups retain opaque backgrounds without blur. File explorer command button add/edit dialogs, CSS- and inline-positioned popups in editors, dates, tasks, Paint, and remote screens, and Mewpet conversations and notifications use the same rules as the hamburger menu. The Mewpet tail uses the same opacity as its body. `src/components/overlay-layers.css` owns the shared background, blur, and outer backdrop rules. Text and icons remain sharp, while inner controls, fixed tree rows, and loading overlays remain solid. Outside presses, Esc, Back, and the existing layer order are preserved.
- Background, text, and primary colors are applied directly to the default body background, body text, and accent, with panel, border, secondary text, link, and button hover colors derived from them. Contrast guidance and link color calculations for gradient drafts check multiple background samples together. The terminal uses solid colors from the same background and text tokens. Light or dark mode is determined by the brightness of the default background color, and deletion and warning colors retain their mode-specific meanings. Background motion stops when the device's reduced-motion setting is enabled.
- The existing single theme color is migrated to the accent actually displayed in the previous mode. Previous Midnight, Rose, and Ocean selections carry over to the new gradient presets unless an identical solid-color custom item is saved. Storage and contrast calculations follow the [theme contract](../../development/ui-contracts.md#theme-colors-and-derived-accents); the rationale follows the [three-color theme decision](../../decisions/0002-theme-palettes.md) and [gradient extension decision](../../decisions/0010-theme-gradients.md).

- Regular and bold variants of the default IBM Plex Sans KR and IBM Plex Mono fonts are bundled with the app and provided without an external internet connection.
- Google Fonts stylesheet and font file sources for Noto Serif KR remain allowed in the production CSP.
- Sources, licenses, and fallback scope follow [Appearance settings](../../../../docs/configuration/appearance.md#appearance-settings).
