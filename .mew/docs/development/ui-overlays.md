## Popup borders

The shared `DialogFrame`, scheduled task, agent instruction, and extension management modals, and task date, Gantt schedule, tag, and assignee popups display a 1px gray border around their content. Use the existing `edge-bright` token for the color to follow light and dark themes. Popups that already have borders retain their existing boundaries.

## Popup coordinates inside modals

`getFixedPopupLayout` (`packages/ui/src/fixed-popup-layout.ts`) in `@mew/ui` converts screen coordinates to fixed-element CSS coordinates. It identifies the containing element created by `backdrop-filter`, `filter`, transforms, contain, or similar properties, accounting for borders, scrolling, and axis-specific scaling. Placement and dimensions fit the intersection of the visual viewport and the overflow/paint clipping regions of that element and its ancestors. Scroll the menu internally when space is insufficient.

`SelectField`, `ActionMenu`, file explorer favorites, account popups, mention lists, `FrontmatterPopover`, tag color selectors, compact `ColorPicker`, and `HoverTipLayer` share this calculation. Preserve portal targets, focus scopes, and Esc/back dismissal.

- Keep the compact picker fixed in its trigger's DOM to preserve form height and Tab order.
- Reposition open lists and pickers on viewport/scroll, theme, and host changes.
- Rotated remote-screen selectors retain inverse-matrix local placement; simple translation and scaling use the shared calculation.

See [Decision 0069](../decisions/0069-shared-fixed-popup-coordinates.md).

Validation includes blur, filters, transforms, borders, scrolling, nested portals, above/below placement, and hit tests on actual items in `server/fixed-popup-ui.test.ts`. `server/project-dialog-ui.test.ts` checks favorites and file operations in both file explorers on PC/mobile and in both themes, while `server/mention-textarea-ui.test.ts` checks modal blur changes and mention selection.

## Dropdowns and selection components

The top bar hamburger and ▶ command menus share `ActionMenuSurface` from `@mew/ui` and the header menu styling. The hamburger uses a width of 220px, 14px text with 20px line height, 4px outer padding and 8px corner radius, and 6px 10px item padding with 8px gaps and 4px corner radius. Minimum item height is 32px for standard pointers and 40px for touch, and menu width is constrained on narrow screens. The hamburger uses `ActionMenu` to handle focus, screen boundaries, and dismissal. The desktop project sidebar and mobile full-screen project panel follow the [project selector contract](ui-project-navigation.md#header-project-switcher).

When a top bar dropdown is open, clicking or touching another menu button once closes it and immediately opens the new menu or mobile project panel. The full-screen mobile project panel covers these buttons and must be closed before opening another header control. Buttons are identified by `data-header-menu-trigger`, and the header variant of `ActionMenu` does not restore focus to the previous button or block the subsequent click when another enabled button is pressed with the left mouse button or touch. Close the previous menu in a task after the new button's click handler finishes to preserve the overlay stack's back-navigation guard. Pressing the same button or an ordinary outside area and the default right-click menu retain their existing dismissal behavior. The desktop project sidebar does not close on menu switching or outside presses. `server/header-menu-switch-ui.test.ts` checks switching in both directions between menus, a single popup, focus in the new menu, Esc/back, and blocking of ordinary outside clicks.

Because the command menu provides both run and terminal buttons, retain its default width of 308px and cap it at 90% of the screen width. It shares 14px text with 20px line height, 4px outer padding, 6px 10px item padding with 8px gaps, and minimum heights of 32px for standard pointers and 40px for touch with the compact header menus. Run and terminal buttons are 32px wide. Both lists share the 28px handle on the left and the number at the far right from the shared `MenuReorderHandle`, along with the hover, focus, and active backgrounds of `mew-sortable-menu-row`. Projects highlight the entire current row, and commands highlight the entire running row, without separate checkmarks or running dots. Display focus outlines around the entire row as well, and preserve the accessibility semantics of `aria-checked` and the existing stop button.

Command reordering reuses the shared vertical drag hook and existing list persistence API. It supports mouse and touch handles, ↑/↓ on the handle, and Shift+↑/↓ on the row; the add item is not reordered. Reflect the order immediately in the UI, serialize save requests, and do not send status polls while saving. Earlier polling responses must not overwrite the order. If saving fails, restore the last saved order and display an error. Default arrow-key navigation and initial focus when opened by a shortcut prioritize command names and exclude reorder handles.

Ports stay on the same line as the command name, between the name and the stop/terminal controls. The port group uses at most 28% of the row width and scrolls horizontally without wrapping or widening the menu, leaving the remaining flexible space for the truncated name. Port numbers are small buttons with 12px text, 16px line height, 2px 5px padding, a 1px border, a themed background, and 4px corner radius; their height is 26px for standard pointers and 32px for touch. Truncate long project and command names, and expose full paths and commands through tooltips.

Open the project command menu with Alt+R or the existing Ctrl+E and focus the first command. If the desktop project sidebar is open, use ▶ on the current project row; otherwise, use ▶ in the top bar. If the menu is already open, only move focus to the first command. Inside the menu, unmodified 1–9 keys and the numeric keypad activate command name buttons in list order to run commands, and the first 9 items provide a number at the far right and `aria-keyshortcuts`. Selecting a running command by number reruns it just like clicking its name; it does not become a stop action. Do not skip disabled items and reassign numbers, and do not execute during key repeats or IME composition. Exclude port, stop, session, and add buttons from numbering. Preserve Alt+1–9 for project switching and the command menu's per-row arrow-key navigation, run, stop, and session buttons.

`ActionMenuSurface` consistently specifies `mew-overlay-surface` to apply the same background rules as the hamburger menu regardless of ARIA role. Use 75% background opacity and 6px blur in gradient themes and light solid-color themes, and retain the existing opaque background in dark solid-color themes. Default `ActionMenu` menus, including file right-click menus, use the [shared context-menu geometry](#shared-action-menus). `server/action-menu-ui.test.ts` checks shared surfaces, fonts, row heights, spacing, and the command menu's separate width on PC/mobile across solid-color and gradient variants of both themes. `server/command-button-menu-ui.test.ts` checks the 90% width limit, shared handles, right-side numbers, row highlighting, reorder persistence and failure recovery, port containers, keyboard controls, and new-tab actions at 1100/390/320px and when resized to 240px.

This rule was established at the user's request; do not add exceptions without an explicit change request.

## Overlay dismissal rules (`useOverlayDismiss`)

**Whenever you create a popup, modal, or dropdown, you must** `useOverlayDismiss(onClose)`**call this hook.** It collects open overlays into a single app-wide stack so that Esc and **Android hardware Back** always close *only the most recently opened one*. Pressing Back over an unregistered popup closes the terminal or file explorer behind it, or leaves the page, instead of closing that popup.

- For auxiliary panels whose state App owns (file explorer, chat, terminal, agent panel, browser, Git, Android, and Features), the shared stack in `utils/mobile-panel-stack.ts` owns the front-to-back order and dismissal order of open panels, while mobile navigation history is managed separately. On mobile, selecting an open panel behind another brings it to the front without closing it; only reselecting the frontmost panel closes it. `hooks/use-panel-dismissals.ts` also registers only this frontmost panel as an overlay, keeping Back behavior aligned with z-index. Add new auxiliary panels to `WORKSPACE_PANEL_IDS` and the open/setter registry in `App.tsx`, and use the shared open/close/toggle/layer functions (type checking prevents missing registrations). Modals, popups, and dropdowns register themselves directly in their respective components. On mobile, this device's browser also remembers the **last frontmost window** for each root project, so the last viewed open window returns to the front after a refresh or restart.
- On mobile, opening a file from the file explorer, chat, terminal, or agent panel closes that window and immediately reveals the selected file's editor pane. The side-by-side panel layout on desktop is preserved.
- Mobile navigation history in `useWorkspacePanelDismissals` remembers up to 20 previous visits (including the editor), separately from the open panel stack. A visit consists of a panel ID and optional screen identifier and restoration callback. Registering each panel's current screen `key` and a `restore` that restores lightweight screen state in `navigation.screens` also records screen transitions within the same panel. Reselecting the same screen and screen changes in panels behind the frontmost panel are not recorded. Back restores both the screen and the frontmost panel; restoration creates no new history and preserves other panels' open states and drafts. The Back function returned by the hook consumes the same history from on-screen Back buttons and returns `true` when handled. With no history, existing panel dismissal or navigation to the screen's parent level applies. Transitions to remaining panels or the editor after closing a panel with browser Back are not added as new visits. Modals and menus consume Back first. History and restoration callbacks are kept only in memory and reset on account or root project changes or when switching to desktop. Close buttons retain their existing behavior. Esc does not consume navigation history or close panels.
- Git registers the list, commit hash, diff source, and file path as screen identifiers. Pressing Back twice in `Git 목록 → diff → 에디터` returns through `diff → Git 목록` for the same file, while historical commit diffs return to the list through commit details. Diff content is not duplicated in history; it is fetched again using the restored source and file. Other panels' internal screens can be extended through the same registration contract. `use-panel-dismissals.test.ts` verifies screen restoration, hidden screen changes, identical screens, and history resets; `server/git-panel-ui.test.ts` verifies actual Git, diff, editor, popup, and on-screen Back flows.
- Back handling adds a single dummy History entry (guard). There is only one guard even with overlapping overlays, and after handling Back, it is re-added if any panel, internal screen, or popup stack remains, regardless of whether unregistration occurred. This includes cases where the frontmost panel changes while the shared registration remains active. Even on the first panel → editor transition, the visit to be recorded by the current render is reflected immediately to retain the guard. If registration is removed and `history.back()` is called before the effect saves navigation history, asynchronous Back navigation can consume the new registration and return to the previous panel. Navigation to the browser's previous page occurs only when all internal stacks are empty. When closed through the UI, the guard is removed with `history.back()` to keep the stack aligned.
- `server/overlay-history-ui.test.ts` checks in actual Chromium History that the first transition to the editor retains the selected screen without calling `history.back()`. It also verifies successive Back handling in the order popup → Git diff from before the editor → Git list → remaining panel → editor, and navigation to the page visited before entering the app only after all internal history is exhausted.
- Do not attach a separate keydown listener to each overlay — even calling `stopPropagation` in the capture phase leaves other listeners attached to the same node (window) running, causing overlapping popups to all close with one Esc press.
- `escapePhase: 'bubble'` is for overlays that **only wrap content**, such as file explorer and terminal panels. If an inner component (editor slash menu or file rename) consumes Esc first and calls `stopPropagation`, the panel does not close. The default `'capture'` is for dialogs — it intercepts the event before the editor or terminal underneath can handle it.
- All workspace panels (file explorer, chat, terminal, agent, browser, Git, Android, Features, debugger, notes, and tasks) remain open even after repeated Esc presses. The same applies to standalone browser and agent screens. Esc panel dismissal was removed to prevent accidentally closing work screens; do not reintroduce it without a user request. `useWorkspacePanelDismissals` always returns false from `closeOnEscape` and uses the optional `onEscape` only to cancel file search. The file explorer does not close even when the search is empty. Popup, modal, and dropdown dismissal, drag cancellation, exiting maximized view, and terminal input retain their existing Esc behavior. `src/hooks/use-panel-dismissals.test.ts` checks repeated Esc presses across all panels, search cancellation, and preservation of Back behavior.
- `closeOnEscape` determines whether to consume Esc. Workspace panels always return false. Popups containing a terminal pass `outsideTerminal` (`src/utils/terminalFocus.ts`) to yield Esc to vim and similar programs. This does not affect Back.
- Use `closeOnBack` when content handles mobile Back first. Returning `false` keeps the window open and reinstates the History guard to handle repeated input. No separate popstate listener or second panel registration is added, preserving the priority of modals and menus opened above it. This callback does not apply to Esc, outside clicks, or the close button.
- Providing `outside: () => 요소` also **closes the overlay when the user clicks outside that element** (only the topmost one, following the same rules as Esc). Touchscreens have no Esc key, so **a popup without a close button has no way out unless this is provided**. The decision uses the `contains()` location rather than propagation—even if `stopPropagation` runs inside, capture has already occurred. For overlays that must not close on outside clicks, such as the file explorer, simply omit it.

The editor's mention and slash menus and link/table tooltips are **intentionally not registered.** They appear and disappear frequently during typing and selection; pushing and popping History each time would hit the browser's pushState limit. Their Esc handling is performed directly by ProseMirror's `handleKeyDown` in `Editor.tsx`.

## Shared action menus

App action menus consist of `ActionMenu`, `ActionMenuItem`, and `ActionMenuSeparator` from `@mew/ui`. The file explorer/server path explorer, agent/terminal tabs, Git changed files/commit history, tasks, layout presets, and table copying use the same components. The header hamburger menu uses the `header` variant of the same `ActionMenu` through `HeaderMenuPopup`. Feature wrappers pass only translated names, icons, action functions, and permission/disabled conditions; they do not duplicate menu/row styles, positioning, keyboard handling, or dismissal logic.

`ActionMenu` defaults to `orientation="vertical"`. Passing `orientation="horizontal"` reuses the same children, action handlers, disabled/checked/danger states, hints, separators, focus, close-on-select behavior, positioning, and dismissal. `ActionMenuItem` reads orientation from the shared context; it keeps its text and hints visually hidden when an icon is provided, derives `aria-label` and `data-tip` from a string label, and retains an explicit tooltip description. Complex label nodes supply `aria-label`. Items without an icon retain visible text rather than becoming unnamed empty controls. No separate action list or feature-specific execution path is required.

The horizontal presentation has a single row, 32px icon targets for mouse input and 36px targets for coarse pointers, 16px icons, 2px gaps, and vertical group separators. It shares the existing popup surface, border, radius, and colors. The row scrolls horizontally when its contents exceed the viewport or host; focused actions are scrolled into view during arrow and Home/End navigation. `role="menu"` and `aria-orientation` describe the presentation. It does not wrap into another row. `HoverTipLayer` wraps the menu with its existing portal host so mouse tooltips remain above the menu and within visible bounds, including disabled items. See [0096](../decisions/0096-shared-horizontal-action-menus.md).

`packages/ui/src/action-menu.css` is the sole owner of menu appearance. Changes to backgrounds, borders, corners, text, icons, row padding, hover/focus, disabled/delete/checked states, hints, and separators in this file apply to all usages. Minimum width is also set by `--mew-action-menu-min-width` in the same file. mew imports `@mew/ui/action-menu.css` once in `src/index.css`.

The default context-menu variant follows the solid workspace surface color instead of the raised popup tint, including light and gradient overlay fills. It retains the shared 75% opacity and 6px backdrop blur where those apply. The container has a 6px corner radius and 3px internal padding. Rows have a 3px corner radius, 3px vertical and 6px horizontal padding, and a 26px desktop minimum height; coarse-pointer targets remain at least 32px high. Text stays at 14px and icons at 16px. The header variant retains its existing dimensions, spacing, and popup tint.

`ActionMenu` repositions based on the actual menu size, visual viewport, and mobile dock height, and scrolls internally when space is insufficient. The default portal target is body; inside a modal it uses the nearest dialog, and in fullscreen it uses the fullscreen element. `portalContainer` can explicitly specify the host. Arrow keys and Home/End skip disabled items, and Enter/Space activates items. Esc, Tab, back, and outside presses close the menu first and restore focus to the invoking element; outside presses do not click underlying elements. The default outside-dismissal event is `pointerdown`. Editor body menus opt into `outsideDismiss="click"`: pointer starts remain uncanceled, and movement greater than 8px, a scroll event during the gesture, or pointer cancellation prevents that gesture from dismissing the menu. An actual outside click closes the menu and consumes that click. By default, selecting an item immediately closes the menu and runs the action. Downloads use `closeOnSelect={false}` to retain the existing cellular confirmation and close when the download actually starts.

### File action context menu
