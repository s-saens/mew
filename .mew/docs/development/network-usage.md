`main.tsx` installs `startNetworkTracking()` before React renders. The in-memory store in `network-usage.ts` separates usage since the current tab opened into received/sent traffic and `desktop`/`other`. Tab totals persist across project switches, remote connection closures, and reconnections, and restart on refresh or in a new tab. Usage from other tabs, users, or the entire server is neither aggregated nor persisted. Payloads, credentials, and message contents are not retained, and the popup makes no additional server requests for aggregation.

## Aggregation Scope

- Completed HTTP requests to the same server use buffered ResourceTiming's `encodedBodySize` to count response bodies actually transferred. Local cache responses with `transferSize` equal to 0 are excluded, and compressed body lengths are used. This includes initial app, font, image, and other resources, as well as the initial HTML response in browsers that provide navigation statistics.
- Fetch uploads count UTF-8 string lengths, ArrayBuffer, view, and Blob sizes, URLSearchParams encoded lengths, and FormData field names, values, and file sizes. Multipart boundaries and headers are excluded. Bodies available only in an already constructed Request and outgoing ReadableStreams of unknown size are not arbitrarily read or estimated. Requests are counted once a response is returned; partial bytes from uploads that fail during transfer cannot be determined.
- Fetch `text/event-stream` responses immediately count chunks read through a TransformStream. No separate clone, background consumption, or full buffering is added, and original backpressure, cancellation, and errors are propagated. The returned Response preserves status, headers, URL, type, redirected, and clone behavior. On completion, its ResourceTiming entry is excluded to prevent double counting. Chunk lengths are body lengths after browser decompression.
- WebSockets to the same server count messages sent in the normal OPEN state and received messages by UTF-8, Blob, and ArrayBuffer lengths. External server traffic is excluded, and native static constants, events, binaryType, and error behavior are preserved. Disabling tracking restores the original fetch and WebSocket and cleans up observers.
- `/api/remote-desktop/` HTTP traffic is classified as remote desktop traffic. `/api/remote-desktop/ws` is excluded from common WebSocket aggregation, and `desktopUsageReporter` adds only new bytes along with authentication messages and WebRTC statistics from the existing connection. A remote session's own displayed values reset on every reconnection, but tab totals retain previous sessions. RTP, DataChannel, candidate-pair, and authentication WebSocket counts are not added redundantly.

Excludes HTTP, WebSocket/TLS/IP headers, ICE connectivity checks, traffic performed separately inside other windows, Workers, or iframes, and transfer volumes the browser does not expose. Differences involving local caching, compression, SSE decompression, multipart, failed uploads, and WebRTC sampling times make this an **estimate for the current tab** rather than a meter matching OS or carrier billing totals.

## Display and Updates

`NetworkUsagePanel` displays cumulative usage and network speed tables below CPU, memory, and GPU and above the process list in the system resources popup. The top bar's network button and separate network popup have been removed. Each table provides Remote Desktop, Other, and Total rows and Upload and Download columns, using Iconoir arrow icons and B, KB, MB, GB, and TB values with one decimal place. Speeds use the same format with `/s` appended. Network figures estimate the current tab's usage rather than server resources, with an explanation below the tables. Network tables remain available while server resources are loading or fail to load. Close, outside click, Esc, and Back follow the system resources popup's behavior, and closing restores focus to the button that opened it. Cumulative usage tracking continues when the popup is closed or covered by the remote viewer.

The store updates cumulative counters for each message and samples rates by direction and category approximately every 1 second while the system resources popup is open and has subscribers. Rates are B/s, calculated by dividing the byte increase since the previous sample by actual elapsed seconds from `performance.now()`; delayed timers do not assume 1 second has elapsed. When traffic stops, only the rate returns to 0 at the next sample, while totals remain. Unsubscribing the last subscriber cleans up the timer; resubscribing excludes prior traffic from rates and displays current rates starting with the first new sample. Subscribers are notified only of changed totals or rates, with notifications batched to once per second. React does not rerender for every high-frequency terminal, collaboration, or browser message. Korean, English, Simplified Chinese, and Japanese share PC and mobile layouts.

## Verification

`network-usage.test.ts` tests session totals, deduplication, immutable snapshots, notification limits, bidirectional rates based on actual elapsed time, return to 0 when idle, resubscription, and request body byte calculations. `network-usage-ui.test.ts` verifies aggregation and the popup using resources, uploads, SSE, cancellation, and clone from a real isolated HTTP/WebSocket server. `remote-desktop-ui.test.ts` tests that actual WebRTC statistics are reflected in the tab store and totals remain after closing the viewer. These tests do not guarantee matching usage on actual remote devices or production billing totals.
