[Installation and execution](../../../docs/guides/getting-started-ko.md)

Automatic commits by general agents inherit the author environment of the logged-in account that started the new supervisor or ACP session. They use linked GitHub information or the Mew profile, and reconnection does not change the account. Existing supervisors must be started in a new tab for this to apply. Authentication, environment, and verification boundaries follow [per-account Git execution](git-connections.md#git-execution-boundaries).

## Passing project context

Retry, branch, additional instructions, and automatic project guidance settings in the default instructions dialog are saved automatically 400 ms after the last change, without a separate save button. Invalid numeric or branch input is not sent to the API. Saves are serialized through the existing revision API, and drafts are preserved on failure or conflict. Other presets are saved immediately upon selection.

Per-project queues, independent tabs, the shared CLI, and completion criteria for feature requests follow [feature-based development](../features/terminals-agents-automation/feature-driven-development-and-markdown-documents.md#실행과-복원). The project and Documents connection captured at submission are passed when the supervisor starts.

[Usage and configuration contract](../../../docs/guides/project-setup.md) · [ADR 0155](../history/decisions/0155-mew-project-agent-context.md).

- The per-account source is `DATA_DIR/agent-accounts/<정규화 계정 ID SHA-256>/agent-guidance.md`; initial creation uses `agent-guidance.txt` in the same account folder, then `server/prompts/agent-guidance.txt`, in that order. Existing MD and TXT files are not overwritten, and previews read in the same priority order without creating files. `GET /api/fs/agent-guidance` returns `{ path, content, revision, settings, branch, instructions, capacityRetry }` with `serverFiles` permission. `PUT` uses `{ key, value, revision }` to atomically replace only the corresponding settings section in the MD file. Valid keys are `commit`, `commitLanguage`, `language`, `detail`, `subagents`, `debugger`, `testing`, `branch`, `instructions`, `capacityRetry`, and the documentation items below; unknown values return 400, and source revision mismatches or damaged settings sections return 409. There is no separate JSON copy of settings; values are read from the source. `instructions` is a string of up to 8,000 characters and changes only the `mew:agent-setting:instructions` section. Input containing other settings markers is rejected, and an empty value clears only that section. Existing free-form guidance is neither moved into this field nor deleted. `subagents` accepts `inherit`, `automatic`, `explicit`, and `never` and changes only the `mew:agent-setting:subagents` section. A missing section is read as `inherit`, and manually edited wording as `custom`. Automatic delegation provides guidance on dividing independent tasks, coordinating shared files, and reviewing results; it does not change runtime settings or permissions. Editing uses the existing `/api/fs/file` and external file tabs. When `expectedContent` is supplied when saving that MD file in the editor, it is compared with the source to prevent stale drafts from overwriting it, returning 409. Reading and saving in the settings dialog refreshes clean open tabs through `mew:external-file-updated` and preserves unsaved tabs. Shared file saves use atomic replacement so independent supervision does not read empty content during a save. The entry point is the Default Instructions button beside Skills and MCP in the agent panel; saving and application scope follow [Shared guidance files](../../../docs/guides/project-setup.md#edit-the-shared-guidance-file).
- Under [ADR 0202](../history/decisions/0202-mew-account-agent-settings.md), default instructions, `agent-defaults.json`, and `agent-settings.json` are stored in the same account folder. They use the server account context of authenticated HTTP and WS connections and are shared within the same account regardless of project path. During initial initialization, existing shared MD, TXT, and JSON files are copied only to the first owner created, and the originals are preserved. Other accounts start with defaults, and deleting or resetting settings after initialization does not import shared values again. The initial migration recipient is fixed in `.legacy-owner` so secrets are not migrated again when the owner changes. CLI use without an account uses the existing shared files.
- Independent supervisors inherit the starting account through `MEW_AGENT_ACCOUNT` and do not pass that internal variable to ACP children. `AgentSession` pins the starting account so reconnections or callbacks from other accounts do not change instructions or defaults. Concurrent-query caches for model and effort candidates and account status are also per-account. New one-time schedules store the creating account, use it for queries, changes, and cancellation, and restore it at execution. For new recurring schedules, the server pins the account and passes it through the runner's `--account`. Git AI Commit starts sessions with the settings of the stored `input.owner`. Older schedules without account information retain shared queries and execution; saving them again pins the saving account. Provider CLI authentication and installation in the OS home directory are not separately isolated. Existing supervisors use the new save contract only after the user applies the changes and reopens the tab.
- Selecting **Follow mew language setting** at the top of the response language list uses the language of the screen that sent the request (Korean, English, Japanese, or Simplified Chinese). The `language: mew` selection is stored in the instruction source, and the screen language passed through the request's `settings.uiLocale` is converted into the actual response language instruction at execution. Explicitly selected languages and manually edited instructions are preserved. CLI and scheduled requests without a screen language follow the language of the user's message; the existing **Not specified** option adds no language instruction.
- `commitLanguage` accepts `en` (default), `ko`, `ja`, `zh`, `mew`, and `agent` and stores the value in the `mew:agent-setting:commitLanguage` section. Commit title and body language is separate from response language, and repository prefixes and formatting are preserved. If the section is missing, queries return `en`, and default English guidance is added only when passing instructions. Existing source text, revision, manual edits, and damaged sections are preserved. `mew` is resolved using the request's UI locale, with English used when no locale is available. `agent` resolves a valid response language setting; for Not specified or manual edits, it instructs the agent to follow the response language. Saves take effect starting with the next request and do not rewrite history. Follows [Decision 0064](../decisions/0064-commit-message-language.md).
- `testing` accepts `required` (default) and `project` and replaces only the `mew:agent-setting:testing` section. Existing accounts without the section are also shown as `required` in queries, and default instructions are added when reading context while preserving the stored source and revision. A manually edited section is `custom`; damaged markers prevent duplicate insertion of default guidance. The default requires writing or improving automated tests for behavior changes and regression tests for bug fixes, and running relevant tests. It includes reporting execution constraints and reasons for not running tests, and excludes documentation-only work. `project` adds no separate Mew requirement to write tests. This is a shared guidance setting, not a gate that enforces execution. Follows [Decision 0072](../decisions/0072-test-writing-guidance.md).
- The documentation items `documentation`, `decisionRecords`, `workRecords`, `documentWriting`, `documentDescriptions`, `documentLinks`, and `documentChecks` are also accepted as keys by `PUT`. Each accepts `required` (default) and `project` and replaces only the `mew:agent-setting:<key>` section with the same name. Their scopes, in order, are reference document updates, ADRs, work and validation records, writing practices, description, links, and checks. Accounts without sections and empty source text are also shown as `required` in queries, and default guidance is added on requests. This does not change the stored source or revision, and each selection leaves other documentation items and test, language, and Git settings unchanged. `project` adds no separate Mew requirement for that documentation item, and existing project instructions remain in effect.
- Exact matches for standalone documentation update wording in the existing default template are replaced with configurable wording only when passing context. User-edited sentences in the source, content inside settings sections, and examples in code fences are preserved. If a settings section is damaged, its syntax is not automatically deleted, and the item's default guidance is not inserted again. The documentation update ordering in the previous default Change intent wording is also limited to updates required by the selected value. As before, the save API rejects damaged or overlapping sections and stale revisions with 409, and unknown values with 400. The collapsed **Documents** group in the UI uses the same API. [Documentation guidance usage](../../../docs/guides/project-setup.md#documentation-guidance) owns the detailed scope of the guidance, [Decision 0073](../decisions/0073-documentation-guidance-options.md) owns the rationale for the choices, and the [work record](../work/agent-documentation-guidance.md) owns actual verification.
- `debugger` accepts `enabled` and `disabled` and replaces only the `mew:agent-setting:debugger` section. If the section is missing, settings queries show `enabled`, and context reads add default English instructions without changing the stored source or revision. Empty source text uses the same default. Disabled and manually edited sections are preserved, and damaged markers prevent duplicate insertion of default guidance. The selection provides debugger usage guidance; it does not install or start adapters or change permissions.
- `capacityRetry` accepts `{ delaySeconds, maxRetries }`. `delaySeconds` is an integer from 1 to 3,600 (default 30), and `maxRetries` is an integer from 0 to 100 (default 20); 0 retries disables automatic retries. The existing revision check in `PUT /api/fs/agent-guidance` is used to store metadata in `<!-- mew:agent-capacity-retry:v1 {"delaySeconds":30,"maxRetries":20} -->` format in the settings section with the same name. Accounts with missing sections or invalid metadata values use defaults for queries and execution without changing the stored file or revision. If the section markers themselves are damaged, the existing 409 and manual correction paths remain in place. These values are Mew execution policy, so they are excluded from text sent to agents and are separate from whether automatic project guidance is enabled. The settings UI follows [Model Congestion Retry Guide](../../../docs/guides/project-setup.md#model-congestion-retries), and execution boundaries follow [Automatic Retry for Insufficient Model Capacity](#automatic-retry-for-insufficient-model-capacity).
- The default template instructs agents to omit skill usage announcements from introductions and progress messages and list only the skills actually used, without duplicates, on one line at the very end of the final response. Use `사용된 스킬: <이름 목록>` in Korean, `Used skills: <names>` in English, and a heading appropriate to the response language for other languages. Omit the line if no skills were used. The same instructions are added only once when reading context from existing MD and TXT files or empty source text, without changing the stored file or revision. Higher-priority runtime instructions requiring advance skill announcements take precedence.
- `AgentSession.#run` sends mew guidance as a separate ACP text block from the user prompt and attachments. `agent-context.ts` combines the project and Documents paths pinned to the session with the settings at execution time. Queued, scheduled, and one-shot runners share this path.
- Before launching a detached supervisor, the parent captures the connection information and passes it through `MEW_AGENT_CONTEXT`. That environment variable is removed from child ACP processes. Recurring schedule commands pass the connection through `--context`.
- Only paths are stored in `DATA_DIR/agent-contexts/<sha256(runtime,cwd,sessionId)>.json`. History restoration uses the stored connection, while new conversations resolve the latest Documents settings for the same project. Screen navigation does not change the connection during a session.
- The mew transcript preserves the user's original text. `<mew-context version="1">` blocks returned in user text in ACP history are removed before display. Guidance does not claim system privileges or verified document reading.
- The owner API (`/api/docs/agent-context`) and `project-setup-cli.ts` share the planning and application logic in `project-setup.ts`. The API validates the current project path and compares the preview revision again when applying changes. Creation with `wx` preserves existing documents and files created concurrently.
- `GET` on the same owner API returns `{ projectRoot, settings, revision }`. `PATCH` accepts `{ projectRoot, revision, instructions, enabled? }` and changes only additional instructions and whether automatic guidance is enabled, preserving the Documents path, entry document, and other settings. Instructions are a string of up to 8,000 characters. A current project or settings revision mismatch returns 409, and invalid input returns 400; existing files are not overwritten. The **Current Project** tab in the Default Instructions dialog uses this API and does not create a separate settings copy.
- Mew global instructions apply to all projects in the current account and explicitly state that additional project instructions take precedence over conflicting Mew global preferences in that project. Explicit user requests and existing project instructions remain in effect. Both scopes are reread on the next actual request, and neither is passed when automatic guidance is disabled. Build, execution, and restart restrictions are not included in the default template; the project owns them. Follows [Decision 0061](../decisions/0061-agent-guidance-scopes.md).
- If automatic guidance fails, report the error without falling back to another project to perform the work. Fix the settings JSON or document connection, then submit the request again.

## Git AI Commit Jobs

- If no per-account Git connection exists, log in before starting the job. Job input pins only the owning account and connection ID, and checks for disconnection or replacement at execution start and before each commit. Author and token boundaries follow the [Git Connection Contract](git-connections.md).

[ADR 0174](../history/decisions/0174-mew-commit-skill-and-automatic-commits.md) · [Guide](../../../docs/guides/projects.md#git-operations-panel).

- `git-ai-commit-routes.ts` validates Git and agent permissions and the current workspace. It accepts selected files in the current project's root repository, a job UUID, and an agent set ID. `POST /api/git/ai-commit` performs actual automatic commits; the previous `/draft` apply API is not provided.
- AI commit start requests pass the screen's `uiLocale`. The logged-in account's commit language is resolved at job start and pinned in the planning prompt. The selection takes precedence over the language of recent commits and agent set roles while preserving repository prefixes and formatting. It uses the same selection as general ACP context and passes the same language instructions to the final plan for large changes. If the `agent` selection cannot resolve the response language to a concrete value, manually edited response, additional, and free-form instructions are also passed to planning. Automatic planning that still cannot determine a language uses English because it has no examples of the user's language. The input's `languageSnapshot` pins the two language settings sections passed during execution while preserving other current instructions. Changing settings during a job does not change the language of the ongoing plan or modify the stored source.
- `mew-skills.ts` atomically creates `<DATA_DIR>/skills/commit/SKILL.md` only once. The default source is `server/prompts/commit-skill.txt`; afterward, the user file is the canonical source. At startup, the latest file and the agent set's runtime, model, and roles are pinned in the job input. The same file is also linked to `/commit` candidates for all runtimes and to project guidance. The guidance itself is not commit approval.
- `git-ai-commit.ts` captures the full Git tree for selected files using a separate temporary index. It does not touch the actual index. The AI receives the selected files' existing staged changes, final working-tree diff, and the latest 15 commit titles. Input exceeding 24,000 characters or truncated at 160,000 characters or the 4 MB output buffer switches to the full compression path below. In large-change mode, existing staged changes are provided as reference excerpts of up to 12,000 characters; the actual commit target is the working-tree snapshot. External diff and textconv are not run. Changes to binary files, deletions, and renames are also checked using the full tree and index entries.
- `git-ai-commit-runner.ts` runs an independent ACP session in a per-job `mewcmd-git-<id>` tmux session. It passes the shared skill in `mew-commit-plan` mode and validates `end_turn` and JSON `{commits:[{title,description,files}],skipped:[{file,reason}]}`. Every selected file must be assigned exactly once. Tool approval requests are denied, and no separate OS sandbox is added.
- `git-commit-response.ts` applies the same JSON parsing rules to plans, change evidence, evidence recompression, and original-content requests. Code blocks wrapping the entire response, comments, and trailing commas are allowed. For missing commas, string errors, or truncated JSON, partial parse results are not used; only the affected call is automatically asked to repair its response up to 2 times, with the original input and previous response provided. This retains new ACP sessions with the same runtime, model, and reasoning effort, along with the existing 10-minute limit, cancellation, tool denial, and session cleanup. After recovery, validation must still pass for missing or duplicate selected files and original fragments, and for their ranges. Validation errors fail immediately; when syntax recovery is exhausted, Korean guidance is shown instead of a raw parser error, and no commit is made.
- `git-commit-analysis.ts` reads the fixed Git tree's diff with 3 lines of context to the end in fragments of up to 48,000 characters. `git-commit-packets.ts` represents every fragment losslessly using dictionaries of shared before/after characters, repeated lines, and identical changes. Each fragment is immediately restored and checked against the original. Modes, EOF, Unicode, and the provided context are preserved; excerpt summaries are not used. Content exceeding the 96,000-character packet budget is split into the next packet, and evidence is not discarded because of its size. No embeddings, additional models, or indexing server are required. The character budget is a local heuristic and does not guarantee model-specific token counts.
- If all compressed evidence fits in one packet, planning uses 1 call directly. With multiple packets, two independent ACP sessions run in parallel at a time to analyze each entire packet with `mew-commit-evidence` before creating the final plan. Valid JSON requires 1 call per packet; syntax errors use the automatic recovery above. `{changes:[{sources,summary,uncertainties}]}` is checked for missing or duplicate fragments and out-of-range IDs. Length is a recommended target; valid responses are not rejected solely for exceeding it. If the final evidence exceeds the budget, only the existing evidence is compressed, without resending originals, and the same coverage is validated. Unrecoverable JSON errors or compression failures are reported as job failures. `skipped` is not created solely because a file spans multiple packets.
- Required originals are reread through `{needsDetails:[조각번호들]}`, up to 2 per call. Duplicate requests for originals already read are rejected, but the previous limit of 3 calls has been removed. Only actual safety issues and unresolved intent remain, with reasons. New ACP sessions use the same runtime, model, and reasoning effort, and logs show input count, compressed character count, and call duration. Actual commits use the full tree, and trees and indexes are compared between commits without generating diffs.
- Default agent guidance requests an intent record after changes are complete and before committing, and `project-context-text.ts` provides the `git-change-intent-cli.ts --cwd <프로젝트>` command and stdin JSON `{purpose,files,verification?}`. Files use paths relative to the Git root and include only the full uncommitted changes for this task. Files mixed with other tasks are not recorded. Do not add comments, conversation text, or secrets, and record only validation actually performed. Continue without a record if recording fails or the folder has no Git repository. This guidance does not replace commit approval or formal documentation updates.
- `git-change-intent.ts` stores project-shared metadata in `mew-change-intents/<timestamp>-<uuid>.json` in the actual Git directory (file 600, folder 700). It stores only intent, selected paths, and old/new Git blobs and modes, without copying source or diffs. It does not modify the index or HEAD. It retains the latest 100 records and references only the newest hint whose complete paths and both objects match, up to 12,000 characters, among the latest 50 candidates within 30 days. Git objects are compared in two batch queries rather than a process per path. Unrelated HEAD changes are allowed; further edits to the same file or differences in its prior state invalidate the hint. Damaged records and symbolic-link records are ignored. These hints are shared by project repository users, not private per-account conversations. Full diff analysis and validation immediately before committing are not skipped whether records are absent or match.
- Older Codex sets storing only model names are also mapped in `AgentSession.setModel` to the ID, including reasoning effort, advertised by the current ACP for the same model ([Model Compatibility Rules](../../../docs/configuration/agent-runtimes.md#model-and-permission-defaults-and-runtime-selection)). The original set is not modified. Failure status and progress logs record whether failure occurred during preparation, model configuration, plan analysis, or commit creation. Plain object errors from ACP also preserve `message`, `code`, and `data.details` rather than being displayed as `[object Object]`.
- Before execution and between each commit, HEAD, branch, and the tree and staged state of remaining selected files are revalidated. `git-commit-files.ts` puts only the relevant group from the analyzed tree into a temporary index to commit it and updates only those paths in the actual index. Staged changes and working content outside the selection are preserved, and the Git index lock is used. Hunks within files are not split. Git hooks and signing settings apply as configured.
- Status is available at `<DATA_DIR>/git-ai-commits/<sha256(account,cwd)>/<id>/state.json`, and the latest per-account job at `latest.json`. Uses `starting`, `running`, `committing`, `completed`, `failed`, and `cancelled`; older drafts without `mode: commit` are not executed. Resending a request UUID from the same account does not execute it again. Per-repository `mew-ai-commit.lock` also excludes AI execution by other accounts or processes.
- The analysis time limit is 10 minutes. Cancellation or failure does not forcibly revert an ongoing commit. Each created commit hash is saved to preserve partial success. Cleanup removes child processes, per-job `analysis/` containing input snapshots and original diff fragments, and repository locks for jobs that exited normally. Fragment files are temporary inputs internal to the job and are not retained as permanent documents. tmux jobs persist regardless of server or browser reconnections. Git/AI locks left by forced host shutdown must be removed only after confirming that no other Git or AI processes are running.
- The UI displays actual commit results and reloads the change list and log. It does not overwrite the user's manual title or description or automatically push after completion.
- `git-ai-commit.test.ts` uses temporary repositories, mock ACP, and isolated tmux sessions to check split commits, preservation of staged changes outside the selection, change detection, permissions, cancellation, failure, and reconnection. `git-ai-commit-ui.test.ts` checks desktop and mobile set selection, creation, logs, actual result display, manual draft preservation, cancellation, and restoration. Temporary repositories and mock ACP also check large staged diffs exceeding 4 MB, full original restoration, lossless restoration, packet budgets, dictionary references, complete evidence coverage, a single call for a single packet, batch original requests, new sessions, original rechecks, full-content commits, invalid plans, cancellation, tool approvals, and edits during analysis. Actual summary and grouping quality from paid agents is not automatically validated.

## Tab Ledger and Restoration

When switching only worktrees within the same logical project, `AgentPanel.workspacePath` remains `projectPath` and serves as the identifier for the account tab ledger, active tab, and session connections. `workingPath` is `path`, the selected actual working root, and is used to query the default cwd for new sessions. Existing `tab.cwd` and the cwd of running sessions are unchanged, and panels are not remounted. Selecting a regular project also changes the logical project identifier. Follows the [Worktree Switching Contract](ui-contracts.md#switching-worktrees-within-the-same-project).

- The tab list, names, runtimes, and last session ID per cwd are **saved to the account** and separated by absolute root project path. The browser's `mew:agent-tabs:<root-path>` is only a local fallback and is not used to connect before the server responds. Save PUT requests are serialized one at a time per screen; if multiple updates occur during transmission, only the latest snapshot is sent next, preventing stale responses from rolling back the latest thread pointer. The active tab's WS connects only after server restoration finishes, so it does not first connect using a stale localStorage session. Session IDs are deleted when a tab closes; switching runtime or cwd within the same tab preserves a separate conversation pointer for each combination. The last viewed tab is also saved per root path (`mew:agent-active-tab:<root-path>`) — reopening the window or restarting the browser displays that tab. Each open panel connects one active tab. Restored inactive tabs connect when first selected, and hidden panels do not initiate new connections. Switching tabs or hiding panels preserves existing connections. Agents and regular shells use separate panels, but one controller saves their account ledger together. Swipe the dock to switch to the previous or next tab in the current panel. Panels can be opened and closed from the dock or top menu; tabs can also be switched using the tab bar or keyboard shortcuts, and closed with the tab's close button or `Ctrl+W`. Tab names initially use the selected runtime or agent set name and can be edited by double-clicking the tab ([ADR 0093](../history/decisions/0093-mew-account-synced-project-and-agent-tabs.md) · [ADR 0096](../history/decisions/0096-mew-agent-tabs-created-after-selection.md)).
  - New tabs are created only after a selection, so there is no empty tab for browsing history or entering session input before selecting. A new session starts in that tab immediately after selection, and choosing past sessions remains available from the tab
  - The same session cannot be opened in two tabs (it is locked in the list) — this is determined from a single tab-state response that includes both currently mounted tabs and hidden tabs saved under other root projects in the same account. Two processes holding the same transcript would corrupt the history
  - **As the conversation grows, it scrolls down only when already at the bottom** (bottom detection tolerance: 48px). When scrolling up to read, it holds position and shows only \*\*\[New messages\]\*\* — clicking it scrolls to the bottom, and it also disappears when you scroll to the bottom yourself. Sending a prompt or loading a session again (`reset`) anchors it to the bottom again
  - **Only closing a tab ends its session** (`close_session`). This differs from closing the window. Tabs that are not being viewed keep their WS connections (ongoing conversations must not stop), and only tabs opened at least once are connected (restored tabs are not all launched at once)
  - `PUT /user-ui/agent-tabs` compares tab IDs before and after saving and sends `close_session` to independent supervisors for deleted tabs as well. Termination requests are delivered even if the browser WS is disconnected or a restored inactive tab has no sender. It cleans up the current runtime/cwd connection and previous runtime/cwd connections in stored sessionIds without duplicates and does not launch missing supervisors. Remaining tabs and other accounts' ledgers are untouched. Failed save validation does not trigger termination, and termination connection failures are recorded in server logs. Supervisor termination proceeds asynchronously.
  - If Codex rejects history restoration with `already has an active writer` when no tabs are open, check both the tab ledger and the current sessionId of live supervisors. Send `close_session` to a supervisor to release ownership only after confirming that it is absent from the ledger and has no current turn or queued items. Do not terminate supervisors or delete Codex lock files solely because the browser disconnects.
  - **Elapsed time appears to the right of each turn bubble** — formatted as "15 seconds", "36 minutes 32 seconds", or "2 hours 5 minutes 4 seconds". The server records `startedAt` in `turn_start` and `durationMs` in `turn_end`, so they remain visible in replayed history. Running turns recalculate elapsed time from startedAt to the present every 1 second; older history without timing information hides it. Even after a supervisor exits due to inactivity, it rewrites the full event transcript retained at completion, preserving questions, answers, work details, and elapsed time.
  - Even if ACP does not send the final `turn_end` when replaying history, the last turn is rendered as \*\*Complete (green)\*\* if no saved interrupted state exists and the current session's `meta.busy` is false. Before meta is received or while work is still underway, it remains \*\*In progress (blue)\*\*.

## Messages, Reconnection, and Queues

- **Conversations continued in an external CLI:** Restore using the latest ACP transcript returned by `session/load`. Do not discard the entire ACP response merely because a Mew transcript is stored. Preserve existing Mew events (elapsed time, settings, and work records) only for completed prefix turns with matching questions and answers, and use the latest ACP events from the first difference onward. Independently of answer matching, restore only missing model, effort, and permission values in user messages for prefix turns whose question content and order match. This prevents status bubbles for the same settings from reappearing because intermediate answers were omitted or restoration was repeated without `turn_end`. Do not infer and attach past settings after the first changed question or to questions added externally. Fall back to the stored transcript only when ACP replays no conversation events at all. Save the transcript once after full restoration.
- **Interrupted state restoration:** For prefix turns whose question content and order match, preserve `turn_end.stopReason=cancelled` stored in Mew even if ACP replays answers differently or omits them. Append the saved interrupted ending only when the latest ACP turn has no end event; bubble assembly also creates interrupted turns when only an end event is returned, without answer or start events. Preserve the gray interruption dot after refreshes, supervisor restarts, and repeated restoration. Do not attach past interrupted states after the first changed question or to questions added externally. `agentTranscript.test.ts` validates changed or omitted answers, repeated restoration after saving, bubble assembly, and prevention of state leaking into different questions.
- Reconnecting to a live supervisor synchronizes segments of its current transcript, so external CLI changes are not monitored in real time. Codex **History → Refresh Current Conversation** rereads the same session ID through the existing `load_session` path. It cannot overlap an ongoing turn, approval, or queue, and adapter replacement follows ADR 0122. Refresh is not allowed if another tab owns the same session.
- Adapter replacement waits for actual termination through `disposeAndWait()` after requesting shutdown. This applies not only to history switching but also to creating a new session after automatic restoration fails and recovering the previous conversation after loading selected history fails. Because `session/load` can acquire the writer and then fail during transcript replay, failed adapters must also pass through the termination boundary. Supervisor logs record the initial loading error for the selected history and the error restoring the previous conversation separately.
- For automatic restoration, Codex history switching, and current conversation refresh, if `initialize` advertises `loadSession` support, skip the empty `session/new` and its default settings and load the existing session directly. Apply defaults to the restored session. Runtimes without load support use the existing new-session and authentication paths. If automatic restoration fails, preserve the original pointer and fall back to a new connection; if both loading the selected Codex history and recovering the previous conversation fail, create a new session only after terminating the failed writer. A simple reconnection to a live supervisor uses segmented synchronization of the current transcript without ACP initialization or load (replay for older clients).
- `history.restoreFailure` in an automatic restoration failure response preserves the original conversation pointer and transcript. Even then, immediately apply the model, effort, and permission lists from `history.page.controls` so users can choose before sending a new message. Receiving execution settings lists does not cause the fallback session's transcript or pointer to be adopted or a prompt to be sent. `agent-model-controls-ui.test.ts` verifies list display for direct settings events, segmented history, existing replay, and automatic restoration failure responses, along with preservation of the failed original pointer, on desktop and mobile.
- The display transcript for a saved restoration target is queried in a separate read Worker and displayed early through `history_preview` in parallel with ACP initialization and full restoration. ### History Search

`list_sessions` accepts optional `query` and `requestId`. `query` is a string of up to 256 characters, trimmed before searching; omission or an empty string returns the recent list. The `sessions` response returns the cleaned `query`, the request's `requestId`, and the searched `sessions`. Entries add optional `snippet` and `score` to existing session information. If some source queries fail, the results obtained are returned together with `error`, so search failures are not hidden as empty lists. Search results merge identical session IDs within the current connection's runtime and cwd scope and return up to 50 entries.

Exact and partial session ID matches come first, followed by sorting by title/body search score and recency. Bodies and search terms are compared after Unicode normalization and normalization of differences in case, spacing, and symbols. Key Mew terms are expanded with Korean-English synonyms, so `에이전트패널` finds conversations related to `에이전트 패널` and `agent panel`. No embedding models, vector DBs, or external APIs are used; semantic search that arbitrarily infers unregistered synonyms or context is outside the scope.

Mew transcripts are stored in an FTS5 trigram index inside the existing `<DATA_DIR>/agent-transcripts/transcripts.sqlite`. Only user questions and agent answers are extracted; thinking, tool calls/results, and system notices are excluded. Changes are reflected when transcripts are saved; existing transcripts are supplemented only for sessions that need it by comparing revisions and event counts during searches. The search index does not replace the original transcript; the storage contract for originals and segmented restoration is owned by [Conversation Storage](conversation-storage.md).

For Codex and Claude, disk JSONL files pointed to by the requesting account's current runtime settings are read line by line and merged into the local index. Searches also cover conversations created in external CLIs and conversations beyond the 50 entries in the recent list. The index is reused if the file's modification time and size are unchanged; changed files are reread in full. Individual lines exceeding 8Mi characters are skipped. Mew and runtime execution instructions attached to original user messages are removed before searching. The external CLI index is a rebuildable cache stored in `<DATA_DIR>/agent-runtime-search/<해시>.sqlite` by runtime, runtime home, and cwd. Other runtimes combine transcripts saved in Mew with session lists returned by the runtime. Provider CLI OS accounts, authentication, and history storage locations retain their existing sharing scope; search adds no new account isolation.

During searches, supplementing existing transcripts, reading CLI source files, and querying bodies run in a single reused Worker, separate from the server's main event loop. The requesting account's context is passed to the Worker so it uses that account's runtime settings. Body search and runtime list queries are collected independently, and successful results are returned even if individual sources fail.

The UI searches 250ms after the last input; Enter searches immediately. Responses whose `requestId` differs from the latest request are discarded so older search results cannot overwrite newer ones. Searching itself does not change the conversation pointer or send `load_session`. The existing load path runs only when the user selects a result after reviewing its title, body excerpt, and date. Existing switching restrictions for the current session, occupancy by other tabs, unconfirmed occupancy, busy state, approvals, and queues remain in effect.

The rationale follows [Decision 0084](../decisions/0084-agent-history-search.md), feature-specific UI behavior follows the [Conversation Feature Documentation](../features/terminals-agents-automation/agent-conversations-queue-and-restoration.md#history-search), and verification and production application status follow the [Work Record](../work/agent-history-search.md).

### Automatic Retry for Insufficient Model Capacity

ACP chat's `AgentSession` waits and retries within the same logical turn when it detects a provider-explicit temporary model capacity shortage or overload. An example is `Selected model is at capacity. Please try a different model.`. It detects not only RPC failures but also the path where Codex ACP sends a capacity error at the end of an answer and returns a normal `end_turn`. Generic 429 or rate limiting alone does not qualify; actual usage exhaustion, subscription, billing, and authentication errors retain existing error and queue-hold handling.

At the start of a logical turn, read the `readAgentCapacityRetrySettings` value once from the account that started the session. Retries for that turn retain the same ACP session, model, effort, permissions, and retry settings; settings changes during the wait apply starting with the next turn. By default, make up to 20 additional attempts, each after 30 seconds; the initial request does not count toward this limit. Do not switch models automatically or rerun CLI commands.

If the model, effort, or permissions are changed after capacity retries begin, validate that they are candidates advertised by the runtime and update only the selection for the next message. Keep the current turn's adapter settings fixed and restore the latest selection when the turn ends.

While waiting, retain busy status and the ongoing turn, and do not advance the queue. `meta.capacityRetry` is `{ attempt, maxRetries, retryAt }` or `null`; `attempt` is the next retry's sequence number (starting at 1), and `retryAt` is its scheduled time. The UI uses this state to display the remaining time, attempt count, and stop action. Clear the waiting state when the actual retry request is sent. Preserve answers and tool execution records already received; if work has already been done, request continuation rather than restarting completed original instructions. A user stop immediately cancels the wait and follows the existing FIFO rules after cancellation. Tab closure and dispose cancel the wait and subsequent retry requests.

On success, finish that turn and then execute the next queue item. A capacity error after attempts are exhausted, or when retries are disabled with 0 attempts, is displayed as a final error and waiting messages are held. Resumption requires the user to explicitly send a new message; automatic submission, reconnection, and queue editing do not release the hold. The official TUI, regular terminals, and rerunning CLI commands are outside the scope. The rationale for the server execution policy is owned by [Decision 0074](../decisions/0074-agent-capacity-retry.md); verification and application status are owned by the [Work Record](../work/agent-capacity-retry.md).

## CLI Command Records in Conversations

Under [ADR 0153](../history/decisions/0153-mew-agent-cli-shared-queue.md), CLI mode accepts requests over HTTP and places them in the independent agent supervisor's shared FIFO queue. AI prompts, CLI, and normal-mode `/clear` run sequentially in the same tab; CLI source text and output are not passed to ACP. The input string, including spaces and newlines, is preserved and passed to `$SHELL -lc` (or `/bin/sh -lc` if unset) in the tab's cwd. In CLI mode, `/clear` is also shell input and is not interpreted as an AI session operation. The server generates the runner path and a random `mewcmd-cli-*` name, and creates tmux through `TmuxManager.startCommand` only when execution reaches its turn.

- `server/agent-command-queue.ts` + `agentHost.ts` — Accepted through supervisor IPC `queue_command`, with `AgentSession.enqueueTask` owning the execution and cancellation lifecycle. Agent and terminal permissions are rechecked immediately before execution, and the next task starts after output saving completes. After `/clear`, record the sessionId and user turn count at execution time. Closing the browser/HTTP connection does not cancel the queue, but closing the tab cancels the running CLI and waiting tasks. A user stop cancels only the running CLI; the next waiting task runs after termination and output saving finish. Queued records left after abnormal supervisor termination are marked as interrupted on the next query and are not rerun automatically. Older supervisors that were alive before deployment are replaced by closing and reopening the tab.
- `server/agent-commands.ts` — Per-account storage, input validation, duplicate request prevention, tmux execution and stop requests, and recovery of vanished sessions. Identical requests with the same ID do not execute the command twice.
- `server/agent-command-runner.ts` — An independent runner inside tmux. It provides a real TTY through `node-pty` and relays input and resize events. Execution, output saving, and completion cleanup continue even if the server or browser closes. The shell wrapper keeps the PTY open until the runner receives a random marker at the end of the output, preventing output loss on fast exits. User commands are passed as arguments rather than inserted into the wrapper string.
- Output chunks are saved immediately as standard concatenated gzip members. Only the most recent 512 Ki characters remain in memory. On completion, save the full `output.gz`, `preview.txt` with control sequences removed, and the exit code and status, then terminate tmux. For interruption, the runner detects the `stop` file and sends TERM to the process group, followed by KILL if needed, preserving output already received. Records that could not finish saving normally because of OS shutdown or external forced session deletion are marked as interrupted on the next query.
- Location: `<DATA_DIR>/agent-commands/<계정 SHA-256>/<명령 UUID>/`. Directory permissions are 0700; file permissions are 0600. `record.json` is replaced atomically. Source text and output are not replicated to the browser transcript cache. Records are not automatically deleted.
- `GET/POST /api/agent/commands`, `POST /:id/stop`, `POST /stop-tab/:tab`, `GET /:id/output`, and `GET /:id/archive` all enforce agent and terminal feature permissions and account ownership. Lists are restricted by runtime, cwd, and sessionId, and output is queried only when the popup opens. The server control permission boundary for regular tmux WS remains unchanged.
- The client checks status every 1.5 seconds and uses `afterUserCount` to place the CLI bubble after the corresponding user turn. Even if ACP restores streaming chunks differently, it places the bubble at the same position based on message order. Queued records appear in the shared queue rather than the body and support cancellation and reordering. Cancellation before execution is marked as `cancelledBeforeStart` so no command bubble or interrupted status is created in the body. The record ID is retained to prevent duplicate requests from rerunning; polling and reconnection also convey the cancellation marker to update existing caches. Older pre-execution cancellation records (queuedAt present, identical start/end times, no output/errors) are normalized to the same marker when queried. Interruptions and failures after actual execution, and abnormal supervisor termination records, remain visible. The command bubble is displayed after the user turn recorded at execution. `meta.queuedKinds` distinguishes items; when `meta.activeTask` is cli, the AI answer progress indicator is not activated. CLI is excluded from the model-change status line and AI transcript.

## Memory Protection

`agent-memory.ts` calculates a dynamic pool from Linux total and available memory and non-reclaimable agent usage, then updates the OS limit for user `mew-agents.slice` to 90% of that pool. The separate MemoryHigh throttling is removed, and the limit is not lowered below current usage. This budget is read to run ACP and CLI children in separate scopes. The supervisor and server remain outside the scopes. `AgentSession` checks before startup and FIFO dequeueing and every 2 seconds, cancels only the work in progress, and sends `meta.memoryPaused=true` and an error. A held queue is neither automatically dequeued nor shut down for idleness. Once cancellation completes and sufficient recovery headroom is confirmed, first run a continuation message for the interrupted AI task with its original settings, then resume the FIFO queue. CLI commands are not rerun. A user stop removes the continuation; queue editing, authentication, and usage protections remain in effect. The supervisor's `prompt.automatic=true` (scheduled and feature execution) does not release the hold. Forced OS termination saves the termination error and transcript and closes the session.

Default budgets, recovery criteria, installation, logs, and scope follow [Memory Protection Operations](../../../docs/operations/agent-memory.md); decisions follow [ADR 0164](../history/decisions/0164-mew-agent-memory-protection.md). `agent-memory.test.ts` verifies AI/CLI cancellation and queue holds under synthetic pressure, and verifies the OS boundary with an optional 64MiB scope OOM check.

## Agent Debugger MCP

When debugger sharing is enabled for the current account and project, the regular agent WS passes the `mew-debugger` list created by `debuggerMcpServers` to `AgentSession.start`. The default is an empty list. It checks owner·manager, `agent`·`terminal`, and permission to modify all project files; enabling the option alone does not launch an adapter or change provider MCP settings. Mewpet continues to use its existing helper MCP list.

`server/debugger-mcp.ts` relays through a private Unix socket for each account and project, while `debugger-mcp-stdio.ts` relays stdio JSON-RPC started by ACP. Tools are limited to status queries, permitted commands, starting saved profiles, and terminating the exact session. Permissions, workspace, and sharing options are checked on every call, on policy changes, and every 5 seconds; the socket is closed upon revocation. Commands require the current session, connection, and stop revision. DAP references, execution boundaries, usage, and response limits follow [External DAP Debugger](../features/terminals-agents-automation/external-dap-debugger.md#agent-debugger-connection).

The MCP list is fixed when the independent supervisor starts. After enabling sharing, a new regular agent tab must be started for the list to be passed through; reconnecting an existing tab or using `session/load` on a running supervisor does not add to the list. Scheduled and one-shot runners do not receive this WS connection. `debugger-mcp.test.ts` verifies disabling, handshakes, socket permissions, stale references, and permission revocation; existing `agentWs.test.ts`·`agentHost.test.ts`·`agentAcp.test.ts` verify WS, supervisor, and ACP regression behavior.

## Mewpet Helper Sessions and MCP

Mewpet uses a separate supervisor for each account, browser tab, and runtime. The `mcpServers` option from `AgentSession.start` is passed to the independent supervisor and reused for every session/new and session/load. Regular sessions use an empty list when the optional debugger MCP described above is disabled. Permissions, current screen context, task ID round trips, and persistence boundaries for each session's built-in MCP follow the [Helper Contract](../features/appearance-accounts-operations/mewpet-assistant-conversations-and-controls.md).
