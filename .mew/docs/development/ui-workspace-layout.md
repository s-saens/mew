## Device safe areas

The direct viewport combines `viewport-fit=cover` with `interactive-widget=resizes-content`. Within `--app-height`, the `.mew-workspace` border box reserves all four `env(safe-area-inset-*, 0px)` values once, protecting the header, panel tabs, and Dock from status bars, cutouts, and the home indicator. Follow orientation and viewport changes, including landscape above the desktop breakpoint. Zero insets preserve desktop geometry.

For a positioned Dock (`data-position`), reserve insets only in the workspace. Mobile horizontal docks stay 48px high and vertical docks 48px wide. Protect the panel footer when the Dock is top/side, hidden, or unavailable. The older unpositioned Dock fallback retains its fixed-edge spacing.

Body portals do not inherit workspace padding. `DialogFrame` and `SettingsModal` use `.mew-dialog-overlay` with the greater of each dialog gutter and device inset. Keep the backdrop viewport-sized and the dialog/internal scrolling inside the safe area. Settings and mobile project selection fill that area. Preserve focus, dismissal, layers, and desktop size limits.

`server/workspace-safe-area-ui.test.ts` checks the viewport setting, exact header offsets and compact heights, all four Dock positions without duplicate insets, full-height and ordinary dialogs, the actual settings panel, click dismissal, and overflow across portrait, landscape, narrow landscape, a keyboard-sized viewport and desktop. The isolated Chromium fixture substitutes safe-area CSS environment values; it does not verify Safari's device-provided values or an installed iPhone session. See the [implementation record](../work/workspace-safe-area.md).

## Active tab auto-scrolling

All horizontal tab bars use `TabScrollArea` from `@mew/ui`, and `useTabAutoScroll` inside the component handles bringing active/focused tabs into view. Apply the same rules to editor, agent, terminal, existing project, sheet, DB view, task view, account management, and active session window tabs. When the active tab changes through opening a new tab, Ctrl+number, or similar actions, or DOM focus moves into a tab, smoothly scroll only the minimum horizontal distance needed to bring that tab into view. Do not scroll tabs that are already visible.

Regular tabs indicate selection with `role="tab"` and `aria-selected`. For items that indicate an active state without an actual tab, such as `+` in the agent selector, mark the auto-scroll target with `data-tab-scroll-active`. Scrolling changes only the tab bar's horizontal position, without changing its vertical position, outer scrolling, or input focus. With `prefers-reduced-motion: reduce`, move immediately without animation.

Recheck active tab visibility after tab restoration, addition, renaming, and panel size/layout changes. Suppress this auto-scrolling during dragging to avoid conflicts with existing edge auto-scrolling.

For each direction with remaining scroll distance, overlay a chevron button on the last visible tab at that end of the tab bar. Show only the chevron and two shadow layers colored with the selected theme background (`--color-surface-deep`), keeping their 90% and 75% opacities, offsets, and blur radii, without a background or border, and do not reduce the tabs' visible width. Move at a constant speed of 320px per second while the arrow is held, and stop immediately on release, input cancellation, or loss of window focus. Holding Enter or Space also moves the bar. Retain movement from direct manipulation even with reduced motion enabled. Map standard vertical wheel, Shift+wheel, and horizontal trackpad input to horizontal movement; do not convert Ctrl+wheel zoom into horizontal movement. At the ends, do not prevent the wheel's default behavior. Hide the corresponding button when the left/right end is reached, and hide both when there is no horizontal overflow. Recheck the remaining distance in each direction after scrolling, resizing, and tab addition, deletion, or renaming.

Visible chevron icons repeat a subtle 1.2-second horizontal wall-bounce loop, moving between -2px and +2px around their resting position. Each icon accelerates toward its outer edge, reverses immediately at the wall, and slows toward the inner turning point; left and right paths mirror each other. Animate only the SVG transform so button geometry and tab layout stay fixed. Hidden buttons do not run the loop. With `prefers-reduced-motion: reduce`, keep icons centered and static while preserving held scrolling. See the [implementation and verification record](../work/tab-scroll-arrow-motion.md).

Arrows provide translated accessible names and shared tooltips. Activating them does not change the active tab, and pressing them with a pointer does not affect input focus or tab dragging/renaming. Preserve the position set by the user with the arrows until the next tab activation, focus movement, or layout change.

## Drag reordering motion

The agent `+` runtime list uses the vertical axis (`axis: 'y'`) and dedicated handles (`handleOnly: true`) from `useDragReorder`. Register rows as geometry and preview targets, and attach pointer events to the handles. Handles support immediate touch dragging with `touch-action: none`, while the rest of each row retains normal selection and scrolling. Apply the vertical axis to target detection and edge auto-scrolling as well, and preserve the existing default behavior of horizontal tabs.

File and document moves in the file explorer use the same duration and curve. Record positions immediately after a successful move and retain them until the actual tree update, mapping the moved path and descendant paths to new rows so they remain linked even if React recreates the rows. Surrounding rows move together, and scroll changes are excluded from movement distances. Expanding, searching, failing, or canceling alone does not start movement animations. `sidebar-move-ui.test.ts` validates asynchronous updates, intermediate positions, and reduced-motion transitions; `sidebar-touch-ui.test.ts` validates existing touch input and cancellation.

File, project, agent, and terminal tabs, task items, and docks animate reordered layouts for 180ms with `cubic-bezier(0.22, 1, 0.36, 1)`. `useReorderAnimation` records visible positions before reordering and animates only transforms after React updates. Consecutive moves continue from the current animated position. Tab/dock hit testing uses actual layout coordinates without animation to prevent jitter and reversal. A grabbed-item copy follows the pointer immediately.

Surrounding queue rows and the dashed insertion placeholder move with the same duration and curve. Order persistence, drop, cancellation, and edit-lock contracts follow each feature's existing behavior. Apply keyboard reordering immediately, and omit position animations with `prefers-reduced-motion: reduce`. If the setting changes during dragging, also remove movement animations already in progress.

Validation: `tab-reorder-ui.test.ts`·`mobile-dock-ui.test.ts`·`project-tab-groups-ui.test.ts`·`agent-command-ui.test.ts` check intermediate movement positions on PC/mobile, target stability during consecutive moves, drop, cancellation, scrolling, groups, and reduced-motion settings. All four UI checks passed on 2026-09-30. Frontend type checks passed; full type checks were blocked by an unrelated session API mismatch in `mewcat-assistant.test.ts`, and documentation link checks were blocked by existing missing links.

## Git diff editor tabs

In the Git changes list, distinguish ordinary selection through highlighting from commit-target selection through checkboxes. Display diffs in read-only editor tabs with `mew:diff:` virtual paths, excluding them from file APIs, autosave, comments, collaboration, and presence. Tab identifiers include the project, repository, file, and worktree or commit hash, and are saved with the existing per-account/per-root editor restoration state. Automatically retrieve active worktree diffs only while the editor is visible; stop for inactive tabs, hidden editors, and hidden browser pages. The [Git work panel](../features/git-history/project-git-work-panel.md) owns detailed operations and selection scope.

## Workspace Panel Layout

Panel tab bars use the shared `h-9` height (`calc(var(--spacing) * 9)`, 36px at the default font size). `DockBody` in Git, agent, terminal, and browser panels uses the same spacing basis to calculate the body start position and remaining height. Changing the browser's default font size or maximizing a panel does not cause the body to overlap the tab bar's bottom or leave a gap between them. Mobile uses the same basis. `dock-maximize-ui.test.ts` validates tab bar/body boundaries and bottom hit tests at font sizes of 14, 16, and 20px, plus maximized and mobile layouts.

When no saved docking tree exists, the desktop default places the editor above the terminal (69:31), with Git above the agent on the right (40:60). Workspace column widths are 2:1; when tasks open as a tab, they occupy the rightmost column, splitting the existing workspace at 74:26. Closed panels occupy no space. Terminal, Git, and task panels mounted after the first save are also placed beside their designated neighbors, preserving existing branch ratios. The browser is added as a separate full-height right column. Existing device/account layouts and splits within editor panes are preserved, and panels are not opened automatically. `defaultDockTree` and `addDockGroup` own the default layout; `DockWorkspace` owns restoration precedence and visible-area calculations.

The desktop workspace places the open project sidebar, file explorer, and docked workspace panels in that order. The project sidebar and file explorer are independent fixed panes that return their space when closed. A 20×36px collapse/expand button is centered on the 4px resize boundary to the right of the file explorer, and the left-edge button remains when collapsed. It provides a keyboard-accessible name, tooltip, and `aria-expanded`; mobile retains existing dock/close controls.

Note and task title bars provide a PC-only popup/panel toggle icon. `ToolPresentationToggle` displays the `팝업으로 전환` or `패널로 전환` accessible name and tooltip according to the current presentation and immediately updates the existing browser-stored value in `use-tool-presentation.ts`. The note/task presentation selector was removed from appearance settings. Mobile hides the button and retains panels while preserving the PC selection. PC popups retain the same `DockPanel` while being excluded from the docking tree's visible area. All panels that switch to popups use the shared behavior in `DockPanel` and `overlay-layers.css`. They hide the separate top movement bar and docking grip and move by dragging non-button areas of the title bar. Popups resize by dragging any of the four edges or four corners. Resizing the top or left keeps the opposite edge fixed and respects a minimum of 240×160px (or the workspace size if smaller) and workspace boundaries. Arrow keys on the title tab move the popup, and arrow keys on the bottom-right resize button resize it, in 12px increments; dragging uses pointer capture. Movement and resizing span all of `.mew-workspace-content`, including the file explorer and dock. When focus leaves, overall opacity drops to 50% and backdrop blur is disabled, including on inner elements; clicking or keyboard focus restores it. This effect does not apply in panel mode or on mobile. Panels newly offering popup switching follow this path without separate implementations, based on the [Shared Implementation Decision](../decisions/0062-shared-panel-popups.md). Window resizing clamps coordinates to workspace bounds, and switching to mobile does not overwrite saved PC coordinates. `use-floating-panel.ts` saves position and size keyed by account, root, and panel.

`device-layout.ts` stores only `dock`, `tabs`, and `chrome` locally per account and root; other settings follow the existing account ledger. Initial device restoration uses the account fallback, after which local state takes precedence. Save failures retain in-memory state. `device-layout.test.ts` and `floating-panel-ui.test.ts` validate device/account separation, movement, 8-direction resizing, fixed opposite edges, minimum size, workspace bounds, refresh, mobile, and presentation switching.

The `tasks` panel, separate from notes, uses the same docking, maximization, dock, and mobile stack and restores saved groups, tab assignments, and open state. For saved layouts without tasks, opening the panel adds it beside its default neighbor. Input, object storage, and permission contracts reside in [Task Panel](task-list.md).

- Between the desktop file explorer and workspace panels, a 1px separator in the `edge` color matches shared panel boundaries. Horizontal and vertical docking boundaries are also standardized at 1px; hover and keyboard focus highlight only the line in the accent color. The resize handle's 4px interaction area retains the same `surface-deep` background as the body, and the file explorer handle is hidden on mobile.


Remote desktop is an independent screen overlay defined in [ADR 0136](../history/decisions/0136-mew-native-remote-desktop-webrtc.md). On mobile, the dock remains visible and is hidden only in browser fullscreen. It is excluded from docking and panel restoration. It uses the shared Back stack; Esc dismisses only auxiliary windows and fullscreen while retaining the remote screen. Closing or moving to the background ends video and input. Joystick and view interaction contracts reside in [Remote Desktop](remote-desktop.md).

Under [ADR 0134](../history/decisions/0134-mew-dockable-workspace-panels.md), the editor, agent, regular terminal, Git, notes, and tasks use the shared split area in `DockWorkspace`. Adding Git follows [ADR 0135](../history/decisions/0135-mew-git-workspace-panel.md). The project sidebar, file explorer, member chat, and Android retain their existing auxiliary windows.

### Mobile Keyboard and Screen Zoom

`useMobileKeyboard` remembers the pre-keyboard height during an editing session and uses the visual viewport's `height × scale` to detect actual occlusion. Focus zoom and pinch zoom alone are not treated as a keyboard, and keyboard detection continues while zoomed. When the keyboard opens, both the mobile dock and reserved bottom space are removed. It responds to resize, visual viewport scroll, fullscreenchange, and focus changes, restoring the dock and existing spacing when the keyboard closes.

`server/mobile-dock-ui.test.ts` checks that the dock remains visible when only zoomed, keyboard shrinkage/restoration while zoomed, and fullscreenchange/scroll events. It substitutes viewport values in isolated Chromium instead of using OS fullscreen or an actual IME; keyboard animation on physical devices requires separate verification. `server/agent-command-ui.test.ts` checks internal scrolling in long mobile agent input, positioning above the keyboard, and restoration after it closes.

## Git Repository Tabs

`git-panel.tsx` directly opens only the current project root (`.workspace`, an empty relative path). There are no repository selection tabs, picker, or nested navigation. At the user's request, the 36px top bar is restored, sharing its height, background, and bottom border with `data-dock-tab-bar` and other panels. The left side contains the shared `DockGrip`, Git icon, and `Git` title; the right side contains a 24px close button with a 14px SVG ×. On mobile, the handle is hidden according to the shared rule. `DockBody` uses default top spacing of 36px to keep the body from covering the bar; both the top bar and body close with `Ctrl+W` when focused. The top bar remains in detail, diff, loading, and no-repository states. The GitHub login button and connected account information sit to the left of the close button in the panel header. They render only once in `GitPanel` to preserve their position and login dialog state across detail, diff, loading, and no-repository states. Git maximizes and restores by double-clicking the shared panel handle. `restoreGitPanel` normalizes existing Documents/subrepository tabs and the active selection to the single current root. `workspaceUi.git` owns its identifier, `workspaceUi.chrome.gitOpen` its open state, and `workspaceUi.dock` its layout. Root switching waits for account UI loading before mounting the new project screen.

`GitWorkbench` portals Pull (down arrow) and Push (up arrow) into the title bar's `actionsHost`. They appear in that order to the left of the GitHub account and provide accessible names and tooltips. They are disabled during loading, commit/remote operations, while the AI dialog is open, when there is no repository/remote, or in detached state. Remote requests include the workspace from the repository response to avoid operating on the wrong root after a project switch. `POST /api/git/remote` checks Git capability and full file access, and the server reads the current branch's remote and merge configuration. It fails if there is no upstream and does not accept arbitrary remotes, refs, or options as API input. Pull uses `--ff-only --no-rebase --no-autostash`; Push applies `--no-force --no-follow-tags --recurse-submodules=no` to the explicit `HEAD:upstream`. Within the server process, only one remote request per repository runs at a time, with a 120-second limit and noninteractive authentication. After success or failure, the lists are reloaded while preserving manual drafts and valid selections.

`GitWorkbench` remains mounted under `DockBody` while moving or hidden. Closing the panel or using `Ctrl+W` collapses the Git panel; reopening preserves details and commit drafts. Drafts are not persisted. Previous/next tab signals are ignored. Existing saved tab identifiers are used only for docking layout compatibility. Mobile foreground behavior, Esc, and Back use the shared panel registry. Commit context menus close before the panel.

The default screen presents commit history, changed files, and the composer in that order, with initial heights of approximately 20:50:30. The composer starts at 37.5% of the changes section. `GitComposer` provides a 12px interaction area along its top boundary, matching the agent input, with hover and keyboard-focus highlighting; it does not use CSS corner resizing. Dragging the boundary upward enlarges it, and dragging downward shrinks it, with the bottom fixed. Pointer capture handles mouse and touch input and ends on release, cancellation, or capture loss. Up/Down arrows adjust by 12px; Home/End set the minimum/maximum. The minimum height is 144px; the maximum is 70% of the changes section, with a minimum of 144px. ResizeObserver responds to panel size changes. User-selected height is retained in panel memory, including while hidden in the detail screen or while the panel is closed. Commit and AI Auto Commit buttons appear in that order to the right of the title, with a description field below. Per-file/select-all checkbox selections remain only in panel memory; new files are not selected automatically. `GitWorkbench` retains the commit-history section ratio in memory (default 20%, range 15–85%) and keeps the default list DOM hidden on the detail screen to preserve both lists' scroll positions. Each list scrolls independently with overscroll containment. The boundary uses pointer capture for mouse and touch dragging and ends on release, cancellation, or capture loss. Keyboard Up/Down adjusts by 5%, Home/End moves to either limit, and accessible separator values update as well. Commit rows are 28px high, graph lanes are spaced 10px apart, and relative time is calculated by `relativeCommitTime` using only the largest unit. Returning from a working-tree diff restores the default screen's selection, draft, and scroll position. Commit POST requires an explicit `files` list. The server permits only paths that exactly match the current change list and includes old paths for renames. After registering new files in the index, it uses literal pathspecs and `git commit --only`, so unselected staged files are not committed. Untracked folders are also listed file by file.

Repository status is queried first. If the root is not a repository, an empty state appears and no log or working-tree requests are sent. Retry can refresh the state after Git initialization. ### Mobile Dock and Panel Switching

Mobile dock selection only changes the foreground through the shared `openWorkspacePanel` or `showMobileEditor`; pressing the same button again does not close it. On desktop, only an open, focused panel closes through `closeWorkspacePanel`; other open panels receive focus, and closed panels open.

Dock swipes select the adjacent panel in the displayed dock order, relative to the mobile foreground panel or desktop focused panel. Left-to-right selects the previous panel (-1), and right-to-left selects the next (+1), triggering once when movement reaches at least 20px and horizontal movement exceeds 1.5 times vertical movement. Hidden and unauthorized items are skipped, and navigation stops at either end. Selected tabs are preserved; this does not switch tabs instead. For chat and Android, which are absent from the dock, use a dock button to select the target panel.

Below 768px, `useMobilePanelSwipe` determines the `data-workspace-panel` within the workspace when touch begins. In the file explorer, a rightward swipe selects Documents and a leftward swipe selects Files, stopping at either end. Both directions use the toggle's scope selection and preserve the query, search mode, editor tabs, and foreground panel; guests retain Documents. See the [file explorer contract](../features/projects-files-search/file-folder-exploration-and-operations.md#scope). One-finger swipes in the editor, agent, terminal, Git, and task bodies use the existing tab-switching path. Left-to-right selects the previous tab, and right-to-left selects the next, wrapping at either end. Panels with one or no tabs remain unchanged. The screen is not divided into regions by height; one switch occurs when horizontal movement reaches at least 30px and vertical movement is no more than 0.6 times horizontal movement. Vertical movement after the initial 10px cancels the tab gesture.

In the body, horizontal scrollability is checked for the touch-start element and its ancestors up to the corresponding `data-workspace-panel`. If any area has `overflow-x` set to `auto`, `scroll`, or `overlay` and satisfies `scrollWidth > clientWidth`, the entire touch is left to native browser scrolling, without invoking `preventDefault` or tab switching. This rule applies even at either end, regardless of current scroll position or movement direction. Areas with no actual horizontal overflow or only vertical scrolling retain existing tab switching. Detection stops at the starting panel's boundary; Plain's `data-mobile-key-bar` retains the tab-switching priority rule below.

`EditorPane` marks Markdown Hotview as an allowed body area. For regular files and Markdown Plain, only swipes starting on ordinary buttons within `data-mobile-key-bar` switch tabs, preserving horizontal scrolling, selection, and pinching throughout the body. Arrow presses and drags control the cursor instead; entering an arrow cancels an in-progress tab swipe. See [Mobile auxiliary key bar](ui-editor-input.md#mobile-auxiliary-key-bar). `EditorPane` enables `CodePane`'s shared modifier key bar in mobile Plain regardless of keyboard visibility, floating over the body above status without a separate layout reservation. Embedded editors may omit this option. The key bar uses Esc, Tab, Ctrl, Shift, arrow keys, and Undo/Redo for editable files from the CodeMirror keymap; collaborative history also follows the existing keymap. Swipes prevent horizontal scrolling of the key bar and subsequent key clicks; short taps execute existing key functions.

Horizontal scrolling and reordering in the tab row, popups and input fields, task-row deletion, Gantt scrolling, and schedule dragging remain separate gestures. Multiple fingers, `touchcancel`, window resizing, blur, and screen hiding cancel an active gesture. Actual tab switching occurs only when the current foreground panel matches the starting panel. The rationale for separating switching roles is recorded in [ADR 0079](../decisions/0079-mobile-panel-swipes.md).

## Overlapping windows and resize boundaries

The 4px dividers between docked panels use a single `edge` fill without overlapping additional borders. On hover or keyboard focus, the entire divider uses `accent`. Pointer capture, arrow-key resizing, and minimum/maximum ratios are preserved. The terminal's default background is transparent, exposing the panel background, while explicit program background colors and selection-mode snapshots are preserved.

Desktop `DockBody` does not establish its own z-index. This prevents menus and popups opened inside the body from being trapped in a lower parent layer behind sibling resize boundaries (`z-index: 40`). The body rectangle excludes the header and boundary areas, preserving the existing body layout and drag capture. The mobile layer used to order panels in front is retained.

The terminal command button editor is portaled to `document.body`, and its fullscreen backdrop blocks pointer input to panels and boundaries behind it. Other popups must also receive pointer input within their own areas instead of allowing boundaries behind them to receive it. Fullscreen modals block input across their backdrop, while small menus block input in the areas they cover. Do not merely hide the cursor shape while allowing resizing behind them to remain active.
