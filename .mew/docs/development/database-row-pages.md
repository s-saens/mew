## Database Row Subpages

### Creation and name-based paths

Follows the [Row Page Decision](../decisions/0012-database-row-pages.md) and [Table Database Guide](../../../docs/guides/database.md). Converting the primary column to a page creates `<대표열 값>.md` directly beneath the document containing the DB. The `송상훈` row of a DB in `Books/_Books.md` is stored as `Books/송상훈.md`. If the source is the single document `Books.md`, it is converted to `Books/_Books.md` just like a regular child document. No separate `데이터베이스` document or DB UUID folder is created. A DB without an owning document creates pages at the project root.

Filenames retain Korean characters and spaces, while path separators and OS-reserved characters are replaced with spaces. Prefixes avoid hidden, representative, and reserved names, and long names are shortened. If a file or folder with the same name exists, numbers starting at 2 are appended without overwriting. Row UUIDs and DB UUIDs remain in frontmatter and DB linkage data. Under [0093](../decisions/0093-database-row-title-renames.md), changing a page-type primary title renames the linked file in its current directory after save confirmation. A parent page renames its folder and representative together, retaining children and attachments. A manually moved or named path remains intact during unrelated synchronization; a later primary title change renames it within that selected location. Existing paths are not bulk-renamed on opening.

### Immediate title previews

Primary page title input publishes the same immediate explorer and open-tab previews as Task titles. Until confirmation, opening a page uses its existing path. `EditorDbApi.previewPageTitle` is an optional synchronous host hook; the Mew host resolves scoped absolute paths and publishes the preview. Completion follows the preview through confirmed path remapping and removes only the matching draft. A failed save restores the confirmed title while retaining newer input. After a primary title save or row event, the table refreshes linked page paths without replacing newer local title drafts.

### Legacy paths and structural mutations

Existing `데이터베이스/<DB UUID>/<행 UUID>.md` files are moved to name-based paths beneath the source document on the next regular DB query or edit. Body content, user properties, and row links are preserved, and document links and DB paths are adjusted together. If the owner path is missing or no longer exists, it is recovered only when exactly one source document contains the same DB. Only empty autogenerated DB representative files and empty folders are cleaned up; those with additional body content or other files are retained. Path migration is deferred during row page autosaves to preserve the save request's original path.

DB REST responses also return `documentPageMutations` when paths change. The host DB API saves project drafts and defers autosaving before the request, applies changes from successful responses to open tabs through `applyDocumentPageMutation`, and then resumes autosaving. The shared rename engine registers a rollback with the DB synchronization; parent and child moves are composed into original-to-final mappings, so tabs do not fetch intermediate paths. Linked row paths and nested DB owner paths are updated in the same DB transaction. If the working folder changes while waiting, the request is not executed, and responses already in progress are not applied to tabs in the new folder. Moving a DB's owning document through regular document operations after document creation also updates `owner_path`.

### Shared fields and save baselines

Frontmatter `title` is shared with the primary column, and other columns use their display names as field names. Numbers, booleans, and multiple selections are stored as YAML numbers, booleans, and string arrays. Selection types and options are passed to the Hotview property editor through existing `mew:field` comments and are not mixed with same-named fields or options in regular documents. `_mew_database` and `_mew_row` are linkage identifiers and are hidden from the property view. `상위파일` points to the DB folder representative. `description` starts with the default title. `created` and `updated` are not forcibly created, and body edits on DB pages do not automatically update an existing `updated` either.

`server/db/rowPages.ts` compares paths, last shared values, and column names in `mew.row_pages` to apply only fields changed in frontmatter to the DB. The baseline's `pathTitle` records the last filename-synchronized title separately from the current shared values. Older baselines fall back to their stored primary value. Row-page autosaves and background file-watcher refreshes update shared fields while retaining `pathTitle`; a subsequent ordinary query or edit performs any deferred rename. Background refreshes cannot deliver mutations to a requesting browser, so they must leave structural changes for that request. DB changes write the corresponding fields back to the file while preserving the body and other properties. Renaming a column removes the old frontmatter key. All values to be changed are validated, and if the DB transaction fails, files and renames are rolled back too. This recovery handles runtime exceptions; it is not a persistent file transaction that recovers from forced process termination.

`server/db/rowPageIntegration.ts` connects file autosaving and external file watching. File saves also require the DB capability and project-wide modification permission. Comparison against the save baseline `expectedContent` prevents an older draft with only body edits from overwriting the latest shared fields, and saves are rejected if the same field was changed to different values. Regular document saves and moves do not depend on Postgres availability. Document moves adjust linked paths; if the recorded file is missing, recovery searches within the project for a document matching both linkage UUIDs. Symlinks, hidden folders, archives, and access-blocked folders are excluded from this recovery search, and no candidate is automatically chosen if multiple candidates exist for the same row.

### Detaching and live updates

Converting a page back to text retains its linked path but stops field synchronization. Converting it back to a page reuses the same row's file and body. Deleting a row or DB does not automatically delete the generated page body. Back up Postgres and files together because Markdown alone cannot restore DB definitions, options, or all rows.

Row pages opened in the active editor pane subscribe to their DB row and schema events and reread the file. Tabs without unsaved changes immediately display the latest frontmatter; drafts being edited are preserved, and shared fields are merged on save. Column types use the existing property editors for numbers, selections, multiple selections, and so on; numbers, arrays, and empty values saved in subpage Hotview retain YAML number, array, and `null` types.
