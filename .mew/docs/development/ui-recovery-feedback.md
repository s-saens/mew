## Installable web app and startup guidance

For direct access, `index.html` links to `public/manifest.webmanifest`, PNG icons (192·512px), and an Apple touch icon (180px). In the manifest, `display` is `standalone`, and `display_override` is ordered `fullscreen` → `standalone`. Supported browsers preferentially request the `fullscreen` display mode; unsupported browsers fall back to `standalone`. Launching the installed app is separate from entering `requestFullscreen()` through the Fullscreen API, and installation alone does not guarantee keyboard lock permission or resolve interception of mobile back navigation. Installation requires a secure context over HTTPS or localhost.

The installation assets `public/app-icon-{180,192,512}.png` display a static gradient mixing purple (`#30264c`) and teal (`#123841`) on the default Midnight navy background (`#101827`), with a light inner mark (`#dbe7f5`) and no outer square border. The background uses the default palette from `shared/theme.ts` and the 135° radial gradient from `themeBackgroundImage()`, capturing the same `inset: -8%` area as the app background in a stationary state. Preserve the size, position, and stroke width of the inner path from `public/favicon.svg`, centered within an area spanning 60% of the width and height. The browser favicon and full loading logo retain their existing square borders. The validation and application status of the icon change follows the [work record](../work/app-icon-borderless.md).

Do not add a separate offline cache or service worker to support installation. The app uses the existing host, authentication, and connections, and cannot be used for work when the host is off or the network is unavailable. Retain Mewlink's existing service worker for relaying remote static resources; do not interpret it as offline work functionality.

Because Mewlink runs the installed host app in a nested frame, the top-level public device page needs a manifest, icons, and installation events. The central `/app.webmanifest?device=...` uses the public device path as `id` and `start_url`. The app receives installation availability and launch mode through the existing trusted MessagePort connection channel and forwards user actions on the install button to the parent page. Mobile manual installation instructions direct users to install from the public device page rather than an internal temporary launch URL. Changes to the Git-excluded `mewlink/src/app-manifest.ts`, the central connection parent, and the internal launcher take effect only when the user deploys them to the central frontend separately from the host Mew update.

Display startup guidance in the order installation → fullscreen. Provide an install button when the browser supplies an installation event. On mobile and desktop browsers that support installation, provide the manual installation path through the iOS share menu or browser menu even without an event. In other environments, show installation guidance only when an installation event is available. Hide both prompts when the initial load's installed display mode (`standalone`·`fullscreen`·`minimal-ui`, iOS `navigator.standalone`) or the `appinstalled` event confirms app launch or installation. Do not mistake subsequent Fullscreen API entry for installation, and hide installation guidance during regular web fullscreen.

Immediately save each installation/fullscreen prompt's **Don't show again** setting independently as a scoped browser setting. A prompt dismissed without checking the option stays hidden only for the current app lifetime. Approval request notifications take priority over both startup prompts, and prompts appear even when Mewpet is disabled or has no skin. Preserve remote viewer hide settings, actual fullscreen bindings, and retries after failure. The [Mewpet feature document](../features/appearance-accounts-operations/mewpet-mascot-notifications-and-breaks.md#app-installation-and-fullscreen-guides-at-startup) owns detailed prompt behavior, and the [browser storage contract](browser-storage.md#dont-show-again-for-startup-guidance) owns storage keys. Record the decision rationale in [ADR 0064](../decisions/0064-installable-web-app.md).

Actual Android/iOS installation and fullscreen/back navigation behavior in installed mode require verification on physical devices. Isolated browser checks that mock installation events, display modes, and the Fullscreen API do not replace this verification.

## Shared loading indicators

`packages/ui/src/loading-indicator.css` and `LoadingIndicator` from `@mew/ui` own three types of loading indicators. Select a variant below according to its purpose.

| Type | variant | Usage |
| --- | --- | --- |
| Logo | `logo` | Full entry into Mew, the demo, and Mewlink; full project restoration and switching |
| Three dots | `dots` (default) | Inside panels, editors, and buttons; agent connection, initial preparation, and history retrieval; Mewlink lists and recovery |
| Circular | `spinner` | Attachment upload pending tags in new agent input and pending queue editing |

Do not use the logo for internal retrieval or recovery. Follow [ADR 0075](../decisions/0075-attachment-spinner-indicator.md) for restoring circular indicators in attachment tags.

The three dots inherit the current text color. Arrange three equally sized circles in a row and vary each dot's transform scale and opacity over a 1.2-second cycle. Offset their phases by 160ms so they grow and shrink in sequence from the left without changing position. The default height is 16px, the width is 1.5 times the height, and the dot diameter is 24% of the height. Use 15px for comment submission and 20px for editor/panel waiting states. Agent connection, initial preparation, and history retrieval use the same three dots, replacing the previous empty-bubble shimmer.

The circular indicator uses a 2px circular border in the current text color with only the top border transparent, rotating at a constant speed over a 0.8-second cycle. Display it as a 12px square in attachment upload pending tags, and replace it with the file type icon when the upload finishes. Because sending is blocked during uploads, do not add loading states to user bubble tags; retain the completed file icons. The [agent input and attachment contract](../features/terminals-agents-automation/agent-input-mentions-skills-and-attachments.md) owns detailed tag behavior.

The full loading logo uses the square border and inner mark from `public/favicon.svg` as an inline SVG mask with the same coordinates and stroke width. Keep the logo fixed and rotate only the muted gray-purple and blue-gray light layer every 2.4 seconds. `StartupScreen` on the shared Mew/demo entry screen and `ProjectLoadingOverlay` during full restoration/project switching display a 56px logo. Both screens apply two shadow layers colored with the selected theme background (`--color-surface-deep`) to the `mew-loading-logo-shadow` wrapper outside the logo. Preserve the 80% and 60% opacities, offsets, and blur radii; theme changes update both layers immediately. Gradient themes use their base background color. The shadow spreads downward along the logo outline, is not clipped by the mask, and does not rotate with the logo's light layer. The entry screen uses the lightweight `@mew/ui/loading-indicator` entry point so the initial display does not load unnecessary UI package dependencies.

React logo indicators share the document timeline origin. When loading stages replace the logo during startup, authentication, workspace preparation, or restoration, initialize the new running highlight to the current page phase before paint rather than restarting at zero. Preserve the 2.4-second CSS transform animation and existing pause/reduced-motion behavior; do not add a JavaScript frame loop. This synchronization is local to the current document and does not coordinate separate Mewlink launcher frames. See the [continuous rotation work record](../work/loading-indicators.md#continuous-logo-rotation--2026-10-30).

Git-excluded Mewlink uses the same CSS and the `loadingIndicator` DOM helper. Explicitly specify a 48px logo for the initial full connection, and use three dots for buttons, lists, connected-browser retrieval, and top-bar recovery. The public entry HTML also specifies the logo class before JS is ready. Applying this requires the user to build the local app and deploy the central frontend separately.

The indicator itself is decorative, so set `aria-hidden`. Communicate status through the container's translated name and `role="status"`, or the button's `aria-busy`. Pause the dots, circular indicator, and light layer together with `active=false` or `data-paused` on an ancestor. With reduced motion, retain three static dots, a static circular indicator, and a static logo highlight; in forced colors mode, use the system body text color. Keep the circular indicator's top border transparent even in forced colors mode. Do not use additional SVG requests, JS frame loops, SVG path animations, or animated filters. Use a static CSS filter only for the full-screen logo's shadow.

On 2026-10-26, the full logo and internal three dots were checked in isolated Chromium on mobile/desktop and in both themes. In a trace collected for 1.5 seconds after initial display with 48 instances of each type animating simultaneously, Layout, Paint, and UpdateLayoutTree each occurred 0 times. These results cover the logo and three dots at that time and do not include circular indicator validation. They do not replace performance guarantees for actual mobile or production environments. The validation and application status of the subsequent circular indicator restoration follows the [work record](../work/loading-indicators.md).

## Mewlink stay-signed-in prompt

The central **Stay signed in in this browser** prompt uses the connected app's surface, body/secondary text, border, and primary-button colors. On the app origin, observe only the same-origin app root's `style`/`class` changes and forward necessary derived colors through the existing channel. Accept only allowed 6-digit HEX tokens; store no separate central theme. Gradient prompts retain a 75% background and 6px blur. Stop observation on disconnect or app replacement; without tokens, retain the central theme.

Git-excluded `mewlink/src/connection-parent.ts`·`mewlink/src/launcher.css`·`mewlink/test/trusted-browser.browser.test.ts` own implementation and browser checks. Application requires central frontend deployment.

Display the stay-signed-in prompt at the **top center**, avoiding the bottom area used by Mewpet. Add 72px to the top safe area to place it below the header/tabs, and maintain left/right safe areas, a minimum 12px margin, and a maximum width of 28rem. Align the text, primary button, and close control in one row, allowing only the text to wrap on narrow screens. Show errors on the next row, and keep buttons at least 40px high in touch environments. Use 12px corners and small internal padding, without moving focus or changing the app/Mewpet layers.

If RTC temporarily becomes `disconnected` after the app is displayed, retain the existing screen for 1 second. If it recovers before then, omit the indicator; otherwise show only the shared three dots at the **center of the top bar**, 12px below the top safe area. Show the indicator immediately when a confirmed failure starts full reconnection. Use the same indicator for an offline host, lost internet connection, delayed authentication, and rate limiting. Give the status a visually hidden loading name; omit visible connection, retry, and failure text, backgrounds, borders, blur, and dismiss controls. Preserve the existing iframe and drafts, do not intercept pointer input with the indicator, and honor reduced motion. Before the app opens, recovery likewise shows only an indicator. Initial entry retains the full-screen logo.

After the initial failure, allow **11 automatic retries**. Count actual reconnection attempts or host-presence probes; waiting while hidden or offline and canceled attempts do not consume this allowance. Stop automatic recovery after exhaustion and cover the page with a themed error screen. Use the existing connection background, only the heading “연결 실패했습니다” (“Connection failed”), a primary reconnect action, and the device-list link. Do not display retry counts or diagnostic details on the exhausted recovery screen. Preserve the inert app iframe behind this screen. Manual retry resets the allowance and reconnects in place; successful identity verification removes the screen and restores input, title, and focus. Explicit authentication denial, revoked access, changed account/origin, and logout retain their immediate termination paths. See the [remote access contract](remote-access.md#reattaching-the-same-rtc-after-a-brief-signaling-interruption) and [ADR 0099](../decisions/0099-quiet-automatic-recovery.md).

### Automatic recovery within panels and menus

While a read subscription, agent connection, or metadata load is retrying automatically, show the shared dots with a translated accessible loading name. Keep existing conversations, command rows, memo contents, and terminal drafts visible. Do not show red failure text or instructions to refresh during this wait. Disable actions that depend on unverified command state. A failed save, prompt submission, command execution, permission check, or explicit authentication request remains an actionable error; automatic reads must not erase it or repeat the action.

Agent-panel connections and safe command-status reads retry without an attempt limit at 0, 250, 500, 1,000, 2,000, then at most 3,000ms. Successful synchronization resets the delay.

- Online, visible, `pageshow`, or verified remote recovery wakes a pending retry immediately, subject to transport readiness and duplicate guards. Hide/offline events pause monitoring; unavailable states prevent new connections and polling until wake.
- Supported agent sockets check a fresh matching relay probe on foreground return and after 15 seconds idle. Bound a stalled initial relay response with a monotonic active-time budget independent of provider startup, after virtual-socket quota and backpressure waits.
- Bound command-status reads through JSON completion to 5 seconds of available transport time. Foreground return replaces stale reads and ignores late replies.
- Retain conversation/composer DOM and drafts. Reconnect or refresh in place without reload or write replay; transient waits show only dots, however long. Fatal agent events stay visible and stop reconnection.
- Preserve scoped actionable errors for permanent command-status HTTP 4xx except 408/429 and invalid JSON, including a known permanent status whose diagnostic body times out. Explicit cancellation retains the caller's reason.

See [ADR 0111](../decisions/0111-fast-agent-recovery.md), the [session contract](agent-sessions.md#messages-reconnection-and-queues), and the [fast recovery work record](../work/fast-agent-recovery.md).

Mewpet assistant connections and project command metadata retain the shared `AUTOMATIC_RETRY_LIMIT` of 11 after the initial failure. Successful synchronization resets their allowance; exhaustion produces a scoped error and an explicit retry control. A panel-specific failure does not cover the entire workspace. Memo and terminal subscriptions retain their existing retry lifetimes while following the same quiet presentation. The owning [agent](../features/terminals-agents-automation/agent-conversations-queue-and-restoration.md), [command](../features/terminals-agents-automation/project-command-buttons.md), [terminal](../features/terminals-agents-automation/tmux-shell-terminals.md), and [memo](collaboration.md#shared-memo) contracts define their behavior. Earlier bounded recovery verification and application limits remain in the [2026-10-30 work record](../work/quiet-automatic-recovery.md).

On 2026-10-20, simulated-connection Chromium checks using the actual launcher captured layouts at 390/1100px with light/dark central themes and each app theme. Stay-signed-in, recovery in the same iframe, permission revocation, logout, and static design checks passed. The central frontend was not built or deployed.

On 2026-10-21, the 3 simulated-connection Chromium checks `connection-screen.browser.test.ts`·`recovery.browser.test.ts`·`trusted-browser.browser.test.ts` passed. ## Header notifications

When unacknowledged notifications exist, show a bell icon and count immediately to the left of the active sessions button. Subscribe to the same notification queue independently of the Mewpet skin and remote viewer hiding setting, and provide navigation to the relevant screen, individual acknowledgment, and acknowledgment of all notifications in the list. Keep notification channels and tests in the Notifications tab in settings, and show additional toast options only when Mewpet is enabled. Hide Mewpet, fallback images, and loading text while the selected skin loads. Show new notifications through the shared `Toast` for 2.6 seconds, with the latest notification replacing the previous toast. Unacknowledged items remain in the list after the toast ends. Detailed storage, delivery, and defaults follow the [notification contract](../features/appearance-accounts-operations/mewpet-mascot-notifications-and-breaks.md#notification-settings-and-pc-desktop-notifications).

## Full-screen loading during session restoration and return

During account/workspace restoration or revalidation after hidden-page return, bfcache restoration, or presence reconnection, keep the cached screen visible under a central nonmodal indicator. Use `pointer-events: none` and no black cover to preserve header/Dock/panel input and focus. One `ProjectLoadingOverlay` combines project-switch and session-refresh status, using body text color in both themes, `common.loading`, and reduced-motion behavior.

`useRefreshTasks` tracks explicitly registered restoration requests with individual tokens. These include App authentication, current workspace, per-account workspace/root tabs, and first-level tree queries; AgentPanel account-tab restoration; and useTabs restoration of active document bodies and revalidation of open-file permissions. Concurrent requests wait until the last request succeeds or fails, and completion by an unmounted owner does not update state. Body loading when a user opens a file retains the editor-panel indicator; regular tree-change signals, autosave, activity heartbeats, agent turns/streaming, and lazy loading of inactive documents do not trigger full-screen loading.

When returning from hidden to visible or through bfcache's `pageshow.persisted`, `usePresence` runs the existing permission revalidation and workspace query if a socket is open. Disconnected sockets follow the existing reconnection path. Periodic activity reports do not trigger a return refresh. This indicator shows request progress and does not mean all streaming connections are ready.

Verification: `server/workspace-switch-ui.test.ts` uses delayed responses to check initial restoration, cached-body refetching, visibility/bfcache return and presence reconnection, concurrent authentication/tree/file-permission queries, clearing after failure, and nonblocking regular tree notifications. It also checks the central indicator, transparent background, retained click/touch and keyboard operations, and reduced motion at 1100px in dark mode and 390px in light mode.
