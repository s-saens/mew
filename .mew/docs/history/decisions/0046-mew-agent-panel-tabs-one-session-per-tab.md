## Background

[ADR 0043](0043-mew-agent-workspace-scope-and-runtimes.md) fixed the limit at one session per runtime. The panel always showed only one conversation, so starting another task required
clearing the current conversation (`/clear`) or replacing it by loading a past session. There was no way to run
two tasks side by side—to leave document cleanup running while asking about a bug, you had to close
out the conversation in progress. The terminal already supports multiple sessions through tabs.

Also, "Load Previous Session" was a dropdown behind a header icon. Opening the panel initially showed an empty conversation, with nothing
on screen indicating that past conversations could be continued. To resume, you had to know that the button existed and click it.

## Decision

Use tabs to separate conversations. One tab = one session = one child process.

### 1. Include the tab in the channel

- `/api/agent/ws?runtime=<id>&tab=<id>`. The server session registry key becomes `runtime+tab`. This replaces only ADR 0043's "one per runtime"
  rule—the decision that cwd and the file-tool boundary are the workspace remains unchanged.
- `tab` is an opaque string generated by the browser. The server does not interpret it and uses it only as a map key;
  if it does not match `[A-Za-z0-9_-]{1,64}`, the server terminates the connection with 400. If omitted, it defaults to `default`.
- The tab list and names remain only in the browser (`mew:agent-tabs`). Each name comes from a single line of that conversation's first question—the
  server does not know tab names.

### 2. An empty tab is the resume screen

- A tab with no messages exchanged yet displays a list of past sessions in the conversation area. Selecting one resumes it in that tab;
  typing directly uses the new session already allocated. Opening the panel initially provides one tab in this state.
- The `+` in the tab bar opens another empty tab. Starting a new conversation and resuming one share the same screen
- Do not open the same session in two tabs—sessions already open are disabled in the list with the label "Open in Another Tab." Two processes
  holding the same transcript would corrupt the history.

### 3. Closing a tab and closing a window are different

- Sessions survive closing the window (cleaned up after 30 idle minutes once work finishes). Reopening restores them by replaying past events—the independent supervisor in [ADR 0048](0048-mew-agent-supervisor-process.md) owns their lifecycle
- Only closing a tab ends its session (`close_session`). Since tabs will be opened and closed frequently, waiting for the idle timer would let child processes
  accumulate (the same pattern as the 2026-08-10 incident involving 28 orphan processes and 3.4 GB).
- Tabs that are not being viewed keep their WS connections. Switching tabs must not stop a conversation in progress. Connect
  only tabs that have been opened at least once—starting all restored tabs at once would launch a flood of processes.

### 4. What was removed

- Remove the header's 'New Session' (`/clear`) button and 'Previous Sessions'
  dropdown button (the two controls introduced by [ADR 0036](0036-mew-agent-session-controls-and-usage.md)). A new tab is a new conversation, and an empty tab is the resume
  interface, so both controls were second ways to do the same things.
- Also remove the WS message `new_session` and `AgentSession.newSession()`. ACP `session/new` itself remains in use during the handshake—what is removed
  is the operation that clears a conversation in place.
- Revisiting this is allowed: if a need arises to clear just the conversation within a tab, the operation can be restored. It is
  being removed now because having two paths makes the interface less clear, not because it is dangerous.

## Rationale

- It looks like terminal tabs. People opening the window already use tmux through tabs—the same interactions apply
- The only cost of multiple sessions is the number of child processes. No isolation or permission boundaries
  change (the owner/manager gate, cwd = workspace, and ADRs 0037 and 0044 remain unchanged).
- "Empty tab = resume screen" exposes the feature while removing a hidden button. Whether to resume or start fresh is a
  decision made when starting a conversation, not something to find in a menu afterward.

## Results

- N tabs mean N adapter and CLI processes. The 30-minute idle rule (exit when work is finished and no panel is connected) handles
  cases where the browser is simply closed.
- Runtime selection still remains only in the browser (`mew:agent-runtime`) and can be changed per tab. Switching a tab's runtime
  switches to that runtime's conversation; switching back leaves the original conversation intact (because the registry key is `runtime+tab`).
- Because tab names come from the first question, reconnecting after the event buffer (the most recent 500 events) has pushed out the first question
  uses the earliest remaining question as the name. This is left as is because it is only a name.
