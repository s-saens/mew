This is the prior contract, retained as implementation history. Current behavior follows [native Chrome video](../development/browser-desktop.md) and [localhost app tabs](../development/port-preview.md).

## Internal DOM browser

Localhost HTTP(S) links in Mew, including terminal URLs and command-menu port numbers, open the **Browser** workspace panel. The dock opens the same panel; **Menu → Localhost browser** opens its port list even while an app is displayed. The address bar also accepts external HTTP(S) sites; external links elsewhere retain their behavior. `localhost`, IPv4 loopback, and `[::1]` links retain path/query/fragment. Port buttons open `http://localhost:<port>/` and close the menu without running/stopping a command or opening a terminal session. Repeated requests, even for the same URL, navigate the existing panel.

The host needs Chromium for loopback apps and ordinary installed Google Chrome for external pages; the app must already run. `server/browser-dom-executable.ts` chooses by the top-level URL host. Normalized `localhost`, `*.localhost`, IPv4 loopback (`127.0.0.0/8`), IPv6 loopback, and IPv4-mapped loopback use Chromium; other hostnames and LAN addresses use Chrome without DNS classification. `MEW_CHROMIUM_EXECUTABLE` overrides the automation binary, otherwise Playwright's bundled Chromium precedes installed Chromium. `MEW_CHROME_EXECUTABLE` overrides ordinary Chrome, otherwise installed Google Chrome locations are checked. Both retain `MEW_BROWSER_EXECUTABLE` as a lower-priority legacy override. There is no automatic cross-role binary fallback. `server/dom-browser.ts` launches an isolated headless browser and ephemeral context for each authenticated `/api/dom-browser/ws` socket. App JavaScript, APIs, navigation, and HMR run on the host at the native URL; rrweb records snapshots/mutations, and `DomBrowserPanel` rebuilds them without executing app scripts on the viewing device. Clicks, values, keys, scrolling, and viewport changes return by rrweb node ID and document generation, preventing stale input from acting on reused IDs. Input stays blocked until the current document loads and its full snapshot is rebuilt. Ctrl/Cmd+W closes this panel, not an editor tab or host page. Back, Forward, refresh, address entry, close, and manual reconnect share the session.

The Browser follows Mew's resolved dark/light mode, including custom palettes classified by the root `dark` class. Before resize/navigation on each connection, the viewer sends `{ type: 'color-scheme', colorScheme: 'dark' | 'light' }`. The host stores this preference before launching the selected browser session, uses it for the new context, and applies live changes with `page.emulateMedia` without navigation or a new document generation. A class observer sends only mode changes and is disposed with the socket. Each replay iframe sets the same CSS `color-scheme`, including after snapshot recreation, so its `prefers-color-scheme` CSS agrees with host-side `matchMedia` regardless of the viewing device's OS preference. Sites must support automatic color-scheme selection; explicit app theme choices remain the app's responsibility. See the [theme synchronization work record](../work/dom-browser-theme.md) for verification.

The viewer schedules batches in arrival order on its local monotonic live timeline, without waiting for host timestamps or recorded gaps. Each new host document sends its recorder-generated full snapshot once. Navigation commands request another only if no new document loaded, including SPA history and fragment changes. Document tokens use `crypto.getRandomValues`, including on ordinary external HTTP origins.

Scrolling is native on the viewer, including touch momentum. Each document/nested container has increasing viewer revisions; movement updates the host at most once every 60 ms. The host applies coordinates instantly and includes the revision in later rrweb scroll events. The viewer ignores older revisions, leaves matching coordinates unchanged, and applies accepted host scrolls instantly in replay order without echoing input. This prevents delayed echoes and rrweb smooth scrolling from reversing gestures. CSS `scroll-behavior: smooth` does not animate synchronized/restored offsets. Replay rebuilds clear scroll state and timers without relaying restored offsets. Full document navigation and command-generation changes, including SPA Back/Forward, also clear recorded revisions. See the [scroll synchronization work record](../work/dom-browser-scroll-synchronization.md) for checks and device limits.

Direct and Mewlink DOM streams use the existing Mew WebSocket transport, without random preview hosts, Service Workers, or `PREVIEW_DOMAIN`. The central launcher imports `shared/remote-access.ts` and must be rebuilt/deployed with the `/api/dom-browser/ws` allowlist for remote use; an older launcher rejects that socket even after a host update. Agent OAuth retains its separate login video display.

Login and `portPreview` are required; guests and temporary-password sessions are rejected. The socket checks Origin/current access; revocation/logout closes the context. Each viewer has an ephemeral isolated Chrome/Chromium context and browser process without regular browser profiles or Mew cookies. Navigation accepts HTTP(S) on any host, but rejects credential-bearing URLs and Mew configured/listening or reserved development ports, including redirects, assets, and WebSockets on external hostnames. External HTTP(S) assets/APIs remain available. Popup links and `window.open` reuse the current page; unexpected pages/downloads close and dialogs are dismissed. Service Workers are disabled. Close/reconnect closes the owned browser context and process; session lifetimes and transport queues are bounded.

Replay uses a script-disabled iframe, restrictive resource policy, sanitized attributes, and bounded inline images/fonts/CSS, so viewer devices need not resolve local asset URLs. Full navigation/reload replaces the asset cache and aborts old fetches; old assets cannot consume the new budget. Browser-context guards block popup/nested-frame document requests before their first network request and check main-page redirect hops. DOM replay targets document-based interfaces; canvas/WebGL, nested frames, native dialogs, media, drag gestures, uploads, and full extensions are not guaranteed. Reconnect creates a fresh context without prior app login/storage. External navigation extends [ADR 0103](../decisions/0103-localhost-dom-browser.md) under [ADR 0106](../decisions/0106-dom-browser-external-sites.md), and the host runtime uses Chrome/Chromium under [ADR 0136](../decisions/0136-chromium-browser-restoration.md), with purpose selection under [ADR 0137](../decisions/0137-browser-purpose-routing.md); agent OAuth still uses its dedicated video desktop. Initial snapshots await bounded asset inlining: live replay removes neither host/network nor asset-fetch latency.

Chrome/Chromium handles HTTP requests, cookies, WebSockets, history traversal, and pointer activation through native browser APIs. External DOM pages still use Playwright control and rrweb recording; only the separate login video screen avoids CDP and Playwright execution. CDP Fetch interception validates document and asset URLs at every redirect hop, including Mew-port blocking. Obscura-specific Node networking/history bridges and reflected-link patches are no longer in the runtime. See the [restoration work record](../work/chromium-browser-restoration.md) for local verification and remaining application limits.

Top-level navigation, links, and redirects can change browser roles. Switching captures cookies and local storage in session memory by role, closes the old context/process, and recreates the target role with its saved state and current viewport/theme. Closing the panel clears both saved states. Cross-runtime Back/Forward reloads the retained URL; matching native history uses native traversal, including distinct `pushState` entries at one URL. History replacement does not append a toolbar visit. Automatic cross-role redirect chains stop after ten switches; successful navigation or a fresh user navigation resets this budget. Cross-role requests preserve available POST data and content/origin/referrer headers without copying source cookies. File-transfer requests whose body is unavailable are rejected visibly; uploads retain the existing unsupported boundary. Main-document and asset guards remain active before forwarding.
