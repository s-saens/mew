## 목적과 범위

로컬호스트 앱 브라우저의 메모리·CPU 사용량과 시작 시간을 줄일 수 있는지 검토한다. Obscura를 우선 후보로 확인하고 Lightpanda와 Chromium을 비교한다. 이 태스크는 전환 검토이며, 엔진 채택이나 구현 완료를 뜻하지 않는다.

로그인 영상과 원격 데스크톱은 별도 기능이다. 각각의 현재 원리는 [로그인 화면](../docs/development/login-desktop.md), [로컬호스트 앱](../docs/development/port-preview.md), [원격 데스크톱](../docs/development/remote-desktop.md)을 따른다. 이번 검토 대상은 로컬호스트 앱 브라우저다.

## 현재 구조와 교체 조건

호스트의 headless Chromium이 앱의 JavaScript와 API 요청을 실행한다. rrweb이 페이지 구조(DOM)와 변경 내용을 보내면 접속 기기가 화면을 재구성하고, 클릭·입력·스크롤을 호스트로 돌려보낸다.

최종 화면은 접속 기기에서 그리지만, 현재 호스트 코드도 `getBoundingClientRect()`로 클릭 좌표를 계산한다. 앱 자체도 요소 크기와 화면 너비에 의존할 수 있다. rrweb 기록, 스타일·이미지·폰트 전달, CDP 요청 가로채기, 실시간 갱신(HMR)까지 호환성을 확인해야 한다. 구현 진입점은 [server/dom-browser.ts](../../server/dom-browser.ts)다.

## 후보별 기대 장단점

아래 장점은 검증할 가설이다. Mew의 실제 앱에서 성능을 측정하거나 대체 엔진의 동작을 확인한 결과는 아직 없다.

| 후보 | 기대되는 장점 | 단점과 확인할 점 |
| --- | --- | --- |
| Obscura | Chromium 없이 자체 엔진으로 실행하므로 메모리와 시작 비용을 줄일 가능성이 있다. 자체 렌더링과 CDP·Playwright 연결을 지원해 현재 구조를 유지하기에 더 가까운 후보다. | CSS·웹 API·입력 동작이 Chromium과 다를 수 있다. rrweb, 요청 가로채기, WebSocket, 프레임워크 앱이 함께 동작하는지 확인해야 한다. 엔진 배포·업데이트 관리도 필요하다. |
| Lightpanda | 실제 시각적 렌더링을 생략하므로 호스트 처리 비용을 줄일 가능성이 있다. DOM과 JavaScript 중심으로 앱을 실행하는 방향을 검토할 수 있다. | 실제 화면 배치를 계산하지 않아 현재의 좌표 클릭과 스크롤 처리 변경이 필요하다. 크기 측정, 반응형 분기, 가상 목록 등 배치 정보에 의존하는 앱에서 동작이 달라질 수 있다. |
| Chromium 유지 | 현재 구현의 기준 엔진이며, 대체 엔진 도입에 따른 호환성 수정과 배포 작업이 필요 없다. | 실행 비용이 이번 최적화 대상이다. 브라우저 재사용 등 현재 엔진 안에서의 개선 여지도 함께 비교해야 한다. |

경량 엔진으로 바꿔도 접속 기기의 DOM 재구성 비용과 네트워크 지연은 남는다. 엔진 교체만으로 기존 Canvas·WebGL·동영상 재현 제한이 해결되지는 않는다.

## 검토 항목과 완료 기준

- [ ] 같은 호스트·앱·화면 크기에서 Chromium과 Obscura의 프로세스 전체 메모리, CPU, 시작부터 첫 화면까지 걸린 시간을 비교한다. 유휴 상태와 입력·스크롤·HMR 중의 비용을 구분한다.
- [ ] rrweb 초기 화면과 변경 기록, CSS·이미지·폰트 전달, 클릭·입력·키보드·스크롤·화면 크기 변경을 확인한다.
- [ ] 페이지 이동·뒤로/앞으로·새로고침, API·WebSocket·HMR, 모바일 화면, 테마 변경, 세션별 쿠키·저장소 격리와 종료 시 정리를 확인한다.
- [ ] 현재의 Mew 포트 차단, 리다이렉트 검사, 인증과 권한 회수 동작을 유지할 수 있는지 검증한다. 직접 접속과 Mewlink 접속을 구분한다.
- [ ] Lightpanda는 좌표에 의존하지 않는 입력 방식과 배치 정보가 필요한 앱의 처리 가능성을 검토하고, 필요한 변경 규모를 기록한다.
- [ ] 측정 결과와 호환성 실패를 근거로 Obscura 채택, Lightpanda 추가 검토, Chromium 유지 중 하나를 제안한다. 확인하지 않은 항목은 미검증으로 남긴다.

구현으로 이어지면 회귀 테스트, 관련 계약 문서, 결정 기록과 작업 기록을 함께 갱신한다. 적용 가능한 검사와 `npm run build`를 수행하고, 서버 실행·중지·재시작과 배포는 사용자가 담당한다.
