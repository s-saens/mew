Mew is an independent project. This repository's instructions and documentation are authoritative.

For an introduction and usage instructions, follow [README.md](README.md); for documentation navigation and writing, follow [.mew/docs/AGENT.md](.mew/docs/AGENT.md) and [Documentation rules](.mew/docs/README.md). Use `node server/document-descriptions.ts` to select relevant pages in the internal wiki. Use paths, headings, and text search for documents outside the wiki. Read only the relevant body text. There is no requirement to navigate or register MOCs.

Write this repository's project-owned documentation in English, regardless of the response language. Follow the [documentation language policy](.mew/docs/README.md#documentation-language).

Before starting work, read and follow the [Execution and verification rules](.mew/docs/development/getting-started.md); before UI work, also read and follow the [Required UI implementation rules](.mew/docs/development/getting-started.md#required-ui-rules) in the same document. When changing code, features, or operations, update the owning document and its wiki description as part of the same work. Keep decision records in [.mew/docs/decisions/](.mew/docs/decisions/README.md).

Treat the current message's Build and Deploy selections as explicit user instructions. They override older saved build/deploy requirements or prohibitions; the latest explicit user request takes precedence. With Build on, use `npm run build` for this repository and fix failures before completion; with Build off, skip the project build. Deploy on authorizes the task's documented deployment after verification without another confirmation. Check the actual target, credentials, and result. Tests, type checks, lint, and documentation checks remain applicable. The selections do not authorize running the Mew launcher or starting, stopping, or restarting servers; those require a separate explicit user request. Follow the [Execution and verification rules](.mew/docs/development/getting-started.md) for details.

Place new Git worktrees in `.worktrees/<브랜치 슬러그>` in the primary checkout. Replace `/` in branch names with `-`, and do not create another `.worktrees` inside the current worktree. Before creating one, check that the primary checkout's `.gitignore` contains `/.worktrees/`. When moving an existing worktree, check running processes and sessions for path dependencies and preserve uncommitted changes with `git worktree move`.
