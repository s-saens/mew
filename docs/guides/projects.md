## Select a project

To open a folder for the first time, click **Current project icon/name → Add project** on the left side of the header. Navigate to a server folder, then click **Open current folder** to switch to it (owner and manager). To transfer files from your device to the server, open a project and drag the files into the file explorer. [Create your first project](first-steps.md).

In mew, **one folder is one project**. The configured startup folder is also the first project opened. The screen address is always `/`, and the left side of the header shows the current project's icon, name, and command button. Clicking the project name opens the **project sidebar** to the left of the file explorer on desktop, or a dropdown list on mobile. The current project is highlighted with a background across the entire row, and the last item is **Add project**. The list and its order are saved to the signed-in account, with a recovery copy kept in the browser. The file explorer and selector share icons based on each project's `.mew/project-icon.json`.

The project sidebar stays open when you select a project or click elsewhere. It operates separately from the file explorer, and you can drag its right border to resize it. Clicking the close button or the project selector in the header closes it and restores the existing header display. Its open state and width are remembered per account in this browser. Use **▶** on each project row to open that project's [command list](commands.md). Clicking another project's command button does not change the project you are currently viewing.

- **Add project** in the list or `Ctrl/Cmd+Shift+O` opens the server folder browser in the center of the screen. When first opened, focus is on the title; click the address bar directly to type. Enter an absolute path or `~` in the address bar, or click subfolders to navigate, then use **Open current folder** to add that folder to the project list (owner and manager). Use the **New folder, Git clone, and Git init** buttons below the address bar to work at the current location. Enter names and repository URLs in forms within the same dialog, which also show the creation location. Filter the current list by folder name, check the selected path at the bottom, then open it. During creation, cloning, or initialization, duplicate execution, navigation, and closing are blocked; success updates the list and completion message. Errors preserve your input so you can retry. Cancel or Esc in a form returns to the list; Esc in the list closes the dialog. `Ctrl/Cmd+O` opens the server file explorer while keeping the current project.
- Add project and the server file explorer use a shared `FileBrowser` extracted from the Add project dialog. They share the header, address bar, home/parent navigation, name filter, list rows, bottom path, and error retry UI, with folder/file rows at 36px and action buttons and favorites at least 32px tall. Padding around the header, address bar, filter, and bottom selected path stays compact, and favorites at the top appear as a collapsed dropdown to leave room for the folder list. Expanded items are at least 44px tall and scroll within the screen boundaries up to a maximum height of 280px. Long folder names and selected paths are truncated to one line, and the list scrolls separately.
- Selecting a project in the list changes the signed-in account's active project and notifies other connected screens for the same account of the switch. Other accounts' working projects and collaboration rooms are retained. Running agents continue working in the project where they started. The browser loads the new project without refreshing and restores document tabs, layout, and scroll positions per project.
- `Alt+P` opens the project sidebar or mobile list and focuses the first item (owner and manager). It also works in input fields and moves focus to the first item if already open. If the work panel is maximized, it exits maximized mode and opens the sidebar. You can also open it with arrow keys while the selector has focus. Navigate with Up/Down and Home/End, then select with Enter/Space. The desktop panel does not close with Esc or Back; the mobile list closes on selection, Esc, Back, or an outside press and returns focus to the invoking button. It does not open during modal input, IME composition, or key repeat, and the shortcut is sent to the remote computer when the remote screen has focus.
- `Alt+1…9` switches projects in list order (owner and manager). The numeric keypad also works. `Ctrl/Cmd+숫자` selects tabs within the current panel. Modal input, key repeat, and nonexistent numbers do not switch projects; when the remote screen has focus, the shortcut is sent to the remote computer.
- Right-click the current project button or a project in the list, or use `Shift+F10`, to open the **Edit/Delete** menu (owner and manager). On mobile, press and hold the current project button. **Edit** opens the icon picker, and **Delete** removes the project only from the account's list, preserving folders and files. Icons are saved in the project's `.mew/project-icon.json` and shared by all accounts, the file explorer, and the selector. SVG, emoji, and line icon selections are supported; resetting displays the default folder icon.
- Drag the left handle in the list up or down to reorder projects. You can also reorder with **↑/↓** on the handle or **Shift+↑/↓** on the row, without selecting the project or closing the panel. The **Alt+1…9** numbers on the right follow the updated order. No project tab strip or grouping UI is provided. Clicking the arrow beside a subproject in the file explorer switches to that folder (owner and manager). Already registered paths are reused, and the parent project remains in the list.
- Adding and switching projects is available to owner and manager. For member and guest, only the current project's plain name is shown instead of its absolute path.

Workspace screen state (document tabs, pane layout, scroll positions, expanded tree nodes, and auxiliary panels) is retained in a server ledger per signed-in account and restored on other devices and in private windows. Existing `localStorage` values are used as a migration source only when the account ledger is initially empty, and the internal API identifiers `.workspace` and `docs` for the root project and Documents are retained for compatibility. Values closely tied to the device, such as screen width, theme, language, font, and drafts in progress, remain in the browser.

When returning to a recent project, document tabs, layout, and the initial folder listing retained in this login session are restored first. The screen state cache lasts 60 seconds, and hovering over or focusing a list item preloads only that project's screen state. The same request is reused on actual selection; screen state that could not be preloaded and the agent tab list are fetched concurrently with the server project switch. The icon list is also cached briefly to reduce round trips. Folder and file content is read fresh after the server confirms the switch, without clearing cached screens while waiting. Refreshing or using another device reads the server ledger again. During switching and subsequent restoration queries, only a loading indicator is shown in the center of the screen; it does not dim the screen or block clicks, touch, or keyboard interaction. It closes automatically when all restoration requests complete or fail, and a failed switch leaves you in the current project. This follows the [fast switching development contract](../../.mew/docs/development/ui-contracts.md#fast-root-project-switching).

The same full-screen loading display also appears when reopening the app or refreshing the session after returning from another app or browser tab. The existing screen remains interactive, and the indicator disappears when all ongoing restoration queries, including account, project, list, and file permissions, finish. This indicator does not appear for routine file change notifications or autosaves.

Document, terminal, agent, browser, and sheet tab strips do not show horizontal scrollbars when items exceed the available width. Horizontal navigation by touch, trackpad, and Shift+wheel remains available.

Clicking a file tab once in the editor updates that file's location in the file explorer's file view. On desktop, it also opens the file explorer if closed. On mobile, selecting a different file tab keeps the editor visible, and only pressing the currently viewed tab again switches to the file explorer. It switches to the corresponding document/file view, expands parent folders, loads the file list, and scrolls to the row when the file explorer is visible. Files opened outside the project are excluded.

Expanding a folder or parent document in the file explorer extends a vertical line along the left side of its child list. One line appears for each expanded ancestor, so a file three levels deep shows three lines. Collapsing a folder or document also removes its line.

As you scroll the list, expanded folders and parent documents stack at the top by level to show the current location. Each item is pushed out after the end of its child list passes. Pinned rows have no gaps between them, and the hierarchy lines on the left remain continuous. Existing open and collapse actions also work on pinned items.

### Create a missing project path

Navigating to a nonexistent path in the Add project dialog opens a confirmation dialog: **“{first missing path component} does not exist in {existing path}. Create the path?”** For example, if `/work` exists but `/work/new/project` does not, it reports that `new` does not exist in `/work` and also shows the full path to create, `/work/new/project`. Clicking **Create path** creates the intermediate folders too and navigates to that location. Adding the project is a separate action using **Open this project**. Cancel, Esc, or Back closes only the confirmation dialog and preserves the entered path. The confirmation text, creation button, and full-path guidance are displayed in Korean, English, Chinese, and Japanese.

Insufficient permissions, file paths, and broken symbolic links are shown as existing navigation errors instead of a creation confirmation. If creation fails, the address is retained so you can retry. Path creation is owner-only, like the existing New folder action.

### File explorer favorites

Both Add project and the server file explorer show a favorites dropdown **directly below the title and above the address bar**. Click the button to expand it, then click an item to navigate to that folder. Use **Add current folder** to save the path you are viewing, and remove it using × on the dropdown item or the current folder's star button. Use Tab, arrow keys, and Home/End to navigate the list's navigation and removal buttons, and Enter/Space to activate them. Esc, Back, or an outside press closes only the dropdown. Right-clicking a folder in the list (press and hold on mobile) and selecting **Add to favorites** also updates the top list immediately. Files do not have this option. This does not delete folders. Additions and removals are saved on the server per signed-in account and carry over across projects and browsers. Removed default items do not reappear when reopening or refreshing. To add one again, open its path in the address bar and click **Add current folder**.

- macOS: Provides the server user's home, Desktop, Downloads, Documents, Pictures, Music, Movies, and iCloud Drive by default.
- WSL: Provides the WSL home, the `/mnt/c` C drive, and Desktop, Downloads, and Documents from accessible Windows user profiles. Also checks Desktop, Downloads, and Documents relocated into OneDrive, distinguishing them by profile or sync folder name.
- Common: Adds the default folders in the home directory and detected OneDrive, Google Drive, and Dropbox folders. Only folders that exist and can be read and browsed are added automatically; aliases pointing to the same real path are merged into one.
- Refresh reloads the automatic detection results and the account's saved values. If saving fails, the existing list is retained and an error is displayed. Saved custom folders can still be removed from favorites even if they later disappear.

### Cloud folder shortcuts

Cloud folder shortcuts were integrated into **Favorites** at the top of both explorers instead of a separate area. Clicking a shortcut navigates to its path without changing the project list. In the Add Project dialog, browse to the desired subfolder, then open it with **Open This Project**.

- Detection targets the **OS filesystem of the mew server process**, rather than the device running the browser. It does not use account login, OAuth, cloud APIs, or a separate sync feature.
- On macOS, checks OneDrive, GoogleDrive, and Dropbox folders in `~/Library/CloudStorage`, `~/Library/Mobile Documents/com~apple~CloudDocs`, and folders with known service names in `/Volumes`. For CloudStorage paths, see the [Google guidance](https://support.google.com/drive/answer/12178485?hl=en-GB) and [Microsoft guidance](https://support.microsoft.com/en-us/onedrive/missing-files-and-autosave-issues-with-onedrive-on-macos).
- On all platforms, checks folders named after services directly under the server user's home and absolute paths in the `OneDrive`, `OneDriveConsumer`, and `OneDriveCommercial` environment variables. On WSL, also checks sync folders directly under `/mnt/c/Users/*`. Displays multiple folders for different accounts and organizations, showing paths alongside duplicate names. If symbolic links point to the same real path, only one entry is displayed.
- Checks known locations shallowly without recursively searching the entire server. Only directories that exist and can be read and browsed are provided. Name-based detection does not guarantee login or sync status; the OS sync app handles downloading online-only files. Open folders that were not detected because they use custom paths or other drives directly through the existing address bar.
- Cloud detection is managed in `server/cloud-storage.ts`, default favorites composition in `server/file-favorites.ts`, and the shared UI in `src/components/file-browser-favorites.tsx`. The existing owner-only `GET /api/fs/cloud-storage` is retained for compatibility; the new UI uses `/api/fs/favorites` with server file browsing permissions. Detection itself does not write files, settings, or tab lists.

## Projects, subprojects, and Documents in the file explorer

The file explorer has a search field at the top, with no separate search tab. Switch directly using the existing two-button **Documents / Files** toggle below it (English: **Documents / Files**). Documents view shows only the linked Documents folder; Files view shows regular files and folders, subprojects, and the documents folder. The selected view and each list's expansion and scroll state are remembered per account and project. Guests retain their existing document scope. The toggle also supports switching with the Left/Right arrow keys and Home/End.

With the content search icon in the search field off, search matches filenames; with it on, search matches body text. Results retain only matching items and their parent paths in the current view's tree, expand ancestors, and highlight names. Hovering over a content result shows a tooltip with the matching line, up to 3 lines above and below, and about 10 words on either side. Clearing the query restores the previous navigation position. For `Ctrl+P`, `Ctrl+Shift+F`, patterns, and replacement, follow the [search guide](../configuration/search.md).

In Files view, the documents folder appears with its linked folder name (such as `docs`) and a regular folder icon. Clicking the name expands the actual folder and shows its files with extensions; the diagonal arrow beside it switches to Documents view. It follows the same sorting as other folders, and if its actual path is `.mew/docs`, it is browsed under `.mew`.

The **Graph View** button at the Docs root appears above **Document Home**. View internal document links as a graph, zoom with the mouse wheel, two-finger gestures, or zoom buttons, and pan by dragging an empty area. Selecting a node highlights its connections; double-click it or use **Open Document** to open that document. Documents can also be found and opened through search and the list. The graph button is not repeated in subfolders, and only readable Markdown documents within Docs are linked.

Documents is a navigation area that collects documents, not a separate editor. Documents files and regular files remain together in the same editor tab list, preserving their editor pane and dock position when switching.

The document list is structured so parent documents contain child documents. Clicking the `development` name opens `development/_development.md`; the arrow on the left only expands the child list. The representative file is not duplicated among the children. Existing `development/MOC.md` files open the same way and remain compatible without modification. A representative document serves as the area's home, with a title and introductory guidance written in natural language. Actual file and folder names may also use natural language, spaces, uppercase letters, and Korean characters. Renaming also updates existing links. A regular click changes the document in the current tab; Ctrl/Cmd+click opens it in a separate tab. Unsaved body text is preserved.

Use **+** to the right of each document to create a child. When the first child is added to `dev.md`, its body moves to `dev/_dev.md` and the child becomes `dev/child.md`. Deleting or moving away the last child returns it to `dev.md`. Renaming applies to both the folder and its representative file. Existing MOCs are not migrated in bulk; they switch to the new naming when children are created, renamed, or moved in that folder. For the detailed saving and link adjustment contract, see [Documents pages](../../.mew/docs/development/document-pages.md).

The bottom of the file list has 300px of scroll padding on both desktop and mobile so even the last item can be scrolled toward the top of the screen. This applies separately to Documents and Files views so the last item can be scrolled toward the top of the screen.

Creating a new file in Files view uses the filename and extension exactly as entered and does not append `.md` if the extension is omitted. `/api/new-document` creates regular files with empty content and applies initial document content and Documents MOC registration only to `.md` files. **New Document** in Documents view uses a separate page API that automatically appends `.md` and applies the parent-child structure.

Use the search field at the top of the file explorer to search filenames and content. Run root project commands ▶ with the per-project command buttons in the top bar; this does not switch the explorer's search screen. For search scope, wildcards, and replacement, follow [Search usage](../configuration/search.md#filename-and-content-search-and-replacement). Logged-in users see **New File** and **New Folder** in Files view and **New Document** in Documents view. Files view uses the selected folder or the selected file's parent folder. Documents view adds a child to the selected document. With no selection, items are created at the root of the current view. Requesting Reveal Location or Create New File from a file tab switches to the appropriate view for that file. Files and folders can also be created in the selected folder within a subproject. After entering a name, press Enter to create or Esc to cancel. Open Git from **Git** in the dock or with `Ctrl/Cmd+G`.

Subprojects appear in the same list, sorting order, and actual hierarchy as regular folders. Clicking a folder expands or collapses it, and files inside can be opened in the current project. Clicking the diagonal arrow beside it opens that folder as the active project and adds it to the header list. Already registered paths are reused. The top-level expandable row that wrapped Documents is not displayed.

- **Documents** — The docs folder selected by the current project. Selecting the Documents toggle shows its contents; when the owner right-clicks the Documents toggle, the existing settings dialog for changing folders, importing, and exporting opens. The internal identifier and API remain `docs`.
- On mobile, **press and hold a file or folder in the file explorer for at least 0.5 seconds, then release before 1 second** to open the same item menu as a desktop right-click. The folder menu's **Create Git Repository** runs `git init` in the selected folder itself (owner and manager). Holding until 1 second enters move mode, allowing the item to be dragged onto a destination folder. Moving before then is treated as scrolling ([Mobile controls](editor.md#mobile-and-fullscreen)). A folder containing an actual `.mew` directory is a **subproject** regardless of depth. Direct and nested subprojects expand and collapse at their actual locations, and deeper subprojects are browsed in the same tree. A project icon and a separate arrow for opening the project are displayed, and the same file creation, upload, and move rules apply as for other folders. Owners and managers also see hidden folders, but `.git`, `node_modules`, and `.data` are excluded under the existing blocking and performance rules. Subprojects can also be placed inside regular folders without automatically turning intermediate folders into projects.

In Documents view, `_폴더이름.md` and existing MOCs open as the folder's representative body and are hidden from the child list. The Docs root MOC is labeled **Document Home**. In regular Files view, `MOC.md` and `_MOC.md` continue to appear as a map icon + `Map Of Contents` on the first row when the folder is expanded.

Opening a project with the arrow is owner-only. The arrow is disabled for other roles, while permitted file and folder browsing remains available. Subproject expansion state and child-list caches are restored in the same way as regular folders, and descendants of collapsed ancestors are not queried. Select Documents with the Documents toggle. If switching fails, the current project remains active and an error is displayed. The active project is maintained per logged-in account, and switching notifications go only to connections using that account. Running agents remain connected to the previous project. [Project switching contract](../../.mew/docs/development/ui-contracts.md#fast-root-project-switching) · [Subproject browsing decision](../../.mew/docs/decisions/0004-subproject-folder-exploration.md).

### Designate a folder as a subproject

Right-click a writable folder (on mobile, press and hold, then release) and select **Make Subproject**. This creates an empty `.mew` directory in the selected folder and immediately updates the tree. Existing files and `.mew` settings are preserved; Git is not initialized and the root project is not switched.

- When `liiiiv` is open, `abc/def` also becomes a subproject at that location. If `abc` is also a project, it is a nested project within it; even if it is a regular folder, `def` can be designated as a subproject. Opening `abc` itself as the root shows `def` as a direct subproject.
- The creation menu is unavailable for the root, already designated projects, files, read-only folders, and locations inside `.mew` settings. The logged-in account needs file read/write permissions and edit permissions for the target folder and the `.mew` path.
- A **file or link** named `.mew` is not recognized as a marker. If a file or link with that name exists, its contents are preserved and an error is displayed. Creation through a symbolic link path is not allowed.
- A nested project's ▶ uses that folder's `.mew/cmd-button.json` and runs in that folder. Commands and sessions remain separate even if projects at other paths have the same name. ▶ is shown only to accounts with terminal permission.
- The `@` scope selector in search is used to narrow the scope to direct subprojects in Files view. Nested project content is searched within the existing scope that contains it.

Development contract: Send `{path}` (a path relative to the current tree) to `POST /api/subprojects?project=`. Creation is idempotent and updates the marker and the parent row's catalog. The command APIs (`/api/cmd-buttons`, `/api/cmd-buttons/run`) accept an optional `path` for the nested execution folder. Existing project identifiers for editing and collaboration do not change. See [ADR 0151](../../.mew/docs/history/decisions/0151-mew-nested-subprojects.md) for the rationale.

## File and folder management

Selected files, folders, documents, and subprojects in the file explorer are distinguished by their background, without a theme-colored border.

Project operations; renaming, deleting, and opening projects in the server file explorer; Git initialization in the file explorer; Git commit operations; and bulk replacement in search use the app's own input and confirmation components. Dialogs follow the app theme instead of using browser `prompt` and `confirm`, keep Tab focus within the dialog, and restore focus to the invoking control when closed. Destructive operations such as deletion initially focus the Cancel button.

Right-click a file or folder in the file explorer, or press and hold on mobile, to open its item menu. Logged-in users can create, rename, duplicate, copy, cut, paste, delete, and perform other operations. Only menu options available for the selected item and role are shown.

- `F2` renames, `Delete` deletes, `Insert` creates a new file, and `Shift+Insert` creates a new folder. Copy or cut with `Ctrl+C` or `Ctrl+X`, then paste in the destination folder with `Ctrl+V`.
- Include the extension when entering a new filename. Omitting it creates a file without an extension.
- Use Download in the file menu to download the original. Dragging files or folders onto another folder moves them; dragging files from your device into the file explorer uploads them ([Behavior by drop location](editor.md#dragging-and-dropping-file-explorer-items)).
- When recording Git history after moving files or cutting and pasting, the move completes normally even if the original path, which Git had not yet tracked, no longer exists. For previously tracked files and folders, both the deletion at the original path and the new path are recorded.
- Managers and owners can initialize the folder itself using **Create Git Repository** in the folder menu. Creating a new project at an arbitrary server path is done through the owner's [project selection dialog](#프로젝트-탭).
- The owner configures file permissions [for each account and guest](../configuration/accounts.md#my-account-and-account-management) in account management. The file explorer reflects permitted files and read-only status.

## Documents Folder Contract

For the Documents agent guidance and document initialization GUI and CLI, follow [Project document setup](project-setup.md). The path in each project's `.mew/agent-context.json` takes precedence over the existing `MEW_DOCS` and the default path.

Documents is a virtual folder in the file explorer, rather than a tab. The owner selects the actual folder within the current root project; the default is `docs`. If no setting exists and only the old `.mew/docs` exists, that location is used as is. If the folder does not exist, an empty Documents folder is created.

- The internal identifier `docs` is retained. Documents, trees, search, collaboration rooms, git, and storage keys share this name, so it does not change along with the UI layout.
- The actual top-level folder currently used by Documents is not displayed again in the root project tree.
- When the owner right-clicks Documents in the file explorer, `DocsSettingsModal` opens. Folder changes are allowed only within the current root project; importing clears and replaces the existing contents, and exporting copies them into `docs` under the destination.
- Folder selection uses `GET /api/fs/dirs` to read the server filesystem and is owner-only.

| Route | Role | Function |
| --- | --- | --- |
| `GET /api/fs/dirs?path=` | **owner** | List the folder's subfolders |
| `POST /api/docs/root` `{path}` | **owner** | Change the Documents folder within the current root project |
| `POST /api/docs/import` `{path}` | **owner** | Replace Documents entirely (cannot be undone) |
| `POST /api/docs/export` `{path}` | **owner** | Copy to `{path}/docs` |
| `POST /api/docs/pages/{create,rename,delete,move,copy}` | Login and file write permission | Create, convert, move, rename, delete, and copy parent and child documents |

## Server File Explorer

A project-independent popup opened from the header menu (`components/ServerFileExplorer.tsx`). The default path is the server user's home; use the address field or dropdown to open `~` or an absolute path. Folders are read one level at a time when expanded, so the entire home directory is not recursively scanned in advance. All files and folders readable by the mew server's OS user are included, including hidden items. It uses the same shared browsing UI as Add Project, and the name filter narrows the top-level list at the current path. Folder expansion and right-clicking child items remain available. Tab focus stays within the dialog and returns to the invoking button when closed. Both dialogs share favorites and cloud folders; the Add Project dialog provides New Folder, Git operations, and the Open Project confirmation button.

- Clicking a file opens it in a **preview tab** in the focused editor pane while keeping the current project unchanged. External tabs support autosave but do not use collaboration, comments, git history, or project rules, and are not retained in tab restoration after a refresh.
- The right-click menus in the Add Project dialog and server file explorer use the same shared component as the file explorer. They provide Rename, Copy, Cut, Paste, and Delete; folders also show **Add to Favorites**. Paste targets the right-clicked folder, or the containing folder if a file was right-clicked. Paste is disabled when no item has been copied or cut. On mobile, press and hold to open the same menu. After a successful cut-and-paste operation, the source and destination lists and paths of open external files are updated. Files can be downloaded. **On mobile, if the browser detects a cellular connection and the file exceeds 100MiB**, a data charge notice and confirmation to continue downloading appear before the actual download. Wi-Fi, desktop, and browsers that cannot identify the connection type download immediately.
- A folder's **Open as Project** adds that folder itself to the project list and opens it as the active project. This is owner-only and replaces the current screen with the new root under the active root switching contract.
- The browsing, read, and write APIs are available to **logged-in accounts allowed to use the server file explorer** (manager and owner by default). Workspace boundaries and blocking rules for `.git` and `node_modules` do not apply; access uses the same OS permissions as the shell. For the meaning of these permissions on public servers, see [security.md](../operations/security.md).

| Route | Role | Function |
| --- | --- | --- |
| `GET /api/fs/favorites` · `PUT /api/fs/favorites` `{path, favorite}` | Logged-in accounts allowed to browse server files | Retrieve, add, and remove default OS/cloud folders and per-account favorites |
| `GET /api/fs/entries?path=` | manager·owner | Files and immediate subfolders of an absolute-path folder |
| `GET/PUT /api/fs/file` | manager·owner | Read and save external text files (opening text is limited to 10 MB or less) |
| `POST /api/fs/rename` · `DELETE /api/fs/path` · `POST /api/fs/paste` | manager·owner | Rename, recursively delete, and copy/move |
| `GET /api/fs/raw` · `GET /api/fs/download` | manager·owner | External media streaming and file downloads |
| `POST /api/fs/directory` `{path}` | owner | Create missing intermediate folders along the confirmed full path (preserving existing folders) |
| `POST /api/fs/open-project` | owner | Open and activate the selected folder itself as a root project |
| `POST /api/fs/folder` · `POST /api/fs/git/init` · `POST /api/fs/git/clone` | owner | Create within the current folder, initialize Git, and clone repositories |

## Git operations panel

Open **Git** in the dock or use `Ctrl/Cmd+G`, then record changes in the following order.

1. Check whether the current project root is a Git repository. If it is not, right-click a folder and use **Create Git Repository**, or open an existing repository.
2. Click a filename in **Changes** to review its diff. Separately select the checkboxes for files to include in the commit.
3. Click the commit icon, enter a title and description, then click it again or press Enter in the title field. Complete [GitHub login](#github-login) when committing for the first time.
4. Check the new commit in **Commit History**. To send it to the remote repository, run **Push** separately.

### GitHub Login

Close the login popup with the X in the upper right. Copy and external approval beside the code, and Refresh, Cancel Login, and Disconnect at the bottom, appear as icon buttons with action names on hover. **Continue Login** opens the approval screen inside the popup, while the external approval icon opens GitHub in a new tab.

Git connections are **separate for each Mew login account**. Accounts start disconnected and do not inherit the server's existing `gh` or SSH authentication. Attempting a commit, AI auto commit, or Pull/Push without a connection opens the login window. After login completes, the original request runs once with the composed content and selected files preserved. Closing or canceling the window does not run the operation.

You can also connect through **GitHub Login** in the Git panel header. Start login → **Copy Code** → **Authorize on GitHub** to sign in on the official GitHub screen and enter the code. On Linux/WSL hosts, **Continue Login** can also use the panel's [virtual login screen](browser.md#login-screen). Check which GitHub account you are authorizing. Once complete, the connected account appears in the header.

- The connection persists after logging back into Mew, refreshing, or restarting the server. To switch accounts, **Disconnect** and log in again. Disconnecting applies only to your own Mew connection and does not sign you out of GitHub on the web or disconnect other users.
- A default Mew OAuth app is included, so connections require no separate server configuration. Only operators using their own app need to set `MEW_GITHUB_CLIENT_ID` in [Environment Configuration](../configuration/environment.md#github-oauth-connection). Neither gh installation nor a client secret is required.
- Connecting an account requires Mew login and the Git or file write feature. Git operations themselves check existing feature and file access permissions. Only the internal approval screen requires the browser feature and Chromium.
- The commit author and committer are recorded using the connected account's name and GitHub private email address. The repository's shared Git author settings are not changed. Cherry-pick preserves the original author.
- File autosave, creation, copying, and similar operations remain available while disconnected. Incidental automatic commits are skipped in this state, and a connection is established when you explicitly commit.
- The initial provider is github.com. GitHub SSH remotes use HTTPS for transfers without changing the saved address. GitHub determines repository access permissions, organization SSO approval, and branch protection. Only an extensible provider contract is in place for GitLab and Enterprise; they are not yet supported.
- Approval codes can expire, and you must log in again if a token expires or authorization is revoked. Approval that was in progress before a server restart must be started again. Login alone does not run Push. Push resumes after successful login only if one was pending.
- This connection applies to commits and remote operations managed by Mew. Shell commands in terminals and regular agents, and cloning into external folders, use the existing OS environment.

API behavior, token storage, testing, and execution boundaries follow the [Per-Account Git Connection Contract](../../.mew/docs/development/git-connections.md); decision changes follow [ADR 0179](../../.mew/docs/history/decisions/0179-mew-account-git-connections.md).

## Ignore list (.data/ignore.json)

A list of **names** to skip entirely in file listings, search, and tree watching. These are names, not paths, so folders and files with those names disappear at any depth (`dist` → every `dist/` in every project). Edit it in Settings → **Hidden List** (owner/manager). If the file is absent, `DEFAULT_IGNORE` from `server/ignoreList.ts` is used.

```json
{ "names": ["dist", ".next", "node_modules", ".git", ".data"] }
```

- There is **one global list** — it does not vary by project. That is why the server stores it in `.data/`.
- `.git`, `node_modules`, and `.data` are blocked separately at the API layer by `DENY_SEGMENTS` in `paths.ts`. They remain hidden even if removed from the list, so the server adds them back on save and the UI marks them as **Fixed** — making them look removable would lead to “I removed it, so why is it still there?”
- On save, the server shuts down all watchers (`resetTreeWatchers`) and sends a `tree` signal. Active watchers retain tree signatures generated under the old rules and would dismiss the new rules as “no change.” Shutting them down causes them to be registered again under the new rules when clients fetch the new tree (`GET /api/tree`).
- `build/` is **not** hidden by default. The tree exposes only APK/AAB files inside it and suppresses other contents and empty folders (`DOWNLOAD_ONLY_DIRS` in `tree.ts`), while watching does not descend into `build` regardless of the hidden list.
- **Neither this list nor the extension filter applies to owner and manager trees** — they show everything as it exists. The list remains active for trees shown to members and lower roles, and for **search and tree watching** regardless of role.
- The file explorer uses `GET /api/tree?path=<폴더>` to read **only the folder's direct children**. When switching projects, it first renders the expanded state and child snapshots restored from the account, then refreshes only the direct children of open paths. Paths beneath collapsed ancestors and closed top-level folders are read when expanded, and received listings and in-flight requests are reused. File explorer scroll positions, including Documents and project entry points, are saved to the account as the center item's tree identifier, path, and relative position within the item, restoring the same item to the center even during lazy loading. User interaction ends the initial adjustment ([ADR 0125](../../.mew/docs/history/decisions/0125-mew-sidebar-center-anchor-and-visible-loading.md)). API calls without `path` retain the full recursive tree for compatibility with existing server tools. The policy's canonical source is [security.md](../operations/security.md). Display filtering is handled by `isPathVisible` in `server/tree.ts` and `seesEveryFile` in `server/reqAuth.ts`, while actual access is determined by `server/access-policy.ts`. When partial file restrictions apply, the tree is filtered to find allowed subpaths.
- Server: `server/ignoreList.ts` + `GET/PUT /api/ignore` (owner/manager). Client: `IgnorePanel` in `src/components/SettingsModal.tsx`.
