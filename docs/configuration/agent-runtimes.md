## Installation, Login, and Subscriptions

On native Windows, `.exe` and `.cmd` are located through PATH and PATHEXT, and the pinned ACP adapters' npm CMD shims and child processes are invoked through the Windows execution layer. A PowerShell wrapper records the login completion code. Automatic installation buttons are not provided for Cursor and Prime, which have only Unix installation scripts registered, or for Antigravity, which currently has no registered official Windows distribution. For providers configured with a separate Windows executable, check the provider's contract for actual ACP and authentication support. Shared mew support and provider-specific compatibility and public release gates follow the [native Windows contract](../../.mew/docs/development/windows-native.md).

- **Installation and login are separate**. ACP runtimes use provider ACP authentication or registered browser (standalone login video screen)/terminal tasks. Antigravity uses the authentication methods and Google login URL of Google's official ACP server. Claude distinguishes account login from Console login in the official CLI. Manual authorization codes are passed temporarily to the relevant CLI; OAuth tokens are not entered or stored separately ([ADR 0142](../../.mew/docs/history/decisions/0142-mew-claude-acp-and-cli-authentication.md)). Screen wording and layout follow the [display criteria](../../.mew/docs/features/terminals-agents-automation/agent-conversations-queue-and-restoration.md#login-screen).
- **Login is separate from subscriptions and limits** ([ADR 0130](../../.mew/docs/history/decisions/0130-mew-agent-account-entitlement.md)). Query the server CLI account and plan from the **i (Session Info)** popup in Claude, Kimi, Codex, and Cursor ACP chats and from `연결 계정 · 구독` in supported runtime settings. Explicit subscription-required, usage-exhausted, or insufficient-credit errors do not switch to the login screen even when ACP wraps them as `Authentication required`. Preserve the existing conversation and queued messages, and stop automatic consecutive sending. Editing queued messages, reconnecting, and refreshing account information do not resend messages; when the user sends a new message, resume in queue order. Account
  queries use `/api/v1/oauth/userinfo`, `usage`, and `region` in Kimi's temporary `web --host 127.0.0.1 --port 0 --no-open --log-level error` process; `account/read` and `account/rateLimits/read` through Codex's host CLI `app-server`; Cursor's `status --format json`; and Claude's `auth status --json` through the same CLI engine. The executable and environment follow runtime settings, while status command arguments are fixed. Temporary processes have a 20-second timeout, a 256 KiB stdout limit, and a wait period before forced termination after shutdown; the Kimi server connection token is used only temporarily from that child's startup output. Do not read provider authentication stores directly or send model prompts. Display only verified account and plan fields. A free plan does not mean the service is unusable, and unverified plan codes such as `VIP10` must not be treated as proof of
  no subscription. If CLI version or network issues prevent a query, or the query capability is unavailable, provide `확인할 수 없음` and a way to retry. Cursor may return account information without a plan. Distinguish API-key-based Codex from a ChatGPT subscription. View the remaining subscription percentage for Codex, Claude, and Kimi Code in the battery indicator
  on the session toolbar. Project Codex's `usedPercent`, `windowDurationMins`, and `resetsAt`, and `used`, `limit`, `window`, and `resetAt` from the Kimi CLI's normalized `summary` and `limits`, into the public `quota` array (`remainingPercent`, `windowMinutes`, `resetsAt`, and optional `name` and `secondaryBucket`). The full limits popup also includes additional Codex metered buckets and Claude per-model weekly limits; exclude `secondaryBucket` when selecting the summary battery indicator. For OAuth connections, Claude requests only `initialize` → `get_usage` through the same CLI's stream-json SDK control protocol and reads utilization (0–100) and reset times from `rate_limits.five_hour` and `seven_day`. Use `--no-session-persistence`, empty configuration sources, disabled hooks, an empty strict MCP configuration, and empty tools to avoid model prompts, existing sessions, and execution of user hooks/MCP. CLIs that do not support the experimental `get_usage` and failed queries do not provide remaining percentages. Apply the existing 20-second and 256 KiB limits to each temporary process. Since account status and usage are queried through sequential processes, a full Claude query takes up to approximately 40 seconds. Do not query subscriptions for actual API key connections. The browser retains only remaining quota in memory per account and runtime for up to 5 minutes and coalesces concurrent/repeated queries. View session tokens and API-equivalent costs in the existing i popup. The `구독 관리` and `구독하기` buttons open fixed provider-specific URLs in a separate login video screen for the same account (respecting the Kimi region). Closing the page cleans up that window and popup and refreshes only the status. The user checks that the account on the subscription page matches the displayed CLI account; payments and prompt resending are not performed automatically. Account results are displayed only in memory and are not saved to transcripts or localStorage. Antigravity account, plan, and remaining-quota queries and terminal body content are outside the scope of this information card. Antigravity login and chat are supported through ACP.

## Model and permission defaults and runtime selection

- Codex and Antigravity select the **model** and **reasoning effort** separately. The same approach applies to editing queued messages and agent sets. Antigravity recognizes only `(Minimal)`, `(Low)`, `(Medium)`, `(High)`, and `(XHigh)` at the end of server-provided names as effort levels, preserving model qualifiers such as `(preview)`. Only effort levels supported by the selected model are displayed. When switching models, selection follows this order: current effort → `medium` → first supported entry in the server list. Models without effort distinctions do not allow separate effort selection.
- Antigravity effort changes are sent using the original model ID advertised by the server, rather than a separate provider settings request. Model ID suffixes are not guessed, and new IDs are not constructed. Defaults and agent sets preserve the original ID to execute, and queued message effort is also mapped to the corresponding model ID before execution.

- When only a model name is stored without a reasoning effort, as in older Codex agent sets, model selection requests map it to the same model's `모델명[추론 강도]` ID advertised by ACP. An exact ID match takes priority. If conversion is needed, selection follows this order: current session reasoning effort → `medium` → first supported entry for the same model. Explicit reasoning effort and IDs from other runtimes are not changed. If the same model is unavailable, the connector error is displayed without substituting a different model. Saved set files are not modified.

- **The save icon next to the model and permission selectors saves the current values as defaults for that runtime** ([ADR 0063](../../.mew/docs/history/decisions/0063-mew-agent-runtime-saved-defaults.md)). Values are saved per runtime in the logged-in account's `DATA_DIR/agent-accounts/<정규화 계정 ID SHA-256>/agent-defaults.json` and apply to `session/new` and `session/load` in new tabs for the same account and after server restarts. The icon is highlighted when the current selection matches the saved values. When no value is saved, **the permission mode defaults to that runtime's "Allow all"** ([ADR 0037](../../.mew/docs/history/decisions/0037-mew-agent-bypass-permissions-default.md)). ACP sessions start in a restricted mode (claude `default`, codex `auto`), so the server reapplies the mode after each `session/new` and `session/load` (`#applyDefaults`). Because names differ by runtime, selection uses the candidate order (`FULL_ACCESS_MODES`) rather than one hardcoded value — claude `bypassPermissions` · codex `agent-full-access` · hermes `dont_ask`. Claude's `dontAsk` has the opposite meaning (reject anything not preapproved), so the order distinguishes them. The header selector can change the mode for each turn. Setting a mode ID in `MEW_AGENT_MODE` makes it an operator-enforced value that takes precedence over saved permissions. The mode list is used exactly as advertised by the backend — if a mode is not advertised (for example, when running as root), it is silently skipped.

- **A new tab does not start a session until a runtime or agent set is selected** ([ADR 0096](../../.mew/docs/history/decisions/0096-mew-agent-tabs-created-after-selection.md)). Closing the last tab leaves only the centered `새 탭` button; both `+` and this button only open the selector. Uninstalled runtimes are installed only with fixed installation commands from the server registry, and successful installation selects that runtime without a refresh. The WS connection, history, and input field appear only after selection. The runtime is stored per tab in `mew:agent-tabs`, and older tabs are migrated once using the last `mew:agent-runtime` value.

- **The header icon in the session window is a runtime dropdown** ([ADR 0074](../../.mew/docs/history/decisions/0074-mew-agent-header-runtime-switch.md) — lifts 0062's prohibition on switching within a tab). Clicking it expands the same registry used by the new-tab list (icons, installation status, and Use/Install), and selecting another agent **switches that tab's session** — it does not create a new tab. Because the WS connection effect depends on `runtime`, it reconnects and attaches a new session, while the old session remains under server supervision. Installation within the dropdown uses the same fixed command path.

- The `RUNTIMES` registry in `server/agentRuntimes.ts` determines execution surfaces and commands. The client duplicates this list only for **icons**; the server makes the decisions:

  | Runtime | Agent tab surface/command | Authentication | Environment variables |
  | --- | --- | --- | --- |
  | `claude` | Fixed `claude-agent-acp` → official Claude CLI engine | Independent login video screen · official CLI `auth login --claudeai` / `--console`, with authorization code entry when required | ACP: `MEW_AGENT_CMD` · `MEW_AGENT_CLAUDE_CMD` and corresponding `ARGS`; engine: `MEW_AGENT_CLAUDE_CLI_CMD` · `CLAUDE_CODE_EXECUTABLE`; authentication environment: `MEW_AGENT_CONFIG_DIR`/`CLAUDE_CONFIG_DIR` |
  | `antigravity` | Google's official `agy_acp_server.par` 1.1.1 | Official ACP's Google OAuth · Enterprise · API key · Agent Platform | `MEW_AGENT_ANTIGRAVITY_ACP_CMD` · `MEW_AGENT_ANTIGRAVITY_ACP_ARGS` · `GEMINI_HOME` · `GEMINI_API_KEY` |

  The shared setting is `MEW_AGENT_MODE` (if omitted, the full-access candidate order in this document applies). If the entry point is missing or does not speak ACP before login, both the error and terminal auth are shown — the runtime is not hidden from the list, and the tab is not closed. If it still fails after login completes, the latest startup error remains on the same screen. Prime Agent has one session per connection, so one mew tab corresponds to one Prime session (a second tab starts another process).

| Route | Role | Function |
| --- | --- | --- |
| `GET /api/agent-runtimes` | manager·owner | Whether registered runtime executables exist, whether installation, safe removal, and logout are available, and the progress and output of the latest installation |
| `GET /api/agent-runtimes/:id/models` | agent permission | ACP model candidates for agent sets `{models: [{modelId, name}]}`. Unsupported runtimes return 400; lookup failures return 502 |
| `POST /api/agent-runtimes/:id/terminal/:tab` | manager·owner | Creates a dedicated per-tab tmux for a terminal runtime in a validated cwd and runs the official CLI from the registry |
| `DELETE /api/agent-runtimes/:id/terminal/:tab` | manager·owner | Terminates the dedicated tmux and CLI owned by the tab |
| `POST /api/agent-runtimes/:id/install` | manager·owner | Runs the registry's fixed installation command for the ID. Does not accept arbitrary commands or arguments |
| `DELETE /api/agent-runtimes/:id/install` | manager·owner | Runs the fixed uninstall command declared by the registry. Rejects the request if no safe removal contract exists |
| `POST /api/agent-runtimes/:id/logout` | manager·owner | Runs only the noninteractive CLI logout declared by the registry. Does not read or transmit credential values |
| `POST /api/agent-runtimes/:id/auth/:method/run` | manager·owner | Runs the fixed terminal auth command advertised by ACP or specified in the registry in a hidden tmux session. The body contains only `{tab}` |
| `GET /api/agent-runtimes/:id/account` | manager·owner | Temporarily returns the account display name, plan, subscription/limit status, and fixed subscription URL using the official CLI's status feature. `Cache-Control: no-store`, coalesces only concurrent queries; includes the normalized `quota` array for supported runtimes |
| `GET /api/agent-runtimes/:id/auth/:method/status?tab=<id>` | manager·owner | Authentication task status and exit code, allowlisted URL and one-time code for the browser surface, and filtered failure reason. Output and secrets are not recorded |
| `GET /api/agent-defaults/:id` | manager·owner | Model and permission defaults saved per runtime |
| `PUT /api/agent-defaults/:id` | manager·owner | Atomically saves the current model and permissions as defaults for that runtime |
| `GET /api/agent-runtimes/:id/settings` | manager·owner | Runtime settings (executable, additional arguments, env). **Returns env values with only the last 4 characters masked** |
| `PUT /api/agent-runtimes/:id/settings` | manager·owner | Saves by merging — replaces only submitted keys and retains existing values for omitted env keys (because the browser does not know the original secrets) |
| `DELETE /api/agent-runtimes/:id/settings` | manager·owner | Clears user settings for that runtime and restores the registry defaults |

- Each row in the runtime selector and the runtime settings dialog displays actual standard output and standard error during installation at approximately 1-second intervals. If no output is available yet, the installation-in-progress status is shown first. Logs have a maximum height and scroll to follow new output, while preserving the position when users read earlier output. The selector continues to open the agent automatically after successful installation.
- The optional `installation` in `GET /api/agent-runtimes` is `{state: "running" | "succeeded" | "failed", output}`. The server retains the last 12,000 characters of the latest installation output per runtime in memory; retries clear it, and server restarts discard it. Reopening the screen resumes polling for an ongoing installation and stops polling after completion or failure. Only existing runtime API permissions and the registry's fixed installation commands are used.
- The runtime settings dialog is rendered in `document.body` using the shared `DialogFrame` so runtime lists and panel layers do not obscure it. Interactions within the settings dialog and removal/logout confirmation dialogs do not close the runtime dropdown behind them. Esc, Back, and focus trapping/restoration follow the shared modal contract.
- Model, reasoning, and permission defaults saved in Mew (`agent-defaults.json`) and executables, arguments, and provider environment variables (`agent-settings.json`) are stored in `DATA_DIR/agent-accounts/<정규화 계정 ID SHA-256>/` per logged-in account. They are used across all projects for the same account and are unaffected by saves or deletions by other accounts. Existing shared settings are copied once to the earliest-created owner account, preserving the originals. Other accounts start with defaults. Provider CLI login files and installations remain scoped to the OS user, so this change alone does not isolate provider authentication per account. Follow the [storage and execution contract](../../.mew/docs/development/agent-sessions.md#passing-project-context).
- **Runtime settings popup** (gear icon in the list) — saves installation, removal, login, logout, executable paths, extra arguments, and provider env per runtime. For ACP runtimes, `resolvedSpec` applies them to the next tab startup and installation checks; for terminal runtimes, `resolvedTerminalSpec` does so. Claude's executable setting remains the official CLI engine path, while the ACP adapter itself is specified through environment variables. Extra arguments from the previous TUI (`extraArgs`, `MEW_AGENT_CLAUDE_CLI_ARGS`) are preserved but not passed to ACP. Models and permissions are selected in chat settings. Conversations, scheduled runs, login, status queries, and logout use the same CLI engine and provider environment. Secrets remain only on the server; the screen sees only `****끝4자`. After confirmation, removal and logout run only fixed commands from the registry, and Antigravity, which has no safe uninstall contract, does not delete arbitrary files.
- ACP runtime model candidates and execution IDs use the values advertised by ACP. Only the Codex panel display groups them by base model, with effort adjusted through a separate reasoning selector ([display contract](../../.mew/docs/features/terminals-agents-automation/agent-conversations-queue-and-restoration.md#model-and-effort-selection)). After `session/set_model` succeeds, the advertised composite ID list updates the reasoning selection and supported options; `session/set_config_option` responses and `config_option_update.configOptions` are also reflected in model and reasoning state. Defaults retain both the actual composite model ID and a separate reasoning value. The agent set candidate API preserves the existing exact IDs. Both Claude and Antigravity use the shared ACP model, permission, and history screens. The actual lists and scope of session restoration depend on each server's capabilities.
- When editing agent sets, the model candidate API reuses `probeModels`'s per-runtime memory cache and concurrent request coalescing. If no cache exists, it opens a temporary ACP session for model discovery and terminates it as soon as the list is received. It creates no user tabs, WS connections, or prompts. Responses use `no-store`, and queries follow the 20-second limit. On failures such as incomplete installation or login, retry in the form or enter a model ID directly. The UI discards responses received after switching runtimes or closing the form.

## Antigravity official ACP

Under [ADR 0143](../../.mew/docs/history/decisions/0143-mew-antigravity-official-acp.md), Google's official ACP server is used instead of the regular `agy` TUI.

- **Installation**: Logs show downloaded MiB, the percentage when the total size is available, and the file inspection, extraction, and executable verification stages. The installation button in the list downloads the version-pinned 1.1.1 ZIP from `dl.google.com` and places it in `<DATA_DIR>/runtimes/antigravity-acp/1.1.1-<platform>-<arch>/`. It uses Node's built-in download functionality and the system `unzip`. Linux x64/arm64 and macOS arm64 are supported; no official Intel Mac distribution is currently available. On Linux x64, the download is approximately 650 MiB compressed and 1.9 GiB extracted, requiring approximately 2.6 GiB of free space during installation. If downloading or extraction fails, temporary files are cleaned up and the existing installation is not overwritten. No redistributed binaries or npm dependencies are added.
- **Google account**: Select `Log in with Google` in a new tab → open the login page → authorize Google in the independent login video screen → complete authentication through the official server's loopback callback. Free, Pro, and Ultra access depends on the Google account. URLs are retained only in memory during authentication. On cancellation or timeout, the ACP process's login listener is terminated, and retries use a new connection. Failures return to the authentication screen.
- **API key**: Save `GEMINI_API_KEY` in the runtime settings environment variables → new tab → `Gemini API key`. The official 1.1.1 server ignores keys received through authenticate `_meta`, so no separate key entry form is provided.
- **Enterprise / Agent Platform**: Authentication methods are provided exactly as advertised by the official server. Enterprise project/location uses the `gcp` settings in `<GEMINI_HOME>/antigravity-acp/settings.json`. Agent Platform uses `GOOGLE_API_KEY` or `GOOGLE_CLOUD_PROJECT` and `GOOGLE_CLOUD_LOCATION`, along with ADC. This configuration has not been verified with an actual enterprise account.
- **Settings and previous values**: The old `MEW_AGENT_ANTIGRAVITY_CMD` and `ARGS` and saved `cmd` and `extraArgs` are for the TUI and are not passed to ACP. Specify the ACP executable and arguments through the server's `MEW_AGENT_ANTIGRAVITY_ACP_CMD` and `ARGS`. Saved provider environment variables are preserved. Set `GEMINI_HOME` if a separate path is needed (default `~/.gemini`).
- **Account and history**: The official ACP server manages authentication and conversations under `~/.gemini/antigravity-acp/`. This is separate from the regular CLI's `antigravity-cli/`, so log in again if necessary. Existing CLI conversations are not automatically migrated to ACP. No account email or remaining subscription quota information card is provided, and server commands such as the official `/logout` are handled by the server. Automatic logout and removal buttons are not yet available in Mew settings.
- **Verification scope**: The initialize and unauthenticated session/new responses of the official Linux x64 distribution have been checked. Installation success/failure, previous settings, split OAuth URL reception, reconnection, cancellation, and retries after failure are checked in isolated tests. Actual Google login, paid prompts, Enterprise, and macOS execution are not automatically verified.

Official references: [Google Zed integration and authentication](https://antigravity.google/docs/ide/extensions/zed/), [ACP Registry](https://github.com/agentclientprotocol/registry/blob/main/antigravity-acp/agent.json). Official binaries are governed by Google's terms and are not relicensed under Mew's source license.

### Prime installation detection and updates

- Installation status is determined by `MEW_PRIME_AGENT_EXECUTABLE` or the `prime-agent` executable on PATH, rather than the built-in Node adapter.
- Latest-version checks use the distribution repository channel from the official installation script instead of the public npm registry or GitHub releases. Updates run the official CLI's `update` command individually ([update contract](../deployment/native.md#unified-updates-for-installed-dependencies-and-agents)).
