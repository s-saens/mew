# Appearance, notifications, Dock, and keyboard shortcut settings

Customize your workspace in **Settings** in the header menu. For accounts and permissions, see [account settings](accounts.md); for host environment variables, see [server settings](environment.md).

On mobile, tap an item in the settings list to open its detail screen. Using browser/device **Back** or the detail screen's **Back** button returns to the settings list; going back again from the list closes settings. Open selection lists, color pickers, and custom theme editing areas close first. The same return sequence applies when opening Mewpet or debugger settings directly. The **Close** button and Esc close settings.

## Appearance settings

Themes are saved to the logged-in account on the same Mew instance. Changes made on another device also appear on open screens, and the latest values are checked again when returning to the screen or reconnecting. If the account has no theme, the existing selection from the first browser to connect is imported; if no existing setting is available, it starts with **Midnight**.

Settings appear above all app work layers, including memo and task popups. Language and font selection lists within settings also operate above the settings dialog.

On desktop, click the icon on the right of each memo or task tab to switch between popup and panel views. Depending on the current view, the tooltip shows **Switch to popup** or **Switch to panel**, and the browser remembers the selection. This option is not available in appearance settings. Mobile uses panels and preserves the desktop selection.

Language and font lists use custom dropdowns that follow the app theme. Fonts can be selected from the recommended list or entered by name. Use the arrow keys and Enter to select from the list; Esc and Back close only the list.

Changing the language immediately updates agent history, loading, and refresh text, as well as wording in the editor, search, files, Git, scheduling, remote desktop, and shared confirmation dialogs. Open editors, terminals, and drafts in progress are preserved. Documents, conversations, filenames, and original output from external commands remain unchanged. Implementation and checks for missing translations follow the [UI translation contract](../../.mew/docs/development/ui-contracts.md#ui-translation).

In the header menu → **Settings → Appearance**, select a theme combining **background, text, and primary colors**. Each button shows `A` in the text color and `a` in the primary color on the theme background. Clicking the default Dark/Light or Midnight, Forest, Paper, Rose, and Ocean presets applies them immediately. Midnight, Rose, and Ocean use slowly moving gradient backgrounds that blend two colors smoothly. The selected theme and custom list are shared across devices for the same account.

Use the final **+** button to copy and customize the current theme. Background, gradient, text, and primary color buttons are grouped together; on narrow screens, the text and primary colors move together to the next line. Clicking a color button opens a color picker over the settings below without repositioning other items. Change colors by dragging in the color area (mouse or touch), using the hue, saturation, and brightness sliders, or entering a 6-digit HEX code. Reset restores that color to its value when editing began. Clicking the save (floppy disk) icon to the right of the title adds the preview combination to the grid and applies it to the screen. Identical combinations are not saved twice. Clicking a saved custom theme card applies that theme and immediately opens the editing area below the grid. In this state, the save icon replaces that entry, while the adjacent delete (trash) icon deletes it and returns to the default theme. The delete icon is not shown while adding a new theme. Both icons have tooltips and accessible names.

Enabling **Gradient** in custom editing lets you change the two gradient colors and direction. Set the direction by dragging a clock-like circle the same size as the color squares or entering a value in the adjacent numeric field. The top is 0° and the right is 90°, wrapping through 0–359°. With the circle focused, arrow keys adjust by 1° and Page Up/Down by 10°. Toggle movement with **Background animation**. The preview and theme buttons show the same background. Combinations are considered duplicates only when solid/gradient mode, both colors, direction, and animation all match. If the device's reduced-motion setting is enabled, background movement stops regardless of the saved animation setting. Disabling the gradient preserves the selected background color.

Esc and Back close the open color picker and then the custom editing area. Closing the editing area before saving discards the draft and preserves the existing theme. Use the save/delete icons to the right of the title instead of an X in the editing area and text buttons at the bottom. Guidance is displayed for drafts with low text contrast against the background color or at multiple points in the gradient.

The selected theme and custom list are saved in server-side account state, while the browser retains a per-account copy and `mew:themes` for the initial screen. Themes already saved on the server are not overwritten by stale browser copies. If saving fails, the current selection is retained and an error is reported; saving is retried on reconnection, return to the screen, or the next change. Existing `mew:theme` mode and `mew:theme-color` or `mew:accent-color` are migrated while preserving the actual displayed colors. If the selected theme exactly matches the three colors of the previous Midnight, Rose, or Ocean theme, it carries over to the new gradient preset. If the same solid-color combination was saved in the custom list, that selection is preserved. Panel, border, secondary text, link, and button hover colors are calculated automatically, and light/dark mode follows the brightness of the base background color. In gradient themes, bubble, regular button, and component backgrounds use a strong color blend with translucency so the overall background shows through.

In **Settings → Appearance → File icons**, choose **Material Icon Theme**, **Catppuccin**, or **Basic icons**. Each row previews file and folder icons, and selecting a row applies it immediately. Material remains the default for existing accounts. Basic icons uses outline file and folder icons. This choice is saved with your account theme and synchronized across devices; changing a color theme keeps your icon pack selection.

The selected pack shows its source and locally bundled license. Material Icon Theme 5.40.0 comes from npm with its [MIT license](../../public/licenses/material-icon-theme.txt) and [supplemental source notices](../../public/licenses/material-icon-theme-notices.txt). Catppuccin Icons 1.26.0 comes from its official GitHub release with its [MIT license](../../public/licenses/catppuccin-icons.txt). Catppuccin uses Latte artwork in light themes and Mocha in dark themes. All artwork is included with Mew; selecting a pack does not contact a catalog or execute a VS Code extension. The current list contains built-in packs; search and installation from URLs are not available. Custom project and Map Of Contents icons keep their existing behavior. See the [file icon contract](../../.mew/docs/features/projects-files-search/file-folder-exploration-and-operations.md#file-type-icons) for source verification and supported associations.

Popups, dropdowns, menus, dialogs, and floating windows in Light, Paper, Rose, Ocean, and light custom themes display their backgrounds at 75% opacity with 6px backdrop blur, regardless of whether a gradient is enabled. They blend 70% theme background color with 30% existing popup surface color to preserve a light tint. The dialog's black overlay appears only outside the rounded panel so it does not show through beneath the translucent panel. Outside clicks, Esc, Back, and window stacking order are preserved. Dark mode retains the 75% background and 6px blur for gradient popups and opaque backgrounds for solid-color themes. The file explorer's command button add/edit dialogs follow the same rules. Text and icons remain crisp, while internal input elements, pinned tree rows, and terminals retain solid backgrounds. Saved theme colors and gradient settings do not change, and deletion/warning colors retain their meaning in each mode. Detailed storage and color calculations follow the [theme contract](../../.mew/docs/development/ui-contracts.md#theme-colors-and-derived-accents).

`설정 > 화면`, opened from the header's account/settings menu, remembers the language and three font settings per browser. Themes are shared per account. Fonts appear in three rows, **UI, Documents, and Code**, with a selector and reset button on the same line to the right of each label. Selector starting positions align, and the same layout is preserved on narrow screens. Clicking a label focuses its input. Global UI text, Markdown Hotview body text, and Mono (code editor, terminal, inline/block code, and `font-mono` UI) are independent. If an entered font is neither loaded as a web font nor installed on the device, the system fallback for that category is used. Values are saved in `mew:fonts` in `localStorage`, and each item can be reset to its default.

The default UI and Markdown font is IBM Plex Sans KR, and Mono uses IBM Plex Mono. Both fonts are bundled with mew as regular (400) and bold (700) WOFF2 files and served from the same server, so they work without an internet connection or per-device font installation. `index.html` loads `/fonts/ibm-plex/fonts.css`, and `public/fonts/ibm-plex/` is included unchanged in the development server and Vite build output. Original files from IBM's official distributions `@ibm/plex-sans-kr` 1.1.0 and `@ibm/plex-mono` 2.5.0 are used. The [original SIL OFL text](../../public/fonts/ibm-plex/LICENSE.txt) and [sources, versions, and file hashes](../../public/fonts/ibm-plex/sources.json) are distributed together.

Noto Serif KR is loaded once from Google Fonts only when included in saved font settings or selected by the user. The initial HTML for the default screen does not request external font CSS. The production CSP allows only `https://fonts.googleapis.com` as an external stylesheet source and `https://fonts.gstatic.com` as an external font file source. The allowed scope for external scripts is not expanded. Where Google Fonts is unreachable, an installed Noto Serif KR font or a system fallback is used. Entering a font name directly does not automatically download arbitrary web fonts.

## Notification settings

Configure in-app notifications, desktop notifications, sounds, server resource monitoring, and test notifications in **Settings → Notifications**. These settings were moved from the Mewpet tab, and their values are preserved. If there are unread notifications, open the list using the bell icon to the left of the active sessions at the top to review them and go to the corresponding task screen. Even when Mewpet is off, header notifications, OS notifications, and sounds follow their respective settings.

**Open agent tab on approval request** is enabled by default. A new approval request switches to that agent's tab even while you are working on something else. Turn this option off to keep working on the current screen. Disabling automatic switching preserves the orange pending indicator and notifications, and you can navigate directly using Mewpet's **View approval request**. The setting is saved in the browser; if it is missing from existing saved settings, it is treated as enabled.

Activating a Mewpet skin displays **Also show notifications through Mewpet** in the Notifications tab. This option controls only the cat's automatic speech bubbles and notification behavior. It defaults to enabled for existing users, and other notification channels remain active even if Mewpet is turned off or this option is cleared. This follows the [notification feature contract](../../.mew/docs/features/appearance-accounts-operations/mewpet-mascot-notifications-and-breaks.md#notification-settings-and-pc-desktop-notifications).

## Dock settings

Choose **Desktop position** and **Mobile position** independently: **Top**, **Bottom**, **Left**, or **Right**. Changes apply immediately. Desktop defaults to **Left** at widths of 768px or more; mobile defaults to **Bottom** below 768px. The workspace reserves space at the selected edge. Left and right docks arrange icons vertically; top and bottom docks arrange them horizontally. The remote viewer retains its existing toolbar layout.

Use Header menu → **Settings → Dock** to change the visibility and order of currently available items. Changes appear immediately in the preview and the actual dock; Reset restores default positions, visibility, and ordering. Visibility and ordering are shared between the mobile and desktop docks. Open Remote Desktop from the header menu. Open localhost apps by appending `/포트번호` to the current Mew address.

Hiding an icon does not close open panels or task sessions. Hiding all items hides the dock; you can reopen settings from the header menu. Items unavailable due to permissions, login, or project conditions are excluded from both the settings list and the dock. Visibility settings are saved in `mew:mobile-dock-hidden` and ordering in the existing `mew:mobile-dock-order`, with positions in `mew:dock-positions`, per browser, including settings for items excluded by permissions. If storage is unavailable, settings continue to apply on the current page. Changes are synchronized between settings and the dock on the same page and with storage changes from other windows. Existing long-press and keyboard reordering in the dock remain available.

## Keyboard shortcut settings

View the current key combination for each feature under Header menu → **Settings → Keyboard shortcuts**. By default, `Alt+T` toggles the task panel, and `Ctrl+백틱` opens the terminal. Select a configurable item, then enter the combination to use. Each item's Reset button resets only that item; Reset all restores all custom combinations to their defaults. Fixed shortcuts, such as the editor's undo, redo, link, and document search shortcuts, cannot be changed.

Shortcuts target the focused pane. `Ctrl/Cmd+N` and `Ctrl/Cmd+T` open a new tab in the current panel; in the editor and file explorer, they open the new file name input. `Ctrl/Cmd+Shift+N` opens the new folder name input (a new document in the document tree). `Ctrl/Cmd+W` and `Ctrl/Cmd+Shift+W` close one current internal tab; closing a terminal or agent tab also ends its session. `Ctrl/Cmd+1…9` selects a tab in display order, and `Ctrl/Cmd+Tab`, `Ctrl/Cmd+Shift+Tab`, and `Ctrl/Cmd+PageUp/PageDown` cycle through previous and next tabs. Nonexistent numbers are ignored, and shortcuts apply independently to each split panel. View switching in the file explorer and tasks uses the same numbers. These standard combinations are fixed aliases; the existing `Alt+N/W/Q/E` and remappable shortcuts are also available. `Alt+1…9` switches projects in the project selector's list order regardless of the focused panel. Nonexistent numbers, the current project, modals, and key repeats do not trigger switching. When the remote screen has focus, the keys are forwarded to the remote host. The CLI switch shortcut in agent input is `Ctrl+Alt+M`.

To use Chrome's reserved keys, enable fullscreen using **the fullscreen button in the mew header or Alt+Enter**. On supported browsers over HTTPS/localhost, this requests a lock on reserved keys for creating, closing, and switching. F11 fullscreen cannot substitute for this. In a regular Chrome window, some reserved keys do not reach mew, so use the existing Alt combinations or open an app window through **Install this page as an app** in the Chrome menu to use Ctrl+W. When the remote screen has focus, all forwardable keys are sent to the remote host; leaving remote focus restores the app shortcut lock. For details, follow the [focus contract](../../.mew/docs/development/ui-contracts.md#focus-based-tab-shortcuts).
