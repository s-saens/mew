## 요구사항

로그인 중 다른 사용자가 호스트의 게임·작업 포커스를 빼앗지 않아야 한다. OAuth는 패널 크기에 맞는 독립 가상 화면의 일반 Chrome에서 진행하고 그 영상과 입력을 패널에 연결한다. 닫으면 가상 세션을 정리하며 완료된 공식 CLI 인증은 유지한다.

개발 앱은 도메인·Tailscale·Mewlink 접속 주소 뒤의 `/포트번호`로 연다. Mew 로그인과 계정별 권한을 확인한 뒤 호스트의 해당 localhost 앱을 접속한 기기에서 실행한다. 일반 내부 브라우저 메뉴·패널·주소창·바로가기·DOM 중계는 제공하지 않는다.

## 인수 기준과 검증 경계

- 로그인 영상과 클릭·키·붙여넣기·팝업이 같은 전용 X 서버에서 동작한다.
- 닫기·재접속·시작 중 취소·권한 회수에서 키·버튼과 소유 자식을 정리한다.
- `/3333` 비로그인은 인증 후 원래 앱으로 돌아오고 guest·다른 계정·다른 포트·Mew 자체 포트는 우회하지 못한다.
- 프론트의 루트 자산·API·POST·WebSocket/HMR을 전달하고 앱에 Mew 쿠키·전체 API 권한을 주지 않는다.
- 직접 프리뷰는 Vite의 인라인 초기화·여러 줄 import와 고정 문자열 동적 import를 같은 포트 안으로 전달하고 주석·문자열·JSON 데이터는 보존한다.
- 직접 프리뷰의 일반 SPA는 별도 basename 없이 최초 루트·하위 경로를 읽고 history·hash·뒤로·앞으로·새로고침을 유지한다. 지역 변수·생성자 호출·DOM 정체성과 포트별 격리도 보존한다.
- 원격 프리뷰는 Service Worker 초기화 완료를 기다리고, 실패 통지·15초 제한에서는 오류를 표시하며 발급 세션·요청·소켓을 정리한다. 실제 wildcard DNS·HTTPS 준비와 구문 변환의 호환 한계는 [프리뷰 계약](../../development/port-preview.md)을 따른다.
- 격리 자동 검사와 실제 OAuth·게임 동시 사용·운영 도메인·Tailscale·Mewlink 외부망 검증은 구분한다. 운영 반영은 사용자가 수행한다.

2026-10-27: 직접 HTTPS 터널의 Vite 형태 모듈·HTTP/WS와 원격 초기화 실패·권한·자원 정리 등 관련 검사 13개가 통과했다. 공개 프리뷰 DNS의 `ENOTFOUND`는 확인했지만 DNS·중앙 배포·호스트 적용은 하지 않았다. 재현과 한계는 [작업 기록](../../work/command-port-previews.md#2026-10-27--포트-접속-실패-재현수정)에 남긴다.

2026-10-28: 직접 프리뷰의 일반 SPA 경로 처리를 보완했다. Along의 로그인·회원가입 화면은 실행 중인 앱을 대상으로 한 격리 프록시에서 확인했으며, 운영 Mew 적용과 로그인 제출은 검증하지 않았다. [결정](../../decisions/0083-direct-preview-spa-routing.md)과 [작업 기록](../../work/command-port-previews.md#2026-10-28--직접-프리뷰의-spa-초기-경로-수정)을 참고한다.
