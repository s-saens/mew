## 요구사항

- owner·manager는 프로젝트 목록·추가·전환·아이콘 변경, 폴더 생성·Git clone/초기화와 하위 프로젝트·worktree 전환을 사용할 수 있다. 목록과 활성 루트는 계정별로 저장한다. member·guest에는 현재 프로젝트만 표시한다. [결정 0070](../../decisions/0070-manager-project-access.md)을 따른다.

- `Ctrl/Cmd+O`는 서버 파일 권한이 있는 계정의 서버 파일 탐색기를 연다. 파일을 열어도 현재 프로젝트를 유지하며 모바일에서는 에디터를 앞으로 가져온다. `Ctrl/Cmd+Shift+O`는 owner·manager의 프로젝트 열기 창을 연다. Alt 병용·IME 조합은 처리하지 않는다.

- 서버 폴더를 프로젝트로 열고 헤더의 현재 프로젝트 선택기로 작업 공간을 오간다.

### 범위

- 프로젝트의 `.mew/project-icon.json` 하나를 사이드바·프로젝트 선택기의 공통 아이콘으로 사용한다.
- 선택기 목록의 프로젝트 아이콘은 16×16px 영역 안에서 가로·세로 중앙 정렬한다. 라인 아이콘·사용자 SVG·이모지 모두 같은 영역을 사용해 제목과의 세로 정렬을 유지한다.

- 프로젝트 추가·서버 파일 탐색기의 맨 위에 OS/클라우드 기본 폴더와 계정별 즐겨찾기를 제공한다.
- 폴더 탐색·클라우드 바로가기·새 폴더·Git clone·Git 초기화를 프로젝트 선택 창에서 제공한다.
- 헤더 왼쪽에는 현재 프로젝트의 아이콘·이름만 표시한다. 버튼의 좌우 패딩은 10px로 같게 하고 아이콘은 16×16px 영역을 채워 왼쪽에 별도 내부 여백이 더해지지 않게 한다. 누르면 저장된 프로젝트 목록이 열리고 마지막 항목은 **프로젝트 추가**다. 탭 나열·닫기·그룹 UI는 제공하지 않는다.
- 현재 프로젝트 버튼과 목록 행의 우클릭·`Shift+F10`·메뉴 키는 **편집**, **삭제** 메뉴를 연다. 현재 버튼의 터치 길게 누르기도 같은 메뉴를 연다. 목록 행에서 메뉴를 열면 프로젝트 목록을 유지한다. Esc·뒤로가기는 편집·삭제 메뉴만 먼저 닫고 호출 행으로 포커스를 돌린다. 비활성 프로젝트를 삭제하면 열린 목록에서 해당 행만 제거한다. 편집은 기존 아이콘 선택기를 열고, 삭제는 계정별 프로젝트 목록에서만 제거하며 실제 폴더·파일은 보존한다. 현재 프로젝트 삭제는 다른 프로젝트로 전환한 뒤 제거하며 전환 실패 시 목록을 유지한다. 마지막 현재 프로젝트의 삭제는 비활성화한다.
- 목록 행 왼쪽 핸들을 마우스·터치로 위아래로 끌어 순서를 바꾼다. 이름 영역은 프로젝트 선택과 목록 스크롤에 사용한다. 행의 `Shift+↑/↓` 또는 포커스한 핸들의 `↑/↓`로도 이동한다. 재정렬은 프로젝트를 전환하거나 메뉴를 닫지 않으며 계정별 경로 목록과 브라우저 사본에 저장한다. 마지막 프로젝트 추가 항목은 이동하지 않는다. [결정 0071](../../decisions/0071-project-list-reorder.md)을 따른다.
- 프로젝트 선택·아이콘 변경과 계정별 화면 복원을 제공한다. `Alt+1…9`는 드롭다운의 목록 순서대로 프로젝트를 선택한다. 처음 9개 항목 오른쪽에는 `Alt+1`부터 `Alt+9`까지 표시하며 `aria-keyshortcuts`로도 제공한다. 재정렬하면 표시 번호도 바뀐다. 10번째 이후 항목과 프로젝트 추가에는 번호를 표시하지 않는다.

### 경계와 제한

- 프로젝트 전환은 owner·manager에게 허용하며 자기 계정의 활성 프로젝트만 바꾼다. 같은 계정의 다른 접속에는 전환을 알리고, 다른 계정과 guest의 화면·파일 요청 경로는 유지한다.
- 기존 프로젝트 경로 목록과 순서는 유지하며 저장된 그룹 정보는 선택기에서 표시하지 않는다.
- 실행 중 에이전트의 기존 작업 경로는 유지한다.
- Git 브랜치 선택으로 같은 저장소의 기존 worktree를 열 때는 현재 프로젝트의 이름·배치·에디터 칸과 탭·에이전트 및 터미널 탭을 유지하고 파일 작업 루트만 바꾼다. worktree 경로를 별도 프로젝트로 목록에 추가하지 않는다. 프로젝트 선택기나 프로젝트 추가로 폴더를 열면 일반 프로젝트 전환으로 처리해 그 폴더의 화면을 복원한다.

## 구현 내용

- 직계·중첩 하위 프로젝트는 일반 파일 트리의 실제 위치·정렬로 표시하며, 폴더 클릭은 펼침·접기만 수행한다. 옆 화살표는 기존 프로젝트 열기 API로 해당 프로젝트를 선택하고, 목록에 없는 경로만 추가한다. owner·manager 권한·중복 경로 재사용·계정별 복원과 실행 중 에이전트의 작업 경로는 유지한다. 폴더 탐색은 [하위 프로젝트 탐색 결정](../../decisions/0004-subproject-folder-exploration.md), 헤더는 [프로젝트 선택기 결정](../../decisions/0019-project-selector.md)을 따른다.

- 프로젝트 선택기의 전역 capture 리스너는 Alt+1…9를 저장된 목록 순서의 프로젝트에 연결한다. 일반 패널 입력에서도 기존 클릭과 같은 전환 경로를 사용한다. 숫자패드와 macOS Option 물리 키를 지원하고, 현재 프로젝트·없는 번호·모달·반복·owner·manager 권한 없음은 전환하지 않는다. Ctrl/Cmd+숫자는 내부 패널 탭에 남기며 로그인 영상·원격 화면 포커스에서는 Alt+숫자도 원격에 전달한다.

- 활성 프로젝트는 계정 UI 원장의 `activeWorkspace`에 저장한다. HTTP·프로젝트 WebSocket 요청은 계정의 루트를 비동기 컨텍스트에 고정하며, 전환은 서버 시작 루트·환경 설정과 다른 계정의 watcher·공동 편집 방을 바꾸지 않는다. 파일 목록·검색·감시자·협업 방은 루트 경로로 분리한다. 저장값이 없거나 폴더가 사라졌으면 서버 기본 루트를 사용한다. [계정별 경로 계약](../../development/architecture.md#계정별-활성-프로젝트)을 따른다.

- 계정 원장의 `activeWorkspace`는 실제 파일 작업 루트이며 `activeProjectPath`는 화면 복원의 논리 프로젝트 루트다. 일반 프로젝트 선택은 두 값을 대상 경로로 맞추고, 같은 프로젝트의 worktree 전환은 `activeProjectPath`를 유지한다. 헤더 이름·프로젝트 목록·계정 UI·도킹과 팝업·에디터 탭 구조·AgentPanel은 논리 루트를 기준으로 유지한다. 파일·Git·검색·본문 캐시는 실제 루트로 분리하고 열린 파일은 대상 내용과 권한을 다시 확인한다. 실행 중 세션의 cwd는 바꾸지 않으며 새 세션의 기본 cwd만 선택한 worktree를 사용한다. [worktree 전환 계약](../../development/ui-contracts.md#같은-프로젝트의-worktree-전환)과 [결정 0068](../../decisions/0068-project-worktree-context.md)을 따른다.

- `server/projectIcons.ts`가 프로젝트별 아이콘 읽기·저장·기존 값 이관을 맡는다. 직계·중첩 트리와 프로젝트 선택기는 같은 값을 표시하고, 선택기에서 변경하면 프로젝트 파일을 갱신한다.

- 두 탐색기의 항목 우클릭은 사이드바와 같은 메뉴 컴포넌트로 복사·잘라내기·붙여넣기·이름 변경·삭제를 제공하고 폴더에 즐겨찾기 추가를 표시한다.
- 모바일 길게 누르기도 지원한다.

- 두 탐색기 맨 위의 즐겨찾기는 접힌 자체 드롭다운이며, 펼쳐서 폴더 이동·제거를 실행한다.
- 키보드·터치·Esc·뒤로가기를 지원한다.
- 목록은 서버 OS 기본 폴더·감지된 클라우드 폴더와 직접 추가한 경로를 제공한다.
- 추가·제거는 계정별로 저장한다.

- 프로젝트 추가와 서버 파일 탐색기는 프로젝트 추가 창의 디자인을 기준으로 공통 탐색 컴포넌트를 사용한다.
- 주소창·필터·목록 행·하단 경로를 공유하고 각 화면의 기존 작업을 유지한다.

- 프로젝트 추가 창은 처음 열 때 제목에 포커스를 둔다.
- 없는 경로를 입력하면 기존 부모·첫 누락 이름·전체 생성 경로를 네 언어로 확인받고, 확인 시 중간 폴더까지 만든 뒤 해당 위치로 이동한다.
- [경로 생성 계약](../../development/ui-contracts.md#없는-프로젝트-경로-확인생성)을 따른다.

- 폴더 탐색·클라우드 바로가기·새 폴더·Git clone·Git 초기화를 프로젝트 선택 창에서 제공한다.

- 프로젝트 선택기는 공용 메뉴의 테마·키보드 이동·화면 경계·Esc/뒤로가기 닫기·포커스 복원 규칙을 따른다. 목록 항목의 hover·focus는 화면 상태만 미리 준비하고 실제 선택 시 같은 요청을 재사용한다. 파일·트리·에이전트 점유는 미리 조회하지 않으며 [빠른 전환 계약](../../development/ui-contracts.md#루트-프로젝트-빠른-전환)을 따른다.
- 프로젝트 전환 중에는 중앙 로딩 인디케이터를 표시하고, 완료·실패 후 닫는다.
- 검정 덮개 없이 클릭·터치·키보드 조작을 유지한다.
