## 요구사항

- 프로젝트 파일을 이름이나 본문으로 찾고 필요한 내용을 바꾼다.

### 범위

- 파일·문서 트리 위의 검색창 하나와 내용 검색 토글을 제공한다. 현재 보기의 계층 결과·파일 보기의 @ 하위 프로젝트 범위·대소문자·기본 와일드카드·선택 정규식을 지원한다.
- 본문 결과의 해당 줄로 이동하고 파일별·전체 치환을 제공한다.

### 경계와 제한

- 파일명 검색은 후보 수에 상한이 있다.
- 서버의 검색·치환 패턴은 최대 2,000자이며 RE2 호환 엔진으로 실행한다. 전방·후방 탐색과 패턴 역참조는 지원하지 않는다.
- 본문 색인은 일반 문자열·와일드카드의 필수 문자열로 후보를 좁히는 수단이며 원문 대조·장애 시 scanner 경로를 유지한다.
- RAG 의미 검색은 제거했다. 문서 탐색은 README·MOC와 일반 파일 검색을 사용한다.

### 관련 문서

- [검색 설정·계약](../../configuration/search.md)

## 상세 동작

파일 탐색기에는 탐색·파일명·본문 검색 탭이 없다. 맨 위 검색창에서 `Aa`·`.*` 옆의 내용 검색 아이콘을 끄면 파일명을, 켜면 본문을 검색한다. Ctrl+P와 Ctrl+Shift+F는 각각 해당 모드를 선택하고 같은 입력창을 포커스한다. 모드와 문서·파일 범위를 바꿔도 입력은 유지한다. 입력 자동 포커스는 공통 데스크톱 조건을 따른다.

검색창 아래의 기존 문서/파일 두 버튼 토글을 유지한다. 클릭·터치로 바로 고르고 좌우 방향키·Home/End로도 전환한다. 별도 검색 탭 제거는 이 범위 토글의 모양·직접 전환을 바꾸지 않는다. 문서 보기는 Documents만, 파일 보기는 `.workspace` 파일시스템 전체를 검색한다. 파일 보기의 실제 Documents 경로도 일반 파일 경로로 검색되며 별도의 Documents 스코프 결과와 섞지 않는다. 파일 보기에서 `@`로 직계 하위 프로젝트를 하나 이상 고르면 OR 범위로 좁힌다. HTTP API의 기존 무범위 통합 검색과 docs·하위 프로젝트 OR는 호환용으로 유지하며, 새 `root` 범위는 결과 상한을 적용하기 전에 `.workspace` 전체를 선택한다.

검색 결과는 기존 `FileTree` 행·아이콘·들여쓰기·문서 대표 페이지를 재사용한다. 일치 파일과 상위 경로만 표시하고 조상을 자동으로 펼친다. 파일명·본문 모두 일치 항목의 이름을 배경색과 굵은 글씨로 강조한다. 예를 들어 `a1/b1/c1.md`, `a1/b2/c3.md`, `a1/b3.md`에서 `c*.md`를 찾으면 `a1` 아래의 `b1`·`b2`를 펼쳐 두 일치 파일을 보이고 `b3.md`는 숨긴다. 문서 대표 파일이 일치하면 그 페이지 행을 강조하고 자식에 대표 파일을 중복 표시하지 않는다. 검색 중의 펼침·스크롤은 평상시 저장 상태를 덮어쓰지 않으며, 검색어 삭제·취소 시 기존 상태로 돌아온다. 생성과 명시적 파일 위치 표시도 검색을 해제한다.

파일명 검색은 250ms 디바운스 뒤 서버의 증분
파일 카탈로그를 검색하고 상위 50개만 받는다. 전체 후보 트리를 브라우저로 전송하지 않으며 평상시 파일 탐색기의
폴더 단위 지연 로드는 유지한다([ADR 0105](../../history/decisions/0105-mew-incremental-file-catalog-and-exact-search-index.md)).
두 검색 모두 대소문자 구분 옵션을 제공한다. 파일명 검색은 `*` 또는 `?`가 있으면 자동으로 와일드카드를 적용한다.
`*`는 0개 이상의 문자(경로 구분자 포함), `?`는 유니코드 문자 하나를 뜻한다. 파일명 또는 전체 상대 경로를 끝까지 대조하며,
`*.exe`는 하위 폴더를 포함해 `.exe`로 끝나는 파일만 찾는다. `file?.txt`는 `file1.txt`와 일치하고 `file12.txt`는 제외한다.
그 외 문자는 리터럴이며, 와일드카드가 없는 입력은 기존 퍼지 검색을 유지한다. 파일명 정규식 옵션은 사용자 요청에 따라 복원했다. 두 검색 모두 `.*` 옵션을 켜면 와일드카드·퍼지 해석 대신 정규식을 적용한다. 파일명 정규식은 파일명 또는 상대 경로의 부분 문자열을 대조하며 `^`·`$`로 전체 일치를 지정할 수 있다. 잘못된 정규식은 오류로 표시한다.
본문 검색은 옵션 없이 `*`·`?`를 와일드카드로 해석한다. `*`는 같은 줄의 0개 이상 문자(가능한 긴 범위), `?`는 유니코드 문자 하나이며 나머지 기호는 리터럴이다. 와일드카드가 없으면 일반 문자열 검색이다. 검색·SSE·치환은 같은 패턴을 사용하고 빈 매치는 제외한다. 기본 치환 문자열은 그대로 삽입하며 정규식 치환은 `$1` 같은 캡처 그룹을 지원한다. 의미 검색과 History / raw 확장 검색은 이 화면에 두지 않는다.

본문 결과는 파일·문서 행으로 표시하고 hover 또는 키보드 포커스 시 툴팁으로 매치 문맥을 보여 준다. 파일 클릭은 첫 매치로 이동하며, 복수 매치는 툴팁의 이전·다음 버튼으로 고른 뒤 열 수 있다. 문맥은 검색 줄과 위아래 각각 최대 3줄이며 검색 줄이 가운데에 온다. 각 줄은 매치의 원문 열 주변 좌우 약 10단어로 좁히고, 공백 없는 긴 줄도 최대 400 UTF-16 코드 단위와 생략표시 2자로 제한한다. 유니코드 서로게이트 쌍은 자르지 않는다. 파일 시작·끝에서는 있는 줄만 보인다. 툴팁은 body portal과 공통 fixed 좌표 계산을 사용해 패널과 viewport 경계를 맞추고, 스크롤·클릭·Esc·이탈 시 숨긴다. 터치 hover는 띄우지 않는다. 바꾸기 입력을 펼친 쓰기 가능 사용자는 툴팁에서 해당 파일 전체를 치환할 수 있다.
400자를 넘는 원문 줄은 각 매치 앞 최대 24자부터 400자까지 미리보기로 보내고, 생략한 앞뒤에 `…`를 붙인다. `matchStart`·`matchEnd`는 이 미리보기 안의 UTF-16 오프셋이며, `column`은 원문 줄의 0부터 시작하는 UTF-16 오프셋을 유지한다. 추가 `context` 배열은 각 문맥 줄의 `line`·`text`를 담고, 매치 행에만 그 `text` 기준 `matchStart`·`matchEnd`를 둔다. JSON·SSE는 이미 읽은 원문에서 같은 미리보기와 문맥을 만들며 클릭은 원문 위치로 이동한다. 문맥이 없는 이전 응답은 기존 한 줄 미리보기로 표시한다.

서버의 파일명 정규식과 본문 검색·SSE·치환은 `re2js`의 RE2 호환 엔진을 사용한다. 전방·후방 탐색(`(?=...)`, `(?!...)`, `(?<=...)`, `(?<!...)`)과 패턴 역참조(`\1` 등)는 거부하며 JavaScript 기본 정규식 엔진으로 재시도하지 않는다. 기본 본문 와일드카드도 같은 엔진을 사용한다. 모든 패턴은 유니코드 문자 단위로 대조하며 원문 위치는 기존 UTF-16 오프셋을 유지한다. 입력은 2,000자, 컴파일된 명령은 10,000개로 제한한다. 치환의 `$1`·`$<name>`·`$$`는 유지하며 빈 매치는 건너뛴다. 열린 문서 안의 찾기·바꾸기는 별도 편집기 기능이다.

검색 요청이 진행되는 동안에는 `검색 중…`을 보인다. 파일 내용 검색은 일반 문자열·와일드카드에서 반드시
포함되어야 하는 연속 문자열을 골라 로컬 SQLite trigram 색인으로 후보를 좁힌 뒤, 원래 검색 패턴으로 원문을
검증한다. 예를 들어 `unique*workspace phrase`는 `workspace phrase`를 후보 조회에 사용한다. 후보 문자열은
유니코드 문자 3개 이상이어야 하므로 `a😀`·`😀😀`는 짧은 검색으로 취급한다. 대소문자를 구분하지 않을 때
비 ASCII 대소문자 문자는 SQLite·RE2의 변환 차이를 피하도록 문자열을 나누는 경계로 처리한다. 남은 안전한
문자열이 없거나 정규식·색인 구축/장애 중이면 기존 원문 scanner를 사용한다. `*`·`?`만 있거나 고정 문자열이
짧은 와일드카드도 scanner를 사용한다. FTS 후보에는 아직 반영되지 않은 dirty 파일을 더해 원문에서 확인한다.
SSE는 매치 파일을 `result` 이벤트로 보내고, `done`은 잘림·색인 상태·dirty 보완 파일 수를 함께 보낸다.

FTS v2는 본문 `body`와 프로젝트 이름의 SHA-256을 담는 `scope` 열을 색인한다. MATCH 안에서 본문과 프로젝트
조건을 교차 조회한 뒤 파일 메타데이터를 rowid로 찾는다. 프로젝트의 각 파일에 MATCH를 반복하거나 다른
프로젝트의 매치를 메타데이터까지 모두 조회하는 실행 계획을 피한다. 본문 조건을 `body` 열에 한정하므로
프로젝트 해시가 검색 결과를 만들지 않는다. 기존 v1 파생 색인은 원문에서 자동 재구축하며, 구축 중에는 scanner를
사용한다. 권한·검색 범위를 적용한 뒤 기존 4,001개 후보 상한을 적용한다. 선택한 후보를
카탈로그 순서로 다시 정렬하고 scanner의 파일·매치 상한과 원문 검증을 유지한다. 근거는
[결정 0058](../../decisions/0058-search-query-and-catalog-batches.md)을 따른다.

### 성능 계측

`MEW_PERF_LOG=1`이면 `search.scope`는 카탈로그 조회와 현재 계정의 범위·권한 선별 시간,
`search-index.query`는 FTS 후보 조회 시간, `search.scan`은 원문 읽기·매치 시간을 기록한다.
`search.scan`의 `files`는 선택된 경로 수, `allowedFiles`는 범위·권한을 통과한 전체 경로 수,
`indexed`는 FTS 후보를 사용했는지를 뜻한다. `files`에는 scanner의 4천 파일 상한을 적용하기 전 경로 수가
들어갈 수 있다. 검색어·파일 경로·계정·본문은 로그 필드에 넣지 않는다. 브라우저 전송·표시 시간은 포함하지 않는다.

빈 검색창에서는 기존 탐색기와 폴더 단위 지연 로드를 유지한다. 검색 중에는 반환된 경로에서 필요한 조상만 만들어 표시하며 전체 트리나 매치 파일의 본문을 추가 조회하지 않는다. 별도 정렬 도구 줄은 두지 않는다.

Documents와 일반 폴더를 펼칠 때 내부 폴더는 기억된 펼침 상태가 있으면 복원하고, 없으면 모두 접힌 상태로 시작한다. 하위 프로젝트도 같은 방식으로 펼쳐 내부 파일을 탐색하며 별도 화살표만 활성 프로젝트를 전환한다.
처음 표시할 때 활성 문서의 경로를 자동으로 펼쳐 이 상태를 덮어쓰지 않는다. 이후 문서 탭 선택에 따른 경로 펼침은 유지한다.

탐색기의 새 파일은 입력한 확장자를 유지하며, 확장자를 생략해도 `.md`를 자동으로 붙이지 않는다.
이전 자동 보정은 코드 파일·확장자 없는 파일을 원하는 이름으로 만들 수 없어 제거했으며 재도입하지 않는다.
마크다운 파일만 기존 문서 초기 내용과 Documents의 MOC 등록을 적용하고, 나머지는 빈 파일로 만든다.

파일 보기의 결과는 실제 부모 폴더 아래에 표시하고, Documents 보기의 결과는 문서 페이지 계층으로 표시한다. 직계·중첩 하위 프로젝트의 이미 읽은 메타데이터는 아이콘과 이동 버튼에 재사용한다([프로젝트 사용법](../../guides/projects.md)). 결정과 검증 기록은 [ADR 0085](../../decisions/0085-explorer-inline-search.md)와 [구현 기록](../../work/explorer-inline-search.md)을 따른다.

## 검증

- 2026-10-24: 검색·카탈로그·파일 읽기·접근 제어·플랫폼의 통합 회귀에서 58개를 통과하고 Windows 전용 2개는 Linux에서 건너뛰었다. 와일드카드 JSON/SSE 결과 일치·dirty 보완·색인 비활성화·유니코드 짧은 검색·대소문자 변환 차이, 실제 v1→v2 재구축·프로젝트 교집합·scope 메타데이터의 본문 검색 제외를 확인했다.
