## 목적과 결과

상단바 명령 메뉴를 Alt+R로 열고, 메뉴에서 첫 9개 명령을 숫자로 실행하도록 추가했다. 기존 Ctrl+E와 방향키 탐색·Esc 복귀를 유지한다. 숫자 선택은 명령 이름 클릭과 같은 실행이며, 포트·정지·터미널·추가 버튼은 번호 대상에서 제외한다. 번호 표시는 기존 이름 영역 안에 배치해 좁은 메뉴에서도 행 너비를 유지한다.

현재 사용법은 [명령 버튼 안내](../guides/commands.md), 구현 기준은 [드롭다운과 선택 컴포넌트 계약](../development/ui-contracts.md#드롭다운과-선택-컴포넌트)을 따른다.

## 검증과 적용

- `node --test src/utils/command-menu-keyboard.test.ts server/command-button-menu-ui.test.ts`: 5개 통과. 편집기에서 Alt+R 열기, 물리 키·숫자패드, 보조키·IME·키 반복·비활성 항목, 숫자 실행과 포커스 복귀를 검사했다. 격리 Chromium에서 1100/390/320px·밝은/어두운 테마와 240px 크기 변경의 폭·행 밀도·포트 동작도 확인했다.
- `npx tsc -b`: 통과.
- 변경한 TypeScript 파일 4개의 `npx oxlint`: 통과.
- `npm run check:docs`: description 검사는 오류 없이 통과했다. 전체 링크 검사는 작업 전부터 삭제되어 있던 기능 MOC·태스크 문서를 가리키는 기존 링크 18건으로 실패했다. 이번 변경 문서의 링크 오류는 없다.

앱 빌드·배포·서버 실행·재시작은 수행하지 않았다. 실행 중인 인스턴스 적용은 사용자가 빌드 후 수행한다. 실제 모바일 기기의 키보드 입력은 별도로 확인해야 한다.

## 드롭다운 전환 수정 (2026-10-28)

프로젝트 목록이 열린 상태에서 명령어 버튼을 눌러도 목록이 열리지 않는 문제를 수정했다. 기존 메뉴의 바깥 누름 처리가 새 버튼의 클릭을 삼켰고, 클릭만 허용해도 기존 메뉴를 먼저 닫으면 뒤로가기 가드 정리가 새 메뉴 열기를 취소했다. 다른 상단 메뉴 버튼에서는 클릭을 전달하고, 새 버튼의 클릭 처리가 끝난 다음 작업에서 기존 메뉴를 닫는다. 이전 버튼으로 포커스를 되돌리지 않으며 같은 버튼·일반 바깥 누름의 닫기 동작은 유지한다. 현재 계약은 [공용 드롭다운 계약](../development/ui-contracts.md#드롭다운과-선택-컴포넌트)과 [프로젝트 명령 버튼](../features/터미널·에이전트·자동화/프로젝트%20명령%20버튼.md)에 반영했다.

- Chromium 디버거에서 메뉴 바깥 누름의 대상·호출 스택과 전환 중 `popstate`를 확인했다. 임시 디버깅 파일과 연결은 정리했다.
- `node --test server/header-menu-switch-ui.test.ts packages/ui/src/useOverlayDismiss.test.ts src/utils/command-menu-keyboard.test.ts`: 16개 통과. 전환 회귀는 1100/390px·밝은/어두운 단색·그라데이션에서 클릭·터치의 양방향 전환, 단일 팝업, 포커스, 같은 버튼 닫기, Esc·뒤로가기와 일반 바깥 클릭 차단을 검사했다.
- `npx tsc -b`: 통과. 변경 TypeScript 파일의 `npx oxlint`는 오류 없이 완료됐으며 기존 React 경고가 남아 있다.
- `npm run check:docs`: description 오류는 없으며, 삭제된 기능 MOC·태스크를 가리키는 기존 링크 18건으로 전체 링크 검사는 실패했다. 변경 문서의 링크 오류는 없다.
- `server/action-menu-ui.test.ts`의 전체 스타일 검사는 함께 수정 중인 프로젝트 항목 높이 33px와 햄버거 항목 32px의 차이로 실패했다. 이번 전환 회귀는 별도 파일로 검증했으며 다른 작업의 스타일·테스트 변경은 수정하지 않았다.

앱 빌드·배포·서버 실행·재시작은 수행하지 않았다. 실행 중인 인스턴스 적용과 실제 모바일 기기 확인은 남아 있다.
